Страница показывает, как задать настройку CRANE и как сервер выбирает значение, если источников несколько. Сервер читает настройки один раз при старте: из переменных окружения, из файлов секретов (`<ИМЯ>_FILE`) и из необязательного файла TOML, путь к которому задаёт {{< env "CRANE_CONFIG" >}}. Неверное значение не заменяется умолчанием: сервер не стартует и называет переменную в журнале.

Секреты (токен, адрес каталога с паролем, ключ шифрования) безопаснее передавать файлами, чем значениями в окружении. Значения секретных переменных не попадают в тексты ошибок: сообщение называет переменную и причину, но не содержимое.

## Перед началом {#prerequisites}

- Выбранный способ запуска: {{< xref "deploy" >}}.
- Список всех переменных с умолчаниями: {{< xref "reference/environment-variables" >}}.

## Шаги {#steps}

1. Задайте переменные, без которых сервер не стартует: {{< env "CRANE_DATABASE_URL" >}}, {{< env "CRANE_BLOBS" >}}, {{< env "CRANE_PUBLIC_URL" >}} и {{< env "CRANE_TOKEN" >}}. Остальные переменные имеют значения по умолчанию. Минимальный набор для стенда без постоянного хранения:

   ```dotenv
   CRANE_DATABASE_URL=memory
   CRANE_BLOBS=memory
   CRANE_PUBLIC_URL=https://crane.example.com
   CRANE_TOKEN=<token>
   ```

   Значение `memory` пишется явно. Данные в памяти теряются при перезапуске.

2. Передайте секреты файлами. Для переменной с формой `_FILE` задайте путь к файлу вместо значения:

   ```dotenv
   CRANE_TOKEN_FILE=/run/secrets/crane_token
   CRANE_DATABASE_URL_FILE=/run/secrets/database_url
   ```

   Форму `_FILE` имеют {{< env "CRANE_TOKEN" >}}, {{< env "CRANE_DATABASE_URL" >}}, {{< env "CRANE_SETTINGS_KEY" >}}, {{< env "CRANE_CACHE" >}}, {{< env "AWS_ACCESS_KEY_ID" >}} и {{< env "AWS_SECRET_ACCESS_KEY" >}}. Правила чтения файла:

   - сервер убирает из конца содержимого символы перевода строки (`\r`, `\n`), остальные пробелы сохраняются;
   - пустое значение, в том числе пустой файл, считается ошибкой;
   - переменная и её форма `_FILE` вместе дают ошибку `переменные CRANE_TOKEN и CRANE_TOKEN_FILE взаимоисключающие`;
   - файл, который не читается, даёт ошибку с именем переменной `_FILE` и причиной ввода-вывода.

3. При необходимости соберите остальные настройки в файле TOML и укажите путь к нему в окружении. Путь задаёт только окружение: ключа `config` в самом файле нет.

   ```dotenv
   CRANE_CONFIG=/etc/crane/crane.toml
   ```

   ```toml
   public_url = "https://crane.example.com"
   blobs = "file:///data/blobs"
   token_file = "/run/secrets/crane_token"
   database_url_file = "/run/secrets/database_url"
   cargo_proxy_repos = ["crates-io"]
   max_publish_bytes = 20971520
   ```

   Ключ файла — имя переменной без префикса `CRANE_` в нижнем регистре. Значение — строка, целое число или массив строк (сервер склеивает его запятыми). Секреты в файле TOML лежат открытым текстом, поэтому для них используйте ключи `token_file`, `database_url_file` и подобные.

4. Перезапустите сервер. Настройки не перечитываются во время работы.

## Проверка {#verify}

При успешном старте сервер пишет в журнал запись «сервер запущен» с полями `http_port` и `admin_port`. Затем проверьте готовность: {{< xref "reference/ports-and-health" >}}.

При ошибке сервер завершается с кодом `1` и пишет в журнал запись «роль завершилась с ошибкой»; причина лежит в поле `error`. За один запуск сервер сообщает об одной проблеме. Тексты сообщений на русском языке:

```text
не задана переменная CRANE_PUBLIC_URL
переменные CRANE_TOKEN и CRANE_TOKEN_FILE взаимоисключающие
неизвестный ключ `tokn` в файле конфигурации
```

Ошибка разбора TOML называет путь, строку и столбец, но не цитирует содержимое файла, потому что в нём может быть токен:

```text
ошибка разбора TOML в /etc/crane/crane.toml: строка 3, столбец 9
```

## Порядок источников {#precedence}

Значение берётся из первого источника, который его задал:

1. переменная окружения, в том числе заданная пустой строкой;
2. ключ файла TOML из {{< env "CRANE_CONFIG" >}};
3. строка таблицы `setting` в PostgreSQL (см. [Настройки в PostgreSQL](#stored));
4. значение по умолчанию.

Порядок считается по имени переменной. Поэтому нельзя задать секрет одной формой в окружении, а другой в файле: токен в ключе `token` файла TOML вместе с {{< env "CRANE_TOKEN_FILE" >}} в окружении даёт ту же ошибку взаимоисключения.

> [!SECURITY]-
> Порты, список доверенных прокси, адрес каталога и ключ шифрования читаются до слоя PostgreSQL и поэтому никогда не берутся из него. Это {{< env "CRANE_HTTP_PORT" >}}, {{< env "CRANE_ADMIN_PORT" >}}, {{< env "CRANE_TRUSTED_PROXIES" >}}, {{< env "CRANE_DATABASE_URL" >}} и {{< env "CRANE_SETTINGS_KEY" >}}. Строка с таким ключом в таблице `setting` не действует: прямая запись в таблицу не ослабляет, например, список доверенных прокси.

## Настройки в PostgreSQL {#stored}

Под файлом TOML лежит третий слой: таблица `setting` в PostgreSQL. Сервер читает её при старте, если каталог постоянный (`postgres://`). Интерфейса, который записывает настройки в эту таблицу, сейчас нет: ни HTTP API, ни консоли. Администратор развёртывания задаёт настройки окружением и файлом.

Что делает сервер со строками таблицы при старте:

- строка с неизвестным ключом, строка ключа, который задают только окружение и файл, и строка ключа, уже заданного окружением или файлом, не действуют. Сервер пишет предупреждение с ключом и причиной, значение в журнал не попадает;
- секрет, который нельзя расшифровать (нет ключа, другой ключ, повреждённый шифртекст), останавливает старт: значение не заменяется умолчанием. Подробности: {{< xref "configure/settings-encryption" >}}.
