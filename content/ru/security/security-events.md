{{< term "security-journal" "Журнал ИБ" >}} сервера CRANE состоит из трёх потоков: аудит действий (цель `crane::audit`), журнал доступа (`crane::access`) и журнал исходящих запросов (`crane::upstream`). Сервер пишет их строками JSON в стандартный вывод и закрепляет на уровне `info`, поэтому {{< env "RUST_LOG" >}} их не отключает.

Страница перечисляет поля и события, которые сервер пишет сейчас. Целевое устройство журнала описано в {{< xref "features/security/security-journal" >}}. Экспорт в {{< term "siem" >}} сервер пока не содержит.

## Цели журнала {#targets}

| Цель (`target`) | Что пишет | Сообщение (`message`) |
| --- | --- | --- |
| `crane::audit` | Одно событие на каждое действие записи и на каждый отказ в аутентификации | `аудит` |
| `crane::access` | Одну строку на каждый HTTP-запрос к порту API | `запрос обработан` |
| `crane::upstream` | Одну запись на каждую реальную выборку из upstream, включая отказы SSRF-guard | `выборка из upstream` |

Служебные поля `timestamp`, `level` и `target` добавляет библиотека журналирования. Поля события лежат на верхнем уровне строки, а не во вложенном объекте. В журнал не попадают заголовки, тела запросов и ответов, строки запроса (query) и значения токенов. Тексты сообщений заданы на русском языке; для выбора потока используйте `target`, а не сообщение.

## Как выделить журнал из потока логов {#extract}

Сервер пишет все логи в один поток, поэтому журнал ИБ выделяют по полю `target`. Команда читает вывод контейнера `crane`, пропускает строки, которые не являются JSON, и оставляет одну цель:

```bash
docker compose --project-directory . \
  -f deploy/compose/docker-compose.yaml logs --no-log-prefix crane \
  | jq -cR --arg t crane::audit 'fromjson? | select(.target == $t)'
```

Подставьте `crane::access` или `crane::upstream`, чтобы выбрать другой поток. Пример строки журнала доступа (поля сокращены, порядок может отличаться):

```json
{"timestamp":"<время>","level":"INFO","target":"crane::access","message":"запрос обработан","method":"GET","path":"/cargo/internal/index/config.json","status":200,"duration_ms":3,"request_id":"<uuid>","client_ip":"203.0.113.7","user_agent":"cargo/1.90","actor":"crane"}
```

Тот же фильтр подходит коллектору логов: правило по полю `target` выделяет журнал ИБ без разбора текста сообщений.

## Аудит: поля {#audit-fields}

Имена полей — плоские пути схемы {{< cite "ocsf" >}}; значение `metadata.version` равно `1.3.0`. Необязательное поле, у которого нет значения, в строку не попадает.

| Поле | Значение |
| --- | --- |
| `class_uid`, `category_uid` | `3002` и `3` для события входа (Authentication, IAM); `6003` и `6` для действий записи (API Activity, Application) |
| `activity_id`, `activity_name` | `1` Logon у входа; `1` Create, `2` Read, `3` Update, `4` Delete у действий записи |
| `type_uid` | `class_uid` × 100 + `activity_id` |
| `status_id`, `status` | `1` `Success` или `2` `Failure` |
| `status_detail` | Причина отказа; только при `Failure` |
| `status_code` | Стабильный код отказа по правилу формата; только если правило сработало |
| `severity_id` | `1` при успехе, `2` при отказе |
| `metadata.uid` | Идентификатор события (UUID) |
| `metadata.correlation_uid` | Идентификатор запроса (`request_id`); связывает событие с строкой журнала доступа |
| `metadata.version`, `metadata.product.name`, `metadata.product.version` | Версия схемы, `CRANE` и версия сервера |
| `time` | Время события в миллисекундах от начала эпохи Unix |
| `actor.user.uid`, `actor.user.type_id`, `actor.user.type` | {{< term "principal" "Принципал" >}} действия записи и его тип: `1` `User` (человек), `99` для `Robot`, `Workload`, `Agent` |
| `user.uid`, `user.type_id`, `user.type` | То же у события входа; при отказе субъект неизвестен: `type_id` `0`, `type` `Unknown`, `user.uid` нет |
| `src_endpoint.ip` | Адрес клиента |
| `http_request.user_agent` | `User-Agent`, не более 256 символов |
| `api.operation` | Операция (таблица ниже); у события входа поля нет |
| `resources.uid`, `resources.type` | PURL пакета и версии и `package`; только у действий над версией или пакетом |
| `unmapped.repository` | Имя репозитория; только у действий над пакетом |
| `unmapped.trace_id` | Идентификатор трассы из заголовка `traceparent`, если он пришёл |

Адрес клиента и идентификатор запроса берутся из `X-Forwarded-For` и `X-Request-Id` только от прокси из {{< env "CRANE_TRUSTED_PROXIES" >}}: {{< xref "configure/network" >}}.

## Аудит: события {#audit-events}

События с успехом и с отказом отличаются полем `status`. Причина отказа — краткий текст ошибки; цепочка внутренних причин, в которой бывают адреса хранилищ, в событие не входит.

| `api.operation` | Действие | Когда сервер пишет событие |
| --- | --- | --- |
| нет (вход, `class_uid` `3002`) | Отказ в аутентификации | Токен предъявлен и отвергнут: `status` `Failure`, `status_detail` `токен отвергнут`. Успешный вход не пишется. Запрос без заголовка авторизации — часть рукопожатия протокола и не пишется |
| `publish` | Публикация версии | Cargo и npm, успех и отказ |
| `yank`, `unyank` | Скрытие версии и его снятие | Cargo |
| `delete` | Удаление версии | npm |
| `deprecate`, `undeprecate` | Пометка версии устаревшей и снятие пометки | npm |
| `tag`, `untag` | Установка и снятие тега | npm (`dist-tag`) |
| `namespace.reserve` | Резервирование namespace | При старте для каждой записи {{< env "CRANE_NAMESPACES" >}} (принципал `crane:config`, тип `Workload`) и при первой публикации точного имени |
| `upstream.shadow` | Отказ отдать внутреннее имя из публичного upstream | Proxy Cargo и npm; всегда `Failure`, `status_detail` `имя внутреннее: из публичного upstream не отдаётся` |

Чтения аудит не пишет: скачивание файла и запрос индекса видны только в журнале доступа. Сопоставления для файлов версий, изменений настроек и мастера первого запуска есть в адаптере, но сервер эти события пока не пишет.

## Журнал доступа: поля {#access-fields}

| Поле | Значение |
| --- | --- |
| `method`, `path` | Метод и путь запроса без строки запроса (query) |
| `status` | Код ответа |
| `duration_ms` | Длительность обработки в миллисекундах |
| `request_id` | Идентификатор запроса: UUIDv7 от сервера или допустимое значение от доверенного прокси; сервер возвращает его в заголовке `X-Request-Id` |
| `client_ip` | Адрес клиента |
| `user_agent` | `User-Agent`, не более 256 символов |
| `actor` | Имя принципала ({{< env "CRANE_TOKEN_PRINCIPAL" >}}); есть только после успешной аутентификации |
| `cache` | Только у ответов proxy: `hit`, `miss`, `stale` или `stale-on-error` |
| `upstream_failure` | Причина сбоя upstream или проверки целостности: `refused`, `unavailable`, `throttled`, `weak-integrity`, `digest-mismatch`, `too-large` |
| `upstream_reason` | Текст причины; только при `refused` и `digest-mismatch` (для `digest-mismatch` в тексте ожидаемый и полученный SHA-256) |

Запросы к порту проб ({{< env "CRANE_ADMIN_PORT" >}}) в журнал доступа не попадают.

## Журнал исходящих запросов: поля {#egress-fields}

| Поле | Значение |
| --- | --- |
| `host` | Хост upstream |
| `path` | Путь на upstream без строки запроса (query) |
| `status` | Код ответа upstream; есть, если ответ получен |
| `failure` | `refused`, если SSRF-guard отказал в запросе, или `unavailable`, если соединение не удалось; есть вместо `status` |
| `elapsed_ms` | Время до получения заголовков ответа в миллисекундах |

Причину отказа guard (хост вне allowlist, непубличный адрес, запрещённая схема) сервер пишет в поле `upstream_reason` строки журнала доступа запроса, который вызвал выборку: {{< xref "features/security/egress-guard" >}}.

## Чего в журнале сейчас нет {#absent}

- **Защиты от изменения.** Цепочки хэшей и якорей в неизменяемом хранилище нет. Событие аудита остаётся строкой стандартного вывода, и сохранность строки определяет конвейер логов организации.
- **Экспорта в SIEM.** Сервер не доставляет события в SIEM. Строки в схеме {{< term "ocsf" >}} забирает коллектор логов организации.
- **Ролей доступа к журналу.** Журнал читает тот, кто читает вывод контейнера. Маскирования идентификаторов нет.
- **Потока скачиваний.** Скачивание файла видно только строкой журнала доступа.
- **Аудита чтения.** Сервер аудирует действия записи и отказы, чтения — нет.
