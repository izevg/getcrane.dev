Поиск CRANE находит пакеты по задаче, а не только по имени. Он сочетает лексический поиск и поиск по смыслу, показывает только те пакеты, которые пользователь вправе читать, и ставит точное совпадение имени на первое место. Результаты появляются по мере ввода.

Модели в поиске отвечают только за вспомогательные оценки: вектор текста и, если настроено, переупорядочивание кандидатов. Решений о доступе и безопасности модель не принимает, а без моделей поиск остаётся рабочим и работает лексически. Границы использования ИИ в CRANE описаны на странице {{< xref "features/security/ai-boundaries" >}}.

## Что видит пользователь {#user-view}

Поиск ищет по {{< term "hosted-repository" "hosted-" >}} и {{< term "proxy-repository" "proxy-репозиториям" >}}. Результат можно сузить по формату, репозиторию и команде и включить устаревшие пакеты. Строка поиска принимает обычный текст, {{< term "purl" >}} и фильтры вида `format:npm`.

Карточка результата показывает имя, формат, репозиторий, описание, последнюю версию и её состояние, число скачиваний за 30 дней, команду-владельца и жизненный цикл пакета. Для устаревшего пакета показана рекомендованная замена. Если имя похоже на популярное или внутреннее, карточка предупреждает: «Возможно, вы искали …». Экран описан на странице {{< xref "features/registry/console#s-search" >}}.

Результат поиска не даёт права на установку. Клиент получает пакет только после проверки доступа и видимости версии ({{< xref "features/security/access-control" >}}).

## Фильтр доступа до ранжирования {#acl}

CRANE сначала определяет репозитории, которые видит пользователь, и только потом ранжирует. Пользователь не видит то, что не может читать, ни в списке, ни в счётчиках.

Hosted- и proxy-репозитории ранжируются отдельными списками, а затем объединяются. Поэтому большой кэш публичных пакетов не вытесняет внутренние.

## Две ветви поиска {#legs}

**Лексическая ветвь** ищет по полнотекстовому индексу имени, описания и ключевых слов. Сначала запрос строится строго (все термины), а если результатов мало, ослабляется до «любой из» не более чем для семи терминов. Дополнительно CRANE оценивает близость нормализованного имени запросу по триграммам, поэтому опечатки не мешают найти пакет. Ветвь отдаёт до 100 кандидатов.

**Семантическая ветвь** сравнивает смысл запроса со смыслом пакета. Для каждого пакета (а не версии) CRANE строит вектор по имени, описанию, ключевым словам и README последней выпущенной версии и пересчитывает его, когда текст меняется. Вектор получает модель эмбеддингов по OpenAI-совместимому протоколу, а индекс хранится в PostgreSQL. Ветвь тоже отдаёт до 100 кандидатов. Смена модели идёт «рядом»: CRANE заполняет векторы новой модели, строит её индекс, переключает читаемую модель и только затем удаляет старую, не переписывая таблицу пакетов.

Семантическая ветвь использует фильтр доступа внутри самого запроса, поэтому не возвращает пакеты, которые пользователь не вправе читать.

## Слияние и порядок {#fusion}

CRANE объединяет ветви по рангам, а не по сырым оценкам: вклад каждой ветви равен её весу, делённому на сумму константы 60 и ранга кандидата в ветви (reciprocal rank fusion). Так оценки разных шкал сравнимы. Веса ветвей и вес переупорядочивания — стартовые значения, они калибруются на собственном наборе запросов.

Если настроен реранкер (cross-encoder по запросу), он переупорядочивает до 40 лучших кандидатов, и его нормированная оценка добавляется к рангу. Без реранкера порядок определяет слияние.

Порядок строится в два шага: сначала состав, потом порядок. Порог отсекает слабые совпадения, но первый результат остаётся всегда, поэтому выдача не бывает пустой без причины. Затем применяются множители сигналов.

## Сигналы порядка {#signals}

Множители не меняют состав выдачи, только порядок. Значения стартовые.

| Сигнал | Множитель |
| --- | --- |
| Пакет принадлежит команде пользователя | ×1,15 |
| Скачивания за 30 дней | ×(1 + 0,05·ln(1 + n)) |
| Есть README и владелец | ×1,10 |
| Последний релиз старше 2 лет | ×0,85 |
| Устаревший пакет (deprecated, EOL) | ×0,30, с показом рекомендованной замены |
| Открытая критическая уязвимость в последней версии | ×0,80, с бейджем |
| Точное совпадение имени | Всегда первая позиция |

Эти множители влияют на удобство, а не на безопасность: понижение пакета в выдаче не блокирует его установку. Блокировки и карантин описаны на страницах {{< xref "features/security/vulnerability-flow" >}} и {{< xref "features/security/upstream-quarantine" >}}.

## Подсказки рядом с результатами {#hints}

Поисковые данные подпитывают две эвристики. Обе дают кандидата на проверку, а не вердикт.

- **Похожее имя.** Если имя пакета отстоит на одну правку по Дамерау — Левенштейну от популярного или внутреннего имени, а скачиваний из upstream мало, карточка показывает предупреждение. Так CRANE помогает заметить {{< term "typosquatting" >}} ({{< xref "features/security/supply-chain-threats" >}}).
- **Дубликаты библиотек.** Пакеты с косинусной близостью эмбеддингов README и описания от 0,88 и пересечением ключевых зависимостей от 50% показываются как возможные дубликаты.

## Если модели недоступны {#degradation}

- **Нет модели эмбеддингов.** Поиск работает лексически. Консоль показывает баннер «Ассистенты недоступны: поиск работает без семантики».
- **Нет реранкера.** Порядок определяют слияние рангов и порог.
- **Нет ни одной модели.** Поиск работает только лексически и остаётся рабочим.

Поиск доступен и внешним агентам: навык `search_packages` протокола A2A использует тот же поиск и тот же фильтр доступа ({{< xref "features/registry/integrations#a2a" >}}).
