CRANE переносит из Nexus {{< term "hosted-repository" "hosted-репозитории" >}} через REST API Nexus: обходит компоненты, копирует файлы потоком, проверяет контрольные суммы и записывает версии в собственное хранилище. Перенос идёт поэтапно, по командам, и безопасен для повтора.

Переносятся только hosted-пакеты. Кэш {{< term "proxy-repository" "proxy-репозиториев" >}} не переносится: CRANE заполняет его заново по lockfile. Страница описывает, что переносится, как проходит проверка и как переключить клиентов.

## Что переносится {#scope}

- **Переносится:** hosted-репозитории, их компоненты, файлы (assets) и контрольные суммы, а также metadata, необходимая формату.
- **Не переносится:** proxy-кэш. CRANE прогревает его заново по lockfile ({{< xref "features/registry/proxy-cache#offline" >}}).
- **Не переносится как история:** история скачиваний. Она не становится историей использования в CRANE.
- **Групповых репозиториев нет.** Групповые репозитории Nexus не имеют аналога, потому что CRANE не сливает hosted и proxy под одним адресом ({{< xref "features/security/namespace-reservation#no-groups" >}}).

Перенесённые версии получают состояние `Released` и источник `import:nexus`.

## Как идёт перенос {#steps}

1. **Инвентаризация.** CRANE обходит REST API Nexus и составляет список hosted-репозиториев, компонентов, файлов и контрольных сумм.
2. **Перенос.** CRANE копирует каждый файл потоком, пересчитывает SHA-256, сверяет его с контрольной суммой Nexus и записывает файл в {{< term "cas" >}}.
3. **Metadata.** CRANE переносит metadata, необходимую формату.
4. **Сверка.** CRANE формирует отчёт о расхождениях.
5. **Переключение.** Команды меняют адреса репозиториев в шаблонах CI и конфигурации клиентов, а proxy-кэш прогревается заново.

Перенос запускается вручную как фоновая задача воркера и ведёт журнал. Файлы переносятся параллельно, а ошибки повторяются.

## Проверка и повтор {#verify}

Файл попадает в хранилище только после совпадения {{< term "digest" "дайджеста" >}} с контрольной суммой Nexus. Как CRANE проверяет дайджесты, описано на странице {{< xref "features/security/digest-verification" >}}.

Повторный запуск идемпотентен: CRANE пропускает уже перенесённое и дописывает недостающее, поэтому отчёт о расхождениях можно закрывать повторными запусками.

## Переключение клиентов {#cutover}

Переключение выполняется по командам. Для каждой команды:

1. Выпустите токены через `cctl setup`, которая настраивает клиенты на адреса CRANE ({{< xref "features/registry/cli#setup" >}}).
2. Замените адреса репозиториев в шаблонах CI.
3. Прогрейте proxy-кэш по lockfile команды: отчёт о готовности покажет, чего в кэше не хватает ({{< xref "features/registry/proxy-cache#offline" >}}).

Перенесённые имена становятся именами hosted-репозитория, а значит внутренними: proxy не отдаёт их из upstream ({{< xref "features/security/namespace-reservation" >}}).
