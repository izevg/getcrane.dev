Страница описывает, как выбрать кэш {{< term "proxy-repository" "proxy-репозиториев" >}}. Кэш хранит документы {{< term "upstream" >}} и координирует выборки: реплики не запрашивают один и тот же файл у upstream одновременно. Выбор задаёт {{< env "CRANE_CACHE" >}}: `memory` для одного экземпляра или адрес Valkey, когда реплики должны делить кэш.

Кэш не источник истины, его потеря не теряет данных. Поэтому в отличие от каталога и хранилища blob он необязателен: без {{< env "CRANE_CACHE" >}} и без {{< env "CRANE_CACHE_FILE" >}} действует `memory`.

## Перед началом {#prerequisites}

- Для Valkey: сервер Valkey с аутентификацией в сети, доступной только CRANE. Готовый вариант для Compose: {{< xref "deploy/valkey-cache" >}}.
- Хотя бы один proxy-репозиторий: {{< xref "configure/repositories" >}}. Без него кэш не создаётся.

## Шаги {#steps}

1. Выберите режим.

   - `memory`: кэш в памяти процесса, ограничен по байтам (256 МиБ), реплики ничего не делят. Подходит для одного экземпляра. Настройки не нужны.
   - Valkey: общий кэш реплик. Кэш процесса (L1, 256 МиБ) остаётся перед ним.

2. Для Valkey сохраните адрес в файле. Адрес содержит пароль, поэтому передайте его файлом.

   ```text
   valkey://crane:<пароль>@valkey:6379
   ```

   Форма адреса: `valkey[s][-cluster|-sentinel]://[пользователь:пароль@]хост[:порт][/db]`. Схема `valkeys` включает TLS; `redis://` и `rediss://` не принимаются. Таблица схем: {{< xref "deploy/valkey-cache#schemes" >}}.

3. Передайте серверу путь к файлу.

   ```dotenv
   CRANE_CACHE_FILE=/run/secrets/cache_url
   ```

   Допустим и явный выбор `memory`:

   ```dotenv
   CRANE_CACHE=memory
   ```

   Переменная вместе с формой `_FILE` даёт ошибку запуска, как и пустое значение.

4. Перезапустите сервер.

> [!NOTE]
> Содержимое кэша отдаётся клиентам. Valkey должен быть изолирован и требовать аутентификацию: {{< xref "deploy/valkey-cache" >}}.

## Проверка {#verify}

Найдите в журнале запись «кэш proxy выбран» с полем `cache` (`memory` или `valkey`). Запись появляется при старте, если настроен хотя бы один proxy-репозиторий; само значение сервер проверяет при любом запуске. Значение `valkey` подтверждает выбор, но не доступность Valkey: сервер не ждёт подключения, и проба готовности кэш не проверяет.

## Ошибки запуска {#errors}

Сообщения называют переменную и схему, но не остальной адрес. Тексты на русском языке. Примеры идут по порядку: чужая схема, неразобранный адрес, пустое значение, значение вместе с файлом.

```text
CRANE_CACHE: значение со схемой `redis` пока не поддерживается
некорректное значение CRANE_CACHE: ожидалось memory или valkey[s][-cluster|-sentinel]://…
некорректное значение CRANE_CACHE: значение пусто
переменные CRANE_CACHE и CRANE_CACHE_FILE взаимоисключающие
```
