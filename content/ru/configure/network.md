Страница описывает сетевые настройки сервера: порт API, порт проб, публичный адрес и список прокси, которым CRANE доверяет. От публичного адреса зависят ссылки в ответах протоколов. От списка доверенных прокси зависит, какой адрес клиента попадёт в {{< term "security-journal" >}}: адрес клиента или адрес прокси.

По умолчанию сервер никому не верит: заголовки `X-Forwarded-For` и `X-Request-Id` игнорируются, а адресом клиента считается адрес соединения. Доверие включается явно списком {{< env "CRANE_TRUSTED_PROXIES" >}}.

## Перед началом {#prerequisites}

- Обратный прокси с TLS перед сервером. Эталонная настройка: {{< xref "deploy/docker-compose#edge" >}}.
- Подсеть или адреса, из которых прокси подключается к серверу.

## Шаги {#steps}

1. Задайте публичный адрес. Переменная {{< env "CRANE_PUBLIC_URL" >}} обязательна. Значение начинается с `http://` или `https://`, содержит хост, а завершающие `/` сервер отбрасывает. Из адреса строятся ссылки в ответах: например, поля `api` и `dl` в конфигурации Cargo.

   ```ini
   CRANE_PUBLIC_URL=https://crane.example.com
   ```

2. При необходимости измените порты. Сервер слушает оба порта на всех интерфейсах (`0.0.0.0`). Значение — целое число от 0 до 65535.

   ```ini
   CRANE_HTTP_PORT=8080
   CRANE_ADMIN_PORT=9464
   ```

   {{< env "CRANE_HTTP_PORT" >}} (по умолчанию `8080`) — порт API с протоколами пакетов. {{< env "CRANE_ADMIN_PORT" >}} (по умолчанию `9464`) — порт проб. Порт проб отвечает без токена, поэтому не публикуйте его: {{< xref "reference/ports-and-health" >}}.

3. Укажите доверенные прокси: IP-адреса и сети CIDR (IPv4 и IPv6) через запятую. Адрес без префикса означает один хост.

   ```ini
   CRANE_TRUSTED_PROXIES=172.31.250.0/24,::1
   ```

   Для пира из списка сервер читает `X-Forwarded-For` справа налево, пропускает адреса своих прокси, и первый чужой адрес считает клиентом. Левые записи заголовка подделывает кто угодно, поэтому они не влияют на результат. `X-Request-Id` принимается только от доверенного пира и только если значение допустимо; иначе сервер выдаёт идентификатор сам.

   > [!IMPORTANT]
   > Каждый прокси из списка обязан удалять или перезаписывать присланный клиентом `X-Request-Id` и дописывать адрес своего пира в конец `X-Forwarded-For`. Иначе клиент подставит собственные идентификатор запроса и адрес.

4. Перезапустите сервер.

## Проверка {#verify}

1. Найдите в журнале запись «сервер запущен»: поля `http_port` и `admin_port` показывают занятые порты.
2. Выполните запрос через прокси и найдите его в журнале доступа. Адрес клиента в записи должен быть адресом клиента, а не прокси. Если в записи адрес прокси, его нет в {{< env "CRANE_TRUSTED_PROXIES" >}}.

## Ошибки запуска {#errors}

Тексты на русском языке. Примеры идут по порядку: порт вне диапазона, нет публичного адреса, адрес без схемы, адрес без хоста, неверный список прокси, занятый порт.

```text
некорректное значение CRANE_HTTP_PORT: ожидалось целое число в допустимом диапазоне
не задана переменная CRANE_PUBLIC_URL
некорректное значение CRANE_PUBLIC_URL: адрес должен начинаться с http:// или https://
некорректное значение CRANE_PUBLIC_URL: в адресе нет хоста
некорректное значение CRANE_TRUSTED_PROXIES: ожидался список IP-адресов или CIDR через запятую
не удалось занять порт 8080: Address already in use (os error 98)
```

Текст причины занятого порта зависит от операционной системы.
