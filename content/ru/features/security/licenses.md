CRANE определяет заявленную лицензию версии, разбирает её как SPDX-выражение и применяет политику, которую задаёт организация: для каждой категории лицензий и каждого контекста использования решение `allow`, `review` или `deny`. Неизвестная или нестандартная лицензия никогда не получает `allow`: она уходит на `review`.

CRANE не выносит юридических заключений. Он показывает, что объявлено, по какой политике принято решение и кто должен посмотреть неоднозначный случай.

## Угроза {#threat}

Зависимость приносит лицензионные обязательства, о которых никто не знал. Сильный копилефт в библиотеке, которую статически связали с распространяемым продуктом, или сетевой копилефт (AGPL) в SaaS-сервисе обязывают открыть исходный код. Обнаруживается это обычно при сделке или аудите, а не при добавлении зависимости.

## Гарантия {#guarantee}

- Лицензия каждой версии определяется по источникам в фиксированном порядке приоритета, а противоречие между источниками помечается и показывается целиком.
- SPDX-выражение разбирается полностью: `AND`, `OR`, `WITH` и `LicenseRef-*`.
- Неизвестная лицензия, нестандартный текст и `LicenseRef-*` всегда дают `review`, никогда не `allow`.
- Для `AND` итог — худшее из решений, для `OR` — лучшее (выбор за тем, кто использует пакет).
- Категории лицензий и решения по контекстам задаёт организация. Встроенного правила «GPL запрещена» нет.
- Решение по версии сохраняется и отдаётся через API версии.

## Как это устроено {#mechanism}

### Источники лицензии {#sources}

Для версии берётся источник с наибольшим приоритетом:

1. решение ручного review;
2. лицензия из SBOM версии (CycloneDX, SPDX);
3. лицензия из metadata публикации: `license` у npm, Cargo и NuGet, `License-Expression` у PyPI, `<licenses>` в POM у Maven;
4. лицензия, распознанная по тексту файла лицензии с уверенностью не ниже 0,9.

Если источники противоречат друг другу, версия получает пометку конфликта и показываются все источники. {{< term "sbom" >}} и отчёт сканера служат вторым и третьим источником.

### SPDX-выражения {#spdx}

Выражение разбирается чистой функцией, не зависящей от формата пакета. Решение по выражению строится так:

- идентификатор лицензии → решение политики для её категории и контекста;
- `лицензия WITH исключение` → решение политики для пары;
- `A AND B` → худшее из двух;
- `A OR B` → лучшее из двух;
- неизвестный идентификатор или `LicenseRef-*` → `review`.

Порядок решений: `allow` лучше `review`, `review` лучше `deny`.

### Категории и контексты {#categories}

Организация задаёт категории: permissive, weak copyleft, strong copyleft, network copyleft, proprietary и source-available, unknown и custom. Решение зависит от контекста использования: внутреннее, распространяемое, SaaS или встроенное.

**Стартовая политика** для нового развёртывания: permissive — `allow`; weak copyleft для распространяемого — `review`; strong и network copyleft для распространяемого и SaaS — `deny`; unknown — `review`. Организация меняет её под свои требования.

### Оценка вирусности {#virality}

Дополнительно оценочная модель может оценить, насколько сильно обязательства лицензии распространяются на производное ПО в конкретном контексте: при статическом или динамическом связывании, в отдельном процессе, по сети. Оценка полезна для нестандартных текстов, где таблица категорий молчит. Она только ужесточает решение: поднимает `allow` до `review` и задаёт порядок очереди проверки. `deny` она не смягчает. Юридического заключения оценка не даёт.

### Влияние на выдачу {#serving}

Решение `deny` само по себе не закрывает скачивание. Блокировку по лицензии организация включает отдельным правилом политики; по умолчанию лицензионное решение остаётся сигналом и поводом для проверки. Нарушение лицензионной политики порождает событие для SIEM.

## Границы гарантии {#limits}

> [!LIMITS]
> - **CRANE не выносит юридических вердиктов.** Решение `allow`, `review` или `deny` — результат применения политики организации, а не юридическое заключение. Юридическую трактовку лицензий даёт организация.
> - **Заявленная лицензия может не совпадать с действительной.** Автор пакета мог указать лицензию неверно; CRANE сверяет источники, но не гарантирует, что заявление правдиво.
> - **Распознавание по тексту вероятностное.** Лицензия по тексту файла принимается при уверенности не ниже 0,9; ниже этого порога она не считается источником.
> - **Нестандартные лицензии требуют человека.** `LicenseRef-*` и неизвестные тексты уходят на `review`, и решает его организация.
> - **Политика полностью на стороне организации.** Неверно настроенная категория даёт неверное решение: встроенных запретов нет.
> - **Оценка вирусности не снижает строгость.** Она не превращает `deny` в `review`.
