Сервер CRANE поставляется одним бинарником `crane`. Он принимает ровно один аргумент — роль: `serve`, `all`, `migrate` или `healthcheck`. Образ запускает `crane all`. Справочник описывает, что делает каждая роль, какие настройки ей нужны и с какими кодами она завершается.

Все роли пишут журнал в формате JSON в стандартный вывод и читают настройки из окружения и необязательного файла TOML: {{< xref "reference/environment-variables" >}}.

## Использование {#usage}

```text
crane <serve|all|migrate|healthcheck>
```

Любое другое число аргументов и любое другое имя роли дают запись об ошибке с текстом `использование: crane <serve|all|migrate|healthcheck>` и код завершения `2`.

## Роли {#roles}

| Роль | Что делает | Что нужно из конфигурации |
| --- | --- | --- |
| `serve` | Запускает API на {{< env "CRANE_HTTP_PORT" >}} и порт проб на {{< env "CRANE_ADMIN_PORT" >}}; работает до сигнала | {{< env "CRANE_DATABASE_URL" >}}, {{< env "CRANE_BLOBS" >}}, {{< env "CRANE_PUBLIC_URL" >}}, {{< env "CRANE_TOKEN" >}}; остальное необязательно |
| `all` | Синоним `serve`: отдельных фоновых задач у сервера нет | То же, что `serve` |
| `migrate` | Применяет миграции PostgreSQL и завершается | Только {{< env "CRANE_DATABASE_URL" >}}: токен, публичный адрес и blob не нужны |
| `healthcheck` | Запрашивает `/healthz/ready` на `127.0.0.1` и завершается | Только {{< env "CRANE_ADMIN_PORT" >}} |

Файл {{< env "CRANE_CONFIG" >}}, если путь задан, читается любой ролью до разбора остальных настроек. Нечитаемый или неверный файл останавливает любую роль.

## Коды завершения {#exit-codes}

| Код | Когда |
| --- | --- |
| `0` | Роль выполнена: `migrate` и `healthcheck` успешны, `serve` остановлен сигналом |
| `1` | Роль завершилась с ошибкой: неверная конфигурация, недоступные PostgreSQL или хранилище, занятый порт, неготовая проба. Причина в записи «роль завершилась с ошибкой», поле `error` |
| `2` | Ошибка использования: аргументов не один или роль неизвестна |

## serve {#serve}

Роль выполняет шаги по порядку. Любая ошибка останавливает запуск с кодом `1`.

1. Разбирает каталог ({{< env "CRANE_DATABASE_URL" >}}) и ключ шифрования ({{< env "CRANE_SETTINGS_KEY" >}}).
2. Подключается к PostgreSQL, если каталог постоянный. Ожидание соединения — не дольше 5 с. Читает таблицу `setting`.
3. Разбирает остальную конфигурацию: репозитории, кэш, пределы, сеть, токен, blob, namespace.
4. Открывает хранилище blob и создаёт недостающие hosted- и proxy-репозитории в каталоге.
5. Применяет {{< env "CRANE_NAMESPACES" >}}. Шаблон, занятый другой командой, останавливает запуск.
6. Занимает порты: сначала API, затем проб, оба на `0.0.0.0`. Занятый порт даёт ошибку `не удалось занять порт <порт>: <причина>`.
7. Пишет запись «сервер запущен» с полями `http_port`, `admin_port`, `repos`, `proxy_repos`, `npm_repos` и `npm_proxy_repos`.

Роль `serve` миграции не применяет: схему готовит `migrate`.

### Остановка {#shutdown}

Роль останавливается по `SIGINT` или `SIGTERM`: пишет «получен SIGINT» или «получен SIGTERM», завершает оба слушателя штатно, пишет «сервер остановлен» и выходит с кодом `0`.

## migrate {#migrate}

Роль подключается к PostgreSQL (ожидание не дольше 5 с) и применяет миграции. Успех — запись «миграции PostgreSQL применены». Параллельные запуски исключает блокировка. Проверки расширений PostgreSQL перед миграциями: {{< xref "deploy/requirements#extensions" >}}. При каталоге `memory` роль пишет «хранилище в памяти: миграций нет» и завершается с кодом `0`.

## healthcheck {#healthcheck}

Роль подключается к `127.0.0.1:<порт admin>`, запрашивает `/healthz/ready` и завершается с кодом `0` при ответе `200`. Вывода при успехе нет. Подробности пробы и таймаут: {{< xref "reference/ports-and-health#healthcheck" >}}.

## Журнал {#logging}

- Формат — JSON, по строке на событие. Поля события лежат на верхнем уровне строки.
- Уровень задаёт {{< env "RUST_LOG" >}}; значение по умолчанию — `info`.
- События журнала ИБ (цели `crane::audit`, `crane::access`, `crane::upstream`) пишутся всегда на уровне `info`: {{< env "RUST_LOG" >}} их не отключает.
