Страница описывает, как задать два хранилища CRANE: каталог и хранилище {{< term "blob" >}}. Каталог хранит метаданные в PostgreSQL, а blob — байты файлов пакетов в {{< term "cas" "CAS" >}}: локальной файловой системе или S3. Каталог задаёт {{< env "CRANE_DATABASE_URL" >}}, blob — {{< env "CRANE_BLOBS" >}}. Обе переменные обязательны.

Хранилища выбираются парой. Постоянный каталог работает только с постоянными blob, а каталог в памяти — только с blob в памяти. Смешанная пара не стартует: каталог в PostgreSQL после перезапуска ссылался бы на потерянные blob.

## Перед началом {#prerequisites}

- PostgreSQL и расширения нужных версий: {{< xref "deploy/requirements#postgresql" >}}.
- Для S3: бакет и учётная запись с правом `s3:ListBucket`. Пример для Compose: {{< xref "deploy/s3-storage" >}}.

## Шаги {#steps}

1. Выберите сочетание. В таблице три допустимых пары:

   | Режим | Каталог | Blob | После перезапуска |
   | --- | --- | --- | --- |
   | Память | `memory` | `memory` | Данные теряются |
   | Диск | `postgres://…` | `file:///абсолютный/путь` | Данные сохраняются |
   | S3 | `postgres://…` | `s3://бакет…` | Данные сохраняются |

   Значение `memory` пишется явно: молчаливый каталог в памяти потерял бы данные при перезапуске.

2. Задайте каталог. Адрес содержит пароль, поэтому передайте его файлом. Допустимы схемы `postgres://` и `postgresql://`. В пароле используйте только символы, безопасные в URL.

   ```dotenv
   CRANE_DATABASE_URL_FILE=/run/secrets/database_url
   ```

   Файл содержит одну строку:

   ```text
   postgres://crane:<пароль>@postgres:5432/crane
   ```

3. Задайте blob.

   ```dotenv
   CRANE_BLOBS=file:///data/blobs
   ```

   - `file:///абсолютный/путь`: путь абсолютный, без хоста и без параметров запроса. Сервер создаёт каталог, если его нет, и записывает файлы с `fsync`.
   - `s3://бакет[/префикс]?параметр=значение`: в запросе допустимы только несекретные параметры (`endpoint`, `region`, `allow_http` и подобные). Учётные данные в URL запрещены. Список параметров и пример: {{< xref "deploy/s3-storage#blobs-url" >}}.

4. Для S3 передайте статический ключ файлами, парой:

   ```dotenv
   AWS_ACCESS_KEY_ID_FILE=/run/secrets/s3_access_key_id
   AWS_SECRET_ACCESS_KEY_FILE=/run/secrets/s3_secret_access_key
   ```

   Правила:

   - нужна вся пара: один файл без второго даёт ошибку запуска;
   - {{< env "AWS_ACCESS_KEY_ID" >}} вместе с {{< env "AWS_ACCESS_KEY_ID_FILE" >}} (и то же для {{< env "AWS_SECRET_ACCESS_KEY" >}}) взаимоисключающие;
   - без файлов ключи, роли и метаданные берёт клиент S3 из обычных переменных `AWS_*`;
   - при `memory` и `file://` ключ не нужен, и сервер отказывается стартовать с ним;
   - ключей S3 нет среди ключей файла TOML: их задаёт только окружение.

5. Примените миграции до первого запуска сервера. Роль `serve` миграции не применяет.

   ```bash
   crane migrate
   ```

   Роль печатает в журнал «миграции PostgreSQL применены». При каталоге `memory` она печатает «хранилище в памяти: миграций нет» и завершается успешно. Подробности: {{< xref "reference/server-cli" >}}.

## Проверка {#verify}

Запустите сервер и проверьте готовность. Проба обращается к каталогу и к хранилищу blob и укладывается в 1,5 с:

```bash
crane healthcheck
echo $?
```

```text
0
```

Подробности пробы: {{< xref "reference/ports-and-health" >}}.

## Ошибки запуска {#errors}

Сообщения называют переменную и причину. Содержимое URL, пароль и ключи в текст не попадают: для чужой схемы называется только схема. Тексты на русском языке. Примеры идут по порядку: нет каталога, нет blob, смешанная пара, чужая схема каталога, неразобранный адрес каталога, чужая схема blob, неразобранный адрес blob, секретный параметр в запросе S3, ключ S3 при `memory`, недоступный PostgreSQL.

```text
не задана переменная CRANE_DATABASE_URL
не задана переменная CRANE_BLOBS
CRANE_DATABASE_URL и CRANE_BLOBS: memory нельзя смешивать с постоянным хранилищем
CRANE_DATABASE_URL: значение со схемой `mysql` пока не поддерживается
некорректное значение CRANE_DATABASE_URL: не разобран как URL postgres://
CRANE_BLOBS: значение со схемой `gs` пока не поддерживается
некорректное значение CRANE_BLOBS: ожидалось memory, file:///абсолютный/путь или s3://бакет
CRANE_BLOBS: ключ `access_key_id` не из списка несекретных параметров; учётные данные и их поставщики S3 задаются только переменными AWS_*
AWS_ACCESS_KEY_ID_FILE и AWS_SECRET_ACCESS_KEY_FILE: ключ S3 не нужен при memory
не удалось подключиться к PostgreSQL (CRANE_DATABASE_URL): …
```

Ошибки адреса {{< env "CRANE_BLOBS" >}} сервер находит при постоянном каталоге. Если каталог `memory`, любое значение blob, кроме `memory`, даёт ошибку смешанной пары.

Подключение к PostgreSQL сервер ждёт не дольше 5 с. Недоступная база останавливает старт, а не первый запрос.
