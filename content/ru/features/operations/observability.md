CRANE отдаёт телеметрию только в открытых форматах: метрики Prometheus и OpenMetrics, трассы и журналы OTLP, журналы JSON в stdout. Привязки к конкретному стеку нет: подходят VictoriaMetrics, Prometheus, Jaeger, VictoriaLogs, любой OpenTelemetry Collector или существующий стек организации. Телеметрия не влияет на обработку запросов.

Страница описывает, откуда снимать данные, какие метрики есть, что попадает в журналы и трассы и как строятся SLO и алерты. Значения настроек и порты текущего развёртывания описаны в разделе {{< xref "deploy" >}}.

## Точки съёма {#endpoints}

| Точка | Назначение | Кому доступна |
| --- | --- | --- |
| `GET /metrics` | Метрики OpenMetrics с exemplars (`trace_id`) | Только из сети мониторинга; в Helm есть ServiceMonitor и PodMonitor |
| `GET /healthz/live` | Процесс жив, цикл событий не завис | Kubelet |
| `GET /healthz/ready` | Готов принимать трафик: PostgreSQL и хранилище доступны. Valkey и upstream на готовность не влияют | Kubelet, балансировщик |
| `GET /healthz/startup` | Миграции применены, кэши прогреты | Kubelet |
| `GET /api/v1/status` | Версия, режим (`normal`, `read-only`, `degraded`), состояние компонентов и фидов, отставание экспорта в SIEM | Пользователи, `cctl diag`, внешние статус-страницы |
| OTLP | Трассы, журналы и по желанию метрики в OpenTelemetry Collector по gRPC или HTTP | Исходящий; задаются адрес и заголовки |

Метрики и пробы здоровья отдаются на служебном порту, отдельном от основного.

## Метрики {#metrics}

Все метрики имеют префикс `crane_`. Длительности измеряются в секундах, размеры в байтах. Таблица перечисляет группы и характерные метрики; полный каталог находится в справочнике ({{< xref "reference/metrics" >}}).

| Группа | Примеры метрик |
| --- | --- |
| Протоколы и API | Число запросов, длительность (гистограмма), запросы в обработке, размер ответов; метки формат, операция, класс статуса |
| Кэш и proxy | Запросы к кэшу по уровню и результату (попадание, промах, устаревшая копия), объединённые запросы, запросы к upstream и их длительность, признак доступности upstream |
| Публикация и хранилище | Публикации и их объём, число и объём blob, освобождённый сборкой мусора объём, сбои целостности, перенос между хранилищами, использование квот |
| Скачивания | Скачивания и байты по источнику (hosted, hit, stale, miss, coalesced) и команде; запросы metadata отдельно |
| Доступ | Решения авторизации, сбои аутентификации, сбросы эпохи авторизации, токены с истекающим сроком |
| Очереди и события | Задачи в очереди, возраст старейшей, мёртвые задачи, длительность, отставание outbox, доставки webhooks |
| Уязвимости | Открытые находки, нарушения SLA, принятые advisory, отставание фидов, время обнаружения, активные экстренные блокировки, возраст базы сканера |
| ИИ и скоринг | Запросы к моделям, длительность, токены, доля резервных провайдеров, распределение оценок, переопределения |
| A2A | Задачи, подтверждения и длительность |
| SIEM | События и отставание экспорта |
| Зависимости и среда выполнения | Пул соединений БД, длительность запросов, ошибки Valkey, длительность запросов к S3, загрузка среды выполнения, информация о сборке |

### Бюджет кардинальности {#cardinality}

Имена пакетов, пользователи, IP-адреса и токены в метки не попадают. Метки по команде ограничены самыми крупными командами (по умолчанию десять), остальные попадают в корзину `other`, а нераспределённые скачивания — в корзину `none`. Пакет, версия, принципал, токен и IP никогда не бывают метками. Цель — не больше 5000 рядов на реплику; текущее значение видно по метрике `crane_metric_series`.

## Журналы {#logs}

- **Формат.** JSON в stdout, одна строка на событие. Обязательные поля: время, уровень, сообщение, цель, `request_id`, `trace_id`, `span_id`. Для запросов добавляются формат, операция, статус, длительность, вид принципала (человек, робот, агент), команда и правило при отказе.
- **Потоки.** Журнал приложения и журнал доступа различает поле `stream`. Журнал доступа — операционный: ошибки пишутся в нём на 100%, а успешные скачивания прореживаются (по умолчанию сохраняется 10%), чтобы трафик CI не топил журналы.
- **Поля proxy.** В строке журнала доступа для proxy-репозиториев есть откуда пришёл ответ (`hit`, `miss`, `stale`, `stale-on-error`), почему upstream отказал (`refused`, `unavailable`, `throttled`, `digest-mismatch`, `too-large`) и причина. Ответ несёт заголовок `Age`, а для старых клиентов — `Warning`. Клиенту при этом уходит только «upstream недоступен».
- **Исходящие запросы.** Каждая реальная выборка из upstream пишется отдельной строкой в {{< term "security-journal" >}}: хост, путь без query, статус или причина отказа, время до заголовков. Заголовков, тел и ETag в строке нет. Запрос, обслуженный из кэша или присоединившийся к чужой выборке, строки не порождает, поэтому по числу строк виден реальный трафик к upstream ({{< xref "features/security/egress-guard#journal" >}}).
- **Аудит не журнал приложения.** Действия людей и решения доступа идут в неизменяемый аудит и в {{< term "siem" >}}, а не в журнал приложения: у них другие гарантии доставки и хранения. Полная запись скачиваний ведётся отдельным потоком ({{< xref "features/security/security-journal" >}}).
- **Редактирование.** Секреты не реализуют вывод в журнал на уровне типов, а дополнительный фильтр удаляет известные форматы токенов и заголовки `Authorization`.

## Трассировка {#tracing}

CRANE экспортирует трассы по OTLP и распространяет контекст по W3C Trace Context ({{< cite "w3c-trace-context" >}}). Входящий `traceparent` от CI и внешних агентов принимается, а к публичным upstream заголовки трассировки не отправляются.

- **Спаны:** обработка запроса протокола, решение авторизации, поиск в кэше, выборка из upstream, чтение и запись blob, запрос к БД, выполнение задачи, оценка и генерация AI, доставка в SIEM, задача A2A. Атрибут команды содержит slug команды атрибуции, идентификаторов людей в трассах нет.
- **Сэмплирование.** Parent-based, по умолчанию 1%, а ошибки и медленные запросы сохраняются полностью (tail sampling в Collector).
- **Exemplars** связывают точки гистограмм с трассами.

## SLO и алерты {#alerts}

SLI вычисляются из метрик. Алерты строятся по скорости сжигания бюджета ошибок в двух окнах: быстрое окно ловит острые аварии, медленное — тлеющие. Целевые показатели описаны на странице {{< xref "features/operations/availability#slo" >}}.

| Алерт | Условие | Серьёзность |
| --- | --- | --- |
| `CraneDownloadErrorBudgetBurn` | Бюджет доступности скачивания сжигается в 14,4 раза быстрее нормы за 1 час и 5 минут | page |
| `CraneMetadataLatencyHigh` | p99 metadata при попадании в кэш выше SLO 15 минут | page |
| `CraneReadOnlyMode` | Сервис в режиме только для чтения больше 5 минут | page |
| `CraneUpstreamDown` | Upstream недоступен 10 минут | ticket |
| `CraneQueueBacklog` | Возраст старейшей задачи больше 10 минут | ticket |
| `CraneJobDeadGrowth` | Растёт число мёртвых задач за 15 минут | ticket |
| `CraneOutboxLag` | Отставание outbox внешней доставки больше 5 минут | page |
| `CraneFeedLagging` | Фид уязвимостей не синхронизировался 30 минут | page |
| `CraneP0WithoutAction` | P0 открыт больше часа без блокировки или решения | page |
| `CraneVulnDbStale` | База сканера старше 24 часов | ticket |
| `CraneSiemExportLag` | Отставание экспорта в SIEM больше 5 минут | page |
| `CraneIntegrityFailure` | Любой blob с неверным SHA-256 | page |
| `CraneScoreDrift` | Распределение оценок модели сместилось относительно базовой недели | ticket |

Правила поставляются как PrometheusRule в Helm chart и как отдельный YAML для других систем.
