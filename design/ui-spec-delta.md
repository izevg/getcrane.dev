## 1. Корневые исправления (до любых новых компонентов)

**R1. Порядок слоёв (MUST).**
- Целевой порядок: `reset, primitive, semantic, base, layout, component, page, a11y`. Компоненты должны побеждать базовые стили элементов.
- После перестановки нельзя «чинить» слои через `!important` и повышенную специфичность.
- Приёмка: вычисленные стили (сверка в DevTools) по таблице раздела 4.2:
  - `a.term` — `text-decoration-style: dotted`, цвет `--foreground`;
  - `a.cite` — `text-decoration-line: none`;
  - `.chroma a.env` — цвет равен цвету токена Chroma;
  - `.tip-more` — `display: none` при `(hover: hover)`.

**R2. Источник «перечёркивания» (MUST).**
- Линия-соединитель схемы и полоса прогресса — отдельный декоративный элемент (`aria-hidden`), который стоит в DOM **раньше** узлов. Тогда он рисуется под ними без z-index.
- Узлы непрозрачны.
- Ни одна линия не пересекает текст ни на одной ширине.
- Псевдоэлементы `::after` контейнера для линии не используются.

**R3. Шапка на узких экранах (MUST: ни один элемент шапки не выходит за 320 CSS px в обоих языках).**
- Ниже 48rem: знак логотипа без словесного знака (у ссылки остаётся доступное имя «CRANE»), иконка поиска, ссылка на другой язык, кнопка темы, «Меню».
- «Документация» ниже 48rem уходит в меню.
- Ниже 48rem переключатель языка показывает только ссылку на другой язык («EN» / «RU»), текущий язык не дублируется.
- Логотип `flex: none`. Остальные элементы не сжимаются ниже своих целей.
- Цели 40×40 (44×44 на `pointer: coarse`).

**R4. Оглавление (MUST).**
- Считаются все `h2` страницы рекурсивно по дереву фрагментов, плюс «Источники».
- Порог: 3 и больше.
- ≥ 80rem — правая колонка; 64–80rem и ниже — сворачиваемый блок.
- [проверить в реализации: структура `.Fragments.Headings` в Hugo 0.157].

**R5. `content-visibility` на главной (MUST: убрать).**
- Секции небольшие, выигрыша почти нет, а цена — пустые области на полностраничных снимках и прыжки скроллбара.
- MAY оставить только на длинном справочнике переменных, с `contain-intrinsic-size`, измеренным по факту, и проверкой Ctrl F и якорей.
- [поддержка: `content-visibility` — не проверено на дату].

**R6. Подсказки: Esc и подавление (MUST).**
- После Esc фокус возвращается на триггер **без** повторного показа слоя.
- Подавление снимается при уходе фокуса с триггера или после `pointerleave` с него, а не только при новом фокусе.
- [норматив: 1.4.13].

## 2. Компонент `threat` — «Угроза → Ответ CRANE»

### 2.1 Контракт разметки (для `authoring.md`, правит руководитель документации)

- **MUST: заголовок угрозы остаётся обычным Markdown-заголовком** `### Slopsquatting {#slopsquatting}` перед шорткодом. Иначе ломаются якоря, xref, оглавление, проверка 1:1 якорей RU и EN и `.Fragments`. Параметр `title` поэтому не рендерится заголовком. MAY использовать его только как `aria-label` мини-схемы.
- Поля компонента:
  - `summary` — одно предложение до 140 знаков, обязательное;
  - `threat` — «как проявляется», 1–3 предложения, обязательное;
  - `answer` — список фактов, обязательный: цель 3–4 пункта, вне 3–4 предупреждение сборки, 0 или больше 5 пунктов ломают сборку;
  - `chips` — 0–4 чипа;
  - `more` — один путь xref, обязательный на страницах каталога;
  - `flow` — необязательная мини-схема, ровно 3 шага.
- MUST: внутри `threat` и пунктов `answer` работают `term`, `xref`, `env`, `cite` и inline-код. Поэтому эти тексты — **вложенное содержимое** шорткода, а не строковые параметры: в параметре шорткода другой шорткод не работает.
  - Форма вложения — TOLERANCE: вложенные части `threat-what` / `threat-answer` либо блок с разделителем.
  - [проверить в реализации: вложенные шорткоды и `.Inner` в Hugo 0.157].
- `chips` — список ссылок вида `term:<id>`, `xref:<путь>` или `label:<текст>`:
  - term и xref — чипы-ссылки с подсказкой (раздел 4.2);
  - `label` — неинтерактивная метка (например «Событие обнаружения»), без hover, без стрелки, приглушённая;
  - неизвестный id или путь ломает сборку (как у term и xref).
- `more` — чип-ссылка «Подробнее: <title цели>» в конце блока ответа. Вместо «См. …» внутри текста.
  - MUST: в тексте ответа нет второй ссылки на ту же цель.
- `flow` — три строки до 40 знаков: «кто/что → действие». Порядок фиксирован: 1 — источник угрозы, 2 — жертва или канал, 3 — ответ CRANE.

### 2.4 A11y, движение и печать

- Семантика:
  - `h3` (Markdown) → `h4` «Угроза» → `p` → `h4` «Ответ CRANE» → `ul`;
  - ландмарков и ролей `region` нет: семь угроз не должны засорять ландмарки;
  - `h4` в оглавление не попадают (оно строится по `h2` и `h3`).
- Цвет не единственный носитель смысла: тип блока задают `h4` и иконка [норматив: 1.4.1].
- Сворачивания по умолчанию нет. MUST: обе части всегда видны. Причины: Ctrl F, печать, семантика заголовка, сканирование. Резюме стоит первым и выполняет роль «до деталей». Сворачивание — OPEN для владельца.
- Движение: в компоненте его нет. У чипов только hover-цвет 150 мс. Под reduced-motion меняется ровно то же самое (ничего).
- forced-colors: оба блока получают `border: 1px solid CanvasText`, кромку 4 px `CanvasText`, иконки `currentColor`, узлы `flow` — рамку `CanvasText`.
- Печать: фоны могут не печататься, смысл держат `h4` и иконки.

### 2.5 Пример: slopsquatting (факты только из текущего текста страницы)

Тексты финально утверждает руководитель документации.
- `summary`: «Модель советует несуществующий пакет, атакующий регистрирует имя — CRANE держит такой пакет в карантине».
- `threat`: «Языковая модель советует установить пакет, которого не существует. Атакующий регистрирует это имя в публичном реестре и ждёт, пока совет выполнят».
- `answer`:
  - «Пакет без истории (возраст, скачивания, maintainer) из публичного upstream попадает в карантин»;
  - «До конца окна карантина версия не отдаётся»;
  - «Первое обращение к такому имени запускает правило SIEM»;
  - «Кандидат регистрируется как событие обнаружения».

## 3. Диаграммы

**Встраивание.**
- MUST: inline-SVG в `figure`, а не `img`. Причины:
  - mermaid с `htmlLabels: true` выводит подписи через `foreignObject`;
  - в `img` шрифты страницы недоступны, текст не выделяется;
  - CSS-переменные внутрь `img` не проходят.
- Обёртке ставится `role="img"` и `aria-labelledby` на `figcaption`. Внутренности SVG без ролей (скрипт уже чистит `role`, `aria-*`, `title`, `desc`).
- Темы — TOLERANCE:
  - (а) **два файла** `<hash>.light.svg` / `<hash>.dark.svg` (уже реализуется), неактивный — `display: none` по `data-theme`, без JS — по `prefers-color-scheme`. MUST: уникальные id внутри SVG (флаг `-I dg-<hash>-<theme>`);
  - (б) SHOULD как улучшение: один SVG, где сигнальные hex заменены на `var(--dg-*)` при генерации. Скрипт падает, если в выходе остался hex, которого нет в таблице замен (mermaid выводит производные цвета).
- Манифест с хешем исходника и отпечатком токенов уже есть. Нет SVG в production — сборка падает (есть).

**Стиль по токенам (themeVariables с hex токенов; `scripts/lib/mermaid-theme.ts` в основном верен).**
- `theme: "base"`; `darkMode: true` для тёмного варианта [mermaid.js.org/config/theming: настраивается только `base`, только hex].
- Узлы: `primaryColor` / `mainBkg` = `--card`, `primaryBorderColor` / `nodeBorder` = `--input`, `primaryTextColor` / `nodeTextColor` = `--foreground`.
- Связи: `lineColor` = `--muted-foreground`.
- Группы: `clusterBkg` = `--muted`, `clusterBorder` = `--border`, `titleColor` = `--muted-foreground`.
- Подписи связей: `edgeLabelBackground` = `--card`.
- Акцент (узлы CRANE): через `classDef` в исходнике — `--brand-container` / `--brand`. Внешние и необязательные компоненты — пунктирная рамка.
- `fontFamily` `"Onest Variable"`, `fontSize` 14px. MUST: при генерации подключён тот же woff2 (сейчас подключён), иначе рамки узлов рассчитаются по чужому шрифту и подписи обрежутся.
- Контраст: линии к `--card` 7.47 / 8.40 и к `--muted` 6.71 / 7.51 — ✓. Текст ≥ 11.9 — ✓. Рамки `--input` к `--card` 3.71 / 3.56 — ✓.

**Масштаб и узкие экраны.**
- SVG ширины `min(100%, естественная)`, высота по пропорции.
- MUST: текст диаграммы на экране не мельче 12 CSS px. Если при вписывании масштаб < 0.85, вместо сжатия включается горизонтальный скролл в регионе: `role="region"`, `aria-label` = подпись, `tabindex="0"` только при переполнении [норматив: 1.4.10 допускает двумерный скролл для графики, 2.1.1].
- Страница горизонтально не скроллится.
- SHOULD для авторов: диаграммы с больше чем 4 узлами в ряд — `TB`, а не `LR`.

**Подпись и состояние.**
- `figcaption` под диаграммой, `--type-small`, `--muted-foreground`.
- MUST: диаграмма целевой топологии получает атрибут `state="target"` в ограде и бейдж «Целевое состояние» в начале подписи (тот же бейдж, что в шапке страницы). Это закрывает топологию Kubernetes при странице Helm «в разработке».

**«Текст диаграммы».**
- При наличии SVG свёрнут (MUST).
- `summary` — тихий disclosure: шеврон `chevron-right` с поворотом, `--type-small`, `--muted-foreground`.
- Внутри — блок кода с копированием (раздел 4.3).

### 4.3 Подсказки: тайминги и движение

Правила статьи emilkowal.ski/ui/great-animations (прочитана 29.10.2026):
- анимации короче 300 мс;
- ease-out для отклика;
- только `transform` и `opacity`;
- прерываемые transitions вместо keyframes;
- не анимировать действия с клавиатуры;
- reduced-motion — фейд вместо сдвига.

| Параметр | Значение | Допуск |
| --- | --- | --- |
| Открытие при наведении | 120 мс | MUST ≤ 150, 100–150 |
| Соседний триггер, пока слой открыт **или закрыт меньше 300 мс назад** | 0 мс, без анимации входа (приём `data-instant` продукта, `GROUP_TIMEOUT_MS` 300) | 200–300 мс окно |
| Закрытие после ухода указателя | 150 мс; на слое — держать | 120–200 |
| Вход | `opacity` 0→1 + `translateY(4px)`→0 (сверху от триггера — `-4px`), 150 мс, `--ease-out` = `cubic-bezier(0.23, 1, 0.32, 1)` | 120–180 мс; MAY только фейд, как `anim-fade` продукта |
| Выход | Только `opacity`, 90 мс | ≤ 100 мс, короче входа (MUST) |
| Открытие с клавиатуры (фокус, Enter) | Без анимации, мгновенно | MUST |
| Reduced motion | Только `opacity`, ≤ 100 мс | — |

- MUST: переходы прерываемые. Повторный hover во время выхода разворачивает transition, а не перезапускает keyframes.
- MUST: длительности и easing берутся из motion-токенов, а не из ключевых слов CSS (P16).
- `@starting-style` и `transition-behavior: allow-discrete` [поддержка: Baseline Newly с 06.08.2024 — web-features, проверено ранее 29.10.2026]. Без них — без анимации.
