CRANE не отдаёт из публичного {{< term "upstream" >}} пакет, имя которого считается внутренним. На запрос такого имени любой proxy отвечает `404`, не обращаясь ни к кэшу, ни к upstream. Это закрывает {{< term "dependency-confusion" >}}: публичный пакет с внутренним именем не может подменить внутренний.

Имя становится внутренним двумя путями: его покрывает {{< term "namespace" >}} или оно уже опубликовано в hosted-репозитории. Первая публикация нового имени сама резервирует его.

## Угроза {#threat}

{{< threat summary="Пакет из публичного реестра с внутренним именем и версией выше попадает в сборку — CRANE не отдаёт внутреннее имя из upstream." chips="term:dependency-confusion, term:namespace" flow="Атакующий публикует то же имя \| Менеджер берёт версию повыше \| CRANE отвечает 404 на внутреннее имя" >}}

Менеджер пакетов, настроенный на несколько источников, выбирает наибольшую версию, и в сборку попадает чужой код. Атаку описал {{< cite "birsan-dependency-confusion" >}}. Клиенты вроде pip с `--extra-index-url`, NuGet и Maven с `maven-metadata.xml` умеют сливать версии из нескольких индексов, поэтому порядок источников защитой быть не может.

## Гарантия {#guarantee}

- **Инвариант.** Внутреннее имя никогда не отдаётся из upstream.
- Proxy любого формата отвечает на внутреннее имя `404` до обращения к кэшу и upstream и не раскрывает причину: скрытое неотличимо от несуществующего.
- Каждый такой отказ пишется в {{< term "security-journal" >}}, и на нём построено правило SIEM «Разведка dependency confusion».
- Hosted-репозиторий не принимает имя, которое занято в публичном реестре или принадлежит чужой команде.
- Резервирование не снимается неявно.

## Как это устроено {#mechanism}

### Что считается внутренним {#internal}

Имя (формат и нормализованное имя) внутреннее, если выполняется одно из двух условий:

1. его покрывает namespace этого формата;
2. строка пакета с этим именем есть в любом hosted-репозитории этого формата.

Второе условие означает, что первая публикация в {{< term "hosted-repository" >}} и есть резервирование: строку пакета создаёт та же транзакция, что и первую версию. Строки пакетов никогда не удаляются: у версий остаётся только {{< term "tombstone" >}}. Защита действует на формат, а не на конкретный {{< term "proxy-repository" >}}.

### Шаблоны и нормализация {#patterns}

Шаблон namespace — точное имя или префикс с одной `*` в конце сразу после разделителя формата; основа префикса не пуста. Поэтому `acme-*` не покрывает `acmecorp`, а `com.acme.*` не покрывает `com.acmecorp:x`. Имена нормализуются по правилам формата:

| Формат | Нормализация | Префикс | Разделитель |
| --- | --- | --- | --- |
| Cargo | нижний регистр, `-` ≡ `_` (хранится `_`) | `acme-*` → `acme_*` | `-` или `_` |
| PyPI | {{< cite "pep-503" >}}: нижний регистр, серии `-_.` → `-` | `acme-*` | `-` |
| Maven | регистр сохраняется; имя `groupId:artifactId` | только по groupId: `com.acme.*` покрывает groupId `com.acme` и `com.acme.*` | `.` |
| NuGet | нижний регистр | `Acme.*` → `acme.*` | `.` |
| npm | регистр сохраняется | только scope `@acme/*`; префиксы без scope запрещены | `/` после scope |

### Разрешение и вырезание {#resolution}

Побеждает самый специфичный покрывающий namespace: сначала точное имя, затем самый длинный префикс. Это правило задаёт и владельца имени, и приоритет hosted над proxy. Для Cargo имя `acme_payments_core` проверяется по шаблонам `acme_payments_core`, `acme_payments_*`, `acme_*`; для Maven имя `com.acme.b:c` — по `com.acme.b:c`, `com.acme.b.*`, `com.acme.*`, `com.*`.

Владелец namespace — команда ({{< term "workspace" >}}). Платформенная команда может владеть `com.acme`, а команда payments — `com.acme.payments`: подпространство «вырезано». Имя под родителем, не вырезанное отдельно, принадлежит владельцу родителя. Вырезать подпространство для другой команды и вообще создавать namespace, который пересекается с namespace другой команды, может только администратор платформы со {{< term "step-up" >}}. Вложенность внутри одной команды разрешена. Каждое резервирование и вырезание — событие аудита `Reserve` с актором и контекстом запроса.

### Правило публикации в hosted {#publish-rule}

Правило проверяется после проверок репозитория и до чтения тела запроса.

| Условие | Результат |
| --- | --- |
| npm, имя без scope | `422` |
| Имя покрыто namespace другой команды | `403` |
| Имя покрыто своим namespace или уже есть в hosted того же формата | Публикация допускается |
| Новое имя, upstream его не знает | Публикация допускается и становится резервированием (событие `Reserve` с точным именем вдобавок к событию публикации) |
| Новое имя, upstream его знает | `403` |
| Upstream недоступен | `503` |

Резервирование широко известного публичного имени, префикса или scope требует администратора платформы со step-up.

Наличие имени в upstream CRANE выясняет тем же движком и тем же кэшем, что и proxy. Для Cargo запрашивается API crates.io по каноническому имени: индекс не подходит, потому что его путь зависит от написания и `serde-json` не находил бы публичный `serde_json`. Для npm запрашивается packument registry.npmjs.org. Ответ документа, в том числе устаревший, означает «имя публично»; «не найдено» — «имени нет»; любой другой сбой — «неизвестно», и публикация получает `503`.

### Почему в npm только scoped-имена {#npm-scoped}

npm выбирает реестр по scope. Внутренний пакет без scope нельзя защитить от dependency confusion: клиент ищет такое имя и в публичном реестре. Поэтому hosted-репозиторий npm принимает только scoped-имена.

### Почему групповых репозиториев нет {#no-groups}

CRANE не сливает hosted и proxy под одним адресом. Безопасность держит инвариант имён, а не порядок источников: даже клиент, который сам объединяет индексы hosted и proxy, не получит публичную версию внутреннего имени, потому что любой proxy формата отвечает на него `404`. Подробнее о ролях репозиториев: {{< xref "features/registry/proxy-cache" >}}.

> [!PLATFORM]-
> **Как проверяется имя**
>
> Список шаблонов-кандидатов имени строится от самого специфичного к наименее специфичному, и один запрос по индексу (`pattern = ANY(...)`, без `LIKE`) находит покрывающий. Проверка стоит единой точкой перед кэшем и upstream во всех proxy. Если каталог недоступен или отвечает ошибкой, защита закрывается: CRANE отказывает ({{< term "fail-closed" >}}), а клиент получает `503` с `Retry-After`. Источник истины для проверки — каталог, а не кэш реплики.

## Границы гарантии {#limits}

> [!LIMITS]
> - **npm без scope не защищается.** Имена без scope не принимаются в hosted-репозиторий, а значит их нельзя зарезервировать. Внутренние пакеты npm публикуют под scope.
> - **Upstream недоступен — отказ.** Если CRANE не может узнать, занято ли новое имя в публичном реестре, публикация получает `503`. Публичное имя не затеняется, внутреннее не остаётся незарезервированным.
> - **Резервирование не снимается неявно.** Удаление записи из конфигурации резервирование не снимает: резервирования только добавляются.
> - **Формат без proxy.** Если для формата не настроен proxy, CRANE не проверяет, есть ли имя в публичном реестре: затенять нечего.
> - **Защита работает на стороне CRANE.** Клиент, который обращается к публичному реестру напрямую, мимо CRANE, защищён только собственной настройкой.
