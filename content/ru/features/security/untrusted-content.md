Байты пакетов, их metadata, {{< term "evidence" >}} и README недоверенны: их написал автор пакета, а не владелец реестра. CRANE отдаёт их так, чтобы браузер не мог исполнить такое содержимое от имени консоли: протоколы и ссылки на файлы идут с отдельного origin пакетов, на ответах стоят защитные заголовки, консоль работает со строгой CSP, а README показывается без загрузки внешних картинок.

Так файл `-docs.html` или `.svg` внутри пакета не получает доступа к сессии специалиста по безопасности, а README не сообщает автору пакета, кто и когда открыл карточку.

## Угроза {#threat}

Пакет Maven содержит файл `-docs.html` или `.svg` со скриптом. Специалист по безопасности открывает ссылку на этот файл из консоли. Если файл отдан с того же origin, что и консоль, браузер исполняет скрипт как часть консоли. Скрипт читает `csrf_token` из `GET /api/v1/session` и выполняет действия от имени пользователя: например, снимает блокировку или выпускает токен.

`SameSite=Strict` здесь не помогает. Защита `SameSite` запрещает отправлять cookie с чужого сайта, а скрипт из файла работает на самом origin консоли: его запросы считаются своими, а CSRF-токен он читает сам.

Вторая угроза слабее, но реальна. README в Markdown содержит картинку с адреса автора пакета. Консоль, загрузив её при открытии карточки, отправляет автору запрос с IP-адресом и временем просмотра: «пиксель слежки» показывает атакующему, когда пакет изучают AppSec и SecOps.

## Гарантия {#guarantee}

- Протоколы пакетных менеджеров и ссылки на скачивание файлов отдаются с отдельного origin пакетов. Origin пакетов не отдаёт консоль и `/api`, консоль не отдаёт протоколы.
- На каждом таком ответе стоят `X-Content-Type-Options: nosniff`, `Content-Security-Policy: sandbox; default-src 'none'` и `Content-Disposition: attachment`. Исключение — JSON-документы протоколов, их `Content-Disposition` не нужен.
- Консоль работает со строгой CSP: только ресурсы собственного origin, без inline-скриптов и `unsafe-eval`.
- Сырой HTML из README не исполняется. Внешние картинки не загружаются, а показываются ссылкой.

## Как это устроено {#mechanism}

### Отдельный origin пакетов {#origin}

Браузер изолирует страницы по origin. Если файл пакета открывается на origin, где нет ни консоли, ни API, скрипт внутри файла не видит ни cookie сессии, ни CSRF-токен консоли. Поэтому адреса протоколов и presigned-ссылки на файлы указывают на origin пакетов, а адреса в конфигурации клиентов, которые подготавливает CLI, берутся с него же.

Лучше отдельный регистрируемый домен. Поддомен допустим: cookie сессии привязана к хосту (`__Host-`), а изменения требуют CSRF-токена и проверки `Origin`. Настройка адресов описана на странице {{< xref "configure/network" >}}.

### Заголовки ответа {#headers}

Три заголовка работают вместе, и каждый закрывает свой обход:

- `X-Content-Type-Options: nosniff` запрещает браузеру угадывать тип содержимого и исполнять файл как HTML или скрипт, если сервер назвал его иначе.
- `Content-Security-Policy: sandbox; default-src 'none'` помещает документ в песочницу без прав и запрещает любые загрузки ресурсов. Даже открытый `.svg` или `.html` не выполнит скрипт.
- `Content-Disposition: attachment` велит браузеру сохранить файл, а не показать его.

### Строгая CSP консоли {#console}

Консоль не вставляет в страницу ничего недоверенного без санитайзера и ограничивает сама себя политикой, которая запрещает внешние ресурсы.

> [!SECURITY]-
> **Заголовки консоли**
>
> `Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; font-src 'self'; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'self'; frame-ancestors 'none'`
>
> Дополнительно: `Referrer-Policy: no-referrer`, `X-Content-Type-Options: nosniff`, `Cross-Origin-Opener-Policy: same-origin`. Inline-скриптов и `unsafe-eval` нет; исключение из этого правила требует отдельного решения.

### README и metadata {#readme}

README отображается через Markdown-рендерер с санитайзером HTML. Сырой HTML в исходном тексте пропускается, а результат дополнительно проходит санитайзер: слоёв несколько намеренно, потому что текст недоверенный.

- Внешняя картинка (адрес `http` или `https`) не загружается. Вместо неё консоль показывает ссылку с подписью картинки или с её адресом. Картинка внутри ссылки (бейдж) показывается подписью.
- Картинка с другим адресом (`data:` или относительным) ссылкой не становится: остаётся только подпись.
- Внешние ссылки открываются в новой вкладке с `rel="noopener noreferrer nofollow"`.
- Элементы `iframe` и формы вырезаются.

## Границы гарантии {#limits}

> [!LIMITS]
> - **Разделение origin — условие гарантии.** Если адрес origin пакетов не задан или его хост совпадает с хостом консоли, гарантия действует не полностью. Проверка безопасной конфигурации сообщает об этом предупреждением и событием, а в строгом режиме CRANE отказывается стартовать.
> - **Гарантия защищает браузер и консоль, а не сборку.** Пакет, который клиент установил, исполняется там, где его установили. Оценка содержимого пакета — задача {{< xref "features/security/evidence-and-scanning" >}}.
> - **Защита опирается на браузер.** Заголовки действуют, пока браузер их соблюдает.
> - **README остаётся недоверенным текстом.** Ссылка в README может вести на любой адрес. Консоль помечает внешние ссылки, но не проверяет, куда они ведут.
> - **JSON-документы протоколов отдаются без `Content-Disposition`.** Они нужны клиентам пакетных менеджеров как данные и не отображаются как страница.
