# UI-SPEC: getcrane.dev — главная и текстовые страницы

Версия спеки от 29.10.2026. Автор — UI-лид веба. Спеку реализует один fe-coder. Отметки в тексте:
- **MUST** — инвариант. Отступить можно только с письменным обоснованием в отчёте.
- **SHOULD / MAY** — допуск: подгоняется без согласования.
- *мнение* — вкус UI-лида, а не норматив.
- `[норматив: …]` — WCAG или контракт `authoring.md` / `ia.md`.
- `[поддержка: … (источник, 29.10.2026)]` — проверено по первоисточнику.
- `[не проверено]` — не проверено по первоисточнику.
- `[проверить в реализации: …]` — зависит от стека, проверяет исполнитель.

Спека задаёт **что и с какими допусками**. Значения CSS (`cubic-bezier(…)`, `#hex`, `clamp(…)`) — язык спеки, а не готовый код.

## CONTEXT

- **Задача пользователя.** Понять за один экран, что CRANE защищает цепочку поставки и где кончаются его гарантии. Затем выбрать свой путь (разработчик, платформа, безопасность, аудит) и дойти до работающего результата или до точного факта.
- **Где живёт.** Репозиторий `getcrane.dev` (сабмодуль `docs/site` в CRANE): Hugo extended, GitHub Pages, домен getcrane.dev. Пути `/ru/…` и `/en/…`, корень `/` — выбор языка (`ia.md`).
- **Целевые браузеры** (предложение: browserslist сайта ещё не задан). Две последние мажорные версии Chrome, Edge, Firefox, Safari macOS и Safari iOS, Chrome Android.
  - Основа: функции со статусом Baseline Widely available.
  - Newly available — только как основа с фолбэком или как прогрессивное улучшение.
  - Limited — только как улучшение.
  - Firefox ESR [не проверено, какая ESR актуальна на дату] должен читаться без улучшений.
- **Ограничения среды.** Статика. GitHub Pages не даёт своих заголовков ответа (кэш, CSP через заголовок) [проверить в реализации: TTL кэша Pages]. Во время работы страницы нет внешних CDN: шрифты, скрипты, иконки, Pagefind и mermaid лежат в сборке.
- **Проверка на машине.** Ничего не запускалось: спека составлена по файлам и первоисточникам.

## DS FIT

**Источник визуальной системы — веб-консоль CRANE** (`web/src/shared/styles/tokens.css`, `motion.css`, `app/entry/index.css`; `docs/ui/*`).

Переиспользуются:
- **Палитра.** Все семантические токены светлой и тёмной темы: `--background`, `--foreground`, `--card`, `--popover`, `--muted`, `--muted-foreground`, `--hint`, `--border`, `--input`, `--ring`, `--brand`, `--brand-container`, `--brand-border`, `--primary*`, статусы `--success|warning|error|info` с `-bg` и `-strong`, `--surface-high(est)`, `--inverse*`, `--code-bg`, `--char-digit|symbol(-inverse)`, `--scrim`.
- **Форма:** `--radius` 12 px, `--radius-card` 16 px, `--shadow-subtle`, `--shadow-card`.
- **Движение:** `--ease-out` `cubic-bezier(0.23, 1, 0.32, 1)`, `--ease-in-out`, `--dur-instant` 100, `--dur-fast` 150, `--dur-base` 200, `--dur-slow` 250, `--dur-max` 300 мс, а также блок `prefers-reduced-motion` с этими длительностями.
- **Шрифты.** Onest Variable (текст и заголовки) и JetBrains Mono Variable (только код и машинные значения, лигатуры выключены). Оба под OFL с кириллицей (проверено: google/fonts `ofl/onest/METADATA.pb` — license OFL, subsets cyrillic/cyrillic-ext/latin…, wght 100–900; `ofl/jetbrainsmono/METADATA.pb` — OFL, cyrillic, wght 100–800; 29.10.2026). Решение владельца D11 (`docs/ui/decisions.md`) уже исключило шрифты стороннего кита. **Замена не нужна.**
- **Правила консоли, которые сайт наследует.** Моноширинный — только для машинных значений и кода (D12). Цветовая разметка символов — только для хэшей, UUID и префиксов (D13), PURL и версии не размечаются. Форматы не раскрашиваются разными цветами (R14). Фокус — `outline: 2px solid var(--ring)` со смещением 2 px. Тема меняется мгновенно, без транзиций цвета.
- **Логотип:** `brand/crane-mark.svg`; словесный знак inline с `currentColor`. Градиент — только внутри знака, как в консоли.

**MUST (бренд и публичность).**
- В публичных файлах сайта (CSS, JS, HTML, исходники в публичном репозитории) нет упоминаний чужого UI kit и его бренда. Первая строка `tokens.css` консоли и комментарии `colorScheme.ts` / `index.css` содержат такое упоминание. Значения переносятся **без этих комментариев**, комментарии пишутся заново по-русски, о сути.
- Иконки — свой набор SVG под OFL/MIT/ISC (например, Lucide под ISC [не проверено: актуальная лицензия на дату]), инлайн или локальный спрайт. Логотипы экосистем и сторонних сервисов не используются: только текст.
- Лицензия OFL требует распространять шрифт вместе с текстом лицензии. В `static/fonts/` лежит `OFL.txt` для каждого семейства, а на странице «О сайте» или в подвале есть строка с авторами шрифтов. [проверить в реализации: выбрать место строки]

**Чего ДС не покрывает. Предлагается добавить токены уровня component** (раздел «Токены сайта»):
- выноски пяти тонов, LIMITS, аудиторные блоки;
- чипы аудитории, бейджи жанра, состояния и статуса;
- подсветка синтаксиса;
- подсказки;
- типографская шкала для длинного текста (у консоли body 14 px — это мало для документации);
- раскладка сайта.

### Общие зоны (обе страницы)

| Зона | Содержимое | Правила |
| --- | --- | --- |

| Шапка | Логотип (ссылка на главную языка) · «Документация» (ссылка на `start/`) · триггер поиска · языки · тема · «Исходный код» (ссылка на репозиторий, текстом) · на узких экранах кнопка «Меню» | Высота 56 px (SHOULD 56–64). Sticky на экранах высотой ≥ 30rem; ниже — статичная (MUST: при зуме 400 % sticky-шапка съедает треть вьюпорта) [норматив: 1.4.10, 2.4.11]. `scroll-padding-top` = высота шапки + 8 px (MUST) |

Ландмарки: `header` (banner), `nav` (каждый с уникальным `aria-label`), `main`, `aside` (оглавление), `footer` (contentinfo). На странице ровно один `h1`.

### Главная (`/ru/`, `/en/`)

**Сетка.** Контейнер max 1280 px. Поля: `clamp(16px, 4vw, 32px)`. 12 колонок, гаттер 24 px (16 px ниже 64rem). Шаг 4 px, ритм 8 px. Вертикальный интервал между секциями `clamp(4rem, 2.5rem + 5vw, 7.5rem)`.

**Порядок секций — MUST** [норматив: `ia.md`, принцип 1 — безопасность первой]. Порядок в DOM = порядок чтения = порядок фокуса [норматив: 1.3.2, 2.4.3]:

1. **Первый экран (hero): безопасность цепочки поставки.**
   - Overline (`text-overline`): «Self-hosted реестр пакетов и proxy upstream».
   - `h1` (до ~ 18 знаков в строке, `text-wrap: balance`): что CRANE гарантирует для цепочки поставки.
   - Лид, 1–2 предложения, ≤ 60ch: пять форматов и ключевые механизмы.
   - Две кнопки:
     - primary «Первый запуск» → `start/quickstart`;
     - secondary «Угрозы и гарантии» → `features/security/supply-chain-threats`.
   - **Схема «путь пакета»** (см. ниже).
   - Тексты — черновик в разделе CONTENT. Финальную формулировку утверждает ED, каждое утверждение должно опираться на страницу Features.
2. **Гарантии и их границы.** `h2` «Гарантии и их границы». Сетка из 6–8 карточек (см. анатомию). Под сеткой ссылка «Все гарантии» → `features/security/`.
3. **Путь по аудиториям.** `h2` «С чего начать». Четыре карточки-входа (`developer`, `platform`, `security`, `auditor`) по столбцу «Вход» из `ia.md`.
4. **Форматы.** `h2` «Пять экосистем». Пять текстовых плиток Cargo, npm, PyPI, Maven, NuGet → `formats/<id>`. На каждой одна строка: протокол или вид репозитория, из `description` страницы формата.
5. **Развёртывание.** `h2` «Развёртывание». Три карточки: «Один бинарник» (роли `crane`), «Docker Compose на одном узле» → `deploy/docker-compose`, «Kubernetes и Helm» → `deploy/kubernetes-helm`. В каждой 1–2 строки и, MAY, одна реальная команда из `deploy/`.
6. **Начало работы.** Полоса со ссылками: «Что такое CRANE» (`start/`), «Первый запуск», «Основные понятия», «Требования» (`deploy/requirements`).
7. Подвал.

**Анатомия схемы «путь пакета» (hero).**
- Семантически это упорядоченный список `<ol>` с подписью `aria-label` «Путь пакета через CRANE», а не картинка.
- Шаги:
  1. `upstream` (публичный реестр);
  2. группа «CRANE» — «namespace», «карантин», «дайджест», «неизменяемое хранение» (каждый узел — ссылка на страницу гарантии);
  3. «клиент сборки».
- Подписи узлов — метки до 2 слов; моноширинный только для машинных имён.
- Линия между узлами — декоративный элемент `aria-hidden`.
- Раскладка:
  - ≥ 64rem: горизонтальная, на всю ширину контейнера под текстом hero;
  - ниже 64rem: вертикальная, линия слева;
  - ≥ 48rem узлы в один ряд; если не помещаются, перенос, а не горизонтальный скролл [норматив: 1.4.10].
- Фон hero: статичная тонкая сетка в 1 px из `--border` с радиальным затуханием к краям. Это декор, на контраст текста не влияет: текст лежит на `--background`. *мнение*
- MAY: под схемой карточка «Пример отказа» — реальная команда клиента и реальный ответ CRANE на подмену namespace. Требование: текст ответа взят из кода (problem+json, сообщения формата), ED проверяет по коду. Выдуманный вывод запрещён [норматив: `authoring.md`, «Примеры»].

**Анатомия карточки гарантии.**
- Шапка карточки — `h3` со ссылкой на страницу гарантии. Ссылка растянута на всю карточку псевдоэлементом. Вложенных ссылок нет, у карточки один таб-стоп.
- Утверждение: одно предложение, которое можно проверить, взято из раздела `#guarantee` страницы.
- Строка границы: иконка LIMITS, подпись «Граница:» и одно предложение из `#limits`. Цвет `--muted-foreground`.
- Метка доступности (MUST): если настройка гарантии — страница `in-development`, на карточке бейдж «В разработке». Главная не создаёт впечатления, что механизм уже доступен [норматив: `ia.md`, принцип 3; этика].
- Источник данных — файл данных главной с полями `title`, `claim`, `limit`, `href`, `availability`. Писатель и ED правят тексты, а не шаблон [проверить в реализации: имя файла в `data/`].
- Сетка:
  - ≥ 64rem — 3 колонки, первые две карточки (неизменяемые версии, проверка дайджестов) занимают по 6 из 12 колонок, остальные по 4;
  - 40–64rem — 2 колонки;
  - < 40rem — 1.
  - Container query внутри карточки: при ширине < 18rem строка границы уходит под утверждение, иконка — в строку с подписью.

**Карточка аудитории.**
- `h3`: роль («Разработчик», «Инженер платформы», «Специалист по безопасности», «Аудитор»).
- Строка «что ищет» из `ia.md`.
- Список из 2–3 ссылок по маршруту «Вход».
- Ссылок несколько, поэтому карточка **не** растягивает одну ссылку на всю площадь.
- Сетка: ≥ 80rem — 4 колонки, 40–80rem — 2, ниже — 1.

**Плитки форматов и развёртывания.** Карточки со ссылкой, растянутой на площадь. Без цветов экосистем [норматив: консоль R14 — цвет без смысла]. Форматы ≥ 64rem — 5 в ряд; ниже — авто-сетка `minmax(10rem, 1fr)`.

### Текстовая страница

| Ширина | Раскладка |
| --- | --- |
| ≥ 80rem (1280) | Три колонки: дерево разделов 16–18rem · контент (колонка текста ≤ 72ch) · оглавление 13–15rem. Дерево и оглавление sticky под шапкой, со своим скроллом |
| 64–80rem | Дерево + контент. Оглавление — сворачиваемый блок «На этой странице» над текстом, после шапки страницы |
| < 64rem | Одна колонка. Дерево — в модальной панели «Меню» из шапки. Оглавление — сворачиваемый блок, как выше |

Порядок в DOM: шапка сайта → дерево → `main` (крошки → шапка страницы → «Термины на странице» → оглавление-блок для узких → текст → «Источники» → «Предыдущая / Следующая») → оглавление-aside → подвал. Визуально дерево слева, оглавление справа — это совпадает с DOM.

**Шапка страницы (внутри `main`).** Сверху вниз:
- крошки;
- `h1`;
- ряд меток: чипы аудитории из `audience` (первая — минимальная аудитория), бейдж жанра, бейдж состояния (`target`/`current`), при `status: in-development` бейдж «В разработке»;
- `description` как лид (`text-body-lg`, `--muted-foreground`, ≤ 60ch);
- строка действий: «Копировать как Markdown» · «Markdown-версия» (ссылка) · [«Открыть в ассистенте» — до согласования не выводится].

**Дерево разделов.**
- `nav aria-label="Разделы документации"`. Вложенные `ul`, ветки — `details/summary`.
- Ветка текущей страницы раскрыта сборкой (атрибут `open`). Текущая страница — `aria-current="page"`.
- Порядок по `weight`; Features сначала «Безопасность прежде всего» [норматив: `ia.md`].
- Без JS дерево работает полностью.

**Модальная панель «Меню» (< 64rem).**
- `<dialog>`, открывается через `commandfor` / `command="show-modal"` без JS. [поддержка: invoker commands — Baseline Newly available с 12.12.2025: Chrome 135, Firefox 144, Safari 26.2 (web-features explorer, 29.10.2026)]
- Фолбэк для браузеров без invoker commands и без JS: кнопка «Меню» — это ссылка на якорь `#site-nav`, где дерево выведено после `main`. Остров JS заменяет ссылку кнопкой.
- Панель слева, ширина `min(22rem, 100vw - 3rem)`. Фон под ней — `--scrim`.

**Крошки.**
- `nav aria-label="Навигационная цепочка"` / `"Breadcrumb"`, `ol`.
- Последний элемент — текст с `aria-current="page"`, не ссылка.
- < 40rem: виден только родитель в виде «← <Раздел>». Полная цепочка остаётся в DOM для скринридера (визуально скрыта). *мнение*
- Крошки одни на страницу (наследие консоли R5).

**Оглавление.**
- `aside` → `nav aria-label="На этой странице"`. Уровни `h2` и `h3`.
- Скрыто, если на странице меньше трёх `h2`.
- Подсветка текущего раздела — только визуальная, без смены фокуса и без объявлений. MAY: `aria-current="true"` на активной ссылке. *мнение: SHOULD подсветку, MAY aria-current*

**Предыдущая / следующая.** Две карточки внизу по порядку навигации раздела. Подпись «Назад» / «Далее» и название страницы.

## TYPOGRAPHY

**Шкала сайта** (новые токены `--type-*`). Все размеры в `rem`, fluid через `clamp(rem, rem + vw, rem)`. Отношение max/min ≤ 2,5, поэтому зум 200 % увеличивает текст как минимум вдвое [норматив: 1.4.4; подход Utopia].

| Токен | Размер | Межстрочный | Начертание | Где |
| --- | --- | --- | --- | --- |
| `--type-display` | `clamp(2.25rem, 1.6rem + 3vw, 4rem)` | 1.05 | 650, `letter-spacing: -0.02em` | `h1` главной |
| `--type-h1` | `clamp(1.875rem, 1.6rem + 1.2vw, 2.5rem)` | 1.15 | 600 | `h1` текстовых страниц |
| `--type-h2` | `clamp(1.375rem, 1.25rem + 0.6vw, 1.75rem)` | 1.25 | 600 | |
| `--type-h3` | `1.1875rem` | 1.35 | 650 | |
| `--type-h4` | `1rem` | 1.5 | 700 | |
| `--type-lead` | `clamp(1.125rem, 1.05rem + 0.3vw, 1.25rem)` | 1.55 | 400 | лиды |
| `--type-body` | `clamp(1rem, 0.97rem + 0.15vw, 1.0625rem)` | 1.65 RU / 1.6 EN | 400 | текст |
| `--type-small` | `0.875rem` | 1.5 | 400 | таблицы, подписи |
| `--type-caption` | `0.8125rem` | 1.45 | 400 | метки, бейджи |
| `--type-code` | `0.9em` от окружения (блоки — `0.875rem`) | 1.6 в блоках | 400 | код |

Допуск (TOLERANCE): размеры ±1 ступень, начертания ±50 по оси `wght`.

**Длина строки.** Колонка текста 60–72ch (MUST ≤ 80ch [норматив: 1.4.8 AAA как ориентир; *мнение* для MUST внутри сайта]). Таблицы, блоки кода, диаграммы и вкладки могут выходить шире колонки текста, до ширины контентной зоны.

**Переносы и типографика RU.**
- `<html lang>` равен языку страницы (MUST). Цитаты и вставки на другом языке получают свой `lang`.
- `hyphens: auto` — только в абзацах и пунктах списка на контейнере уже 40rem. Не применяется к заголовкам, ссылкам, коду, таблицам, кнопкам. [поддержка: `hyphens` — Baseline Widely available с 18.03.2026 (web-features explorer, 29.10.2026). Наличие словаря русского языка в каждом движке и ОС — [не проверено]: страница должна читаться и без переносов.] MAY: `hyphenate-limit-chars: 6 3 3` [не проверено].
- Неразрывные пробелы ставит шаблон при сборке (MUST, `authoring.md` «Голос»), только в текстовых узлах, никогда в `code`/`pre`/`kbd`/атрибутах/URL:
  - RU: после однобуквенных слов (в, к, с, у, о, и, а, я); перед «—»; между числом и единицей («10 МБ», «15 минут»); в «т. е.», «т. д.»;
  - EN: между числом и единицей.
- «Ёлочки» и внутренние „лапки“ ставит писатель. Шаблон кавычки не заменяет (иначе ломаются примеры). Длинное тире с пробелами в RU, без пробелов в EN — за писателем.

### Выноски NOTE / TIP / IMPORTANT / WARNING / CAUTION

- **Реализация.** Хук `render-blockquote` по `.AlertType`. Неизвестный тип ломает сборку (MUST).
- **Анатомия.**
  - Контейнер: радиус 12 px, внутренние поля 16/20 px, фон `--callout-<tone>-bg`, кромка `border-inline-start: 4px solid --callout-<tone>-edge`, рамка 1 px `--callout-<tone>-border`.

- **Тоны:** NOTE → info, TIP → success, IMPORTANT → brand (`--brand-container`, кромка `--brand`), WARNING → warning, CAUTION → error. Контрасты — в таблице выше.
- **Сворачиваемый вариант** (`-` / `+`): `details`/`summary`, `+` = `open`.

### LIMITS — «Границы гарантии»

Должна отличаться от любой другой выноски с первого взгляда. Это не предупреждение и не ошибка, а граница утверждения. Её нельзя путать с WARNING: тон не тёплый, не красный, не статусный.

- **Фон:** `--limits-bg`. **Рамка:** 1 px `--border` по всему периметру.
- **Кромка:** полоса 8 px со штриховкой (повторяющийся диагональный узор `--limits-stripe` 2 px / прозрачный 4 px). Метафора — «разметка границы», *мнение*.
- **Заголовок:** иконка «граница», «Границы гарантии», 650, `--foreground`.
- **Тело:** список «не защищает от / не действует, если / остаётся на стороне развёртывания». Структуру задаёт писатель.
- **Сворачивать нельзя** (MUST: границы гарантии всегда видны) [норматив: `authoring.md` — блок обязателен; этика — граница не прячется].
- **forced-colors:** кромка `4px double CanvasText` (см. COLOR).
- **На главной** та же иконка и та же подпись «Граница:» в карточках гарантий: единый визуальный знак границы на всём сайте (MUST).

### Подсказки term / xref / cite

**Поддержка на 29.10.2026 (web-features explorer):**
- Popover API — Baseline Newly available с 27.01.2025, Widely ожидается 27.07.2027 (Chrome 116, Firefox 125, Safari 17, iOS 18.3).
- `popover="hint"` — Limited (нет Safari).
- Interest invokers (`interestfor`) — Limited (только Chromium 142+).
- **CSS anchor positioning — Limited**: в web-features поддержка указана только для Safari 27. caniuse на ту же дату показывает частичную поддержку в Chrome 125+, Firefox 147+, Safari 26, полную — в Safari 27.

**Решение:**
- Слой отображения — `popover="manual"` (term, xref) и `popover="auto"` (cite) в top layer.
- Позиционирует JS: снизу от триггера с отступом 8 px; если не помещается — сверху; по горизонтали прижато к полям 16 px вьюпорта; для многострочного триггера — по первому прямоугольнику строки (приём из образца).
- MAY: CSS anchor positioning под `@supports` как улучшение, только после ручной проверки в трёх движках. Поведение без него должно быть таким же.

**Общая анатомия подсказки:**
- поверхность `--popover`, рамка 1 px `--border`, `--shadow-card`, радиус 12 px;
- ширина `min(22rem, 100vw − 32px)`, поля 12/16 px, текст `--type-small`, `--foreground`;
- без «носика» *мнение*.

**term**
- **Триггер:** ссылка на `/<lang>/glossary/#id`. Вид — текст `--foreground` с пунктирным подчёркиванием 1 px `--muted-foreground`, смещение 3 px. Отличается от обычной ссылки (сплошная, `--brand`) формой линии, а не только цветом.
- **Содержимое:** термин (650) · определение · только на тач — ссылка «Определение в глоссарии».
- **Семантика:**
  - контент подсказки рендерится при сборке рядом с триггером (элемент с `popover`, `id`);
  - триггер получает `aria-describedby` на текст определения: скринридер читает определение при фокусе без открытия слоя;
  - подсказка для мыши и клавиатуры — `role="tooltip"` без интерактивного содержимого (APG Tooltip: в подсказке нет фокусируемых элементов).

**xref**
- **Триггер:** обычная ссылка (`--brand`, подчёркивание). Текст — `title` цели.
- **Содержимое:** путь раздела (caption, `--muted-foreground`) · `title` · `description` цели · бейджи жанра и состояния цели · на тач — «Открыть страницу».
- **Семантика:** та же, что у term.
- **Ограничение:** подсказки только для внутренних ссылок `xref`, не для каждой ссылки на странице.

**cite**
- **Триггер:** кнопка-чип в тексте.
  - Вид: «[N] <издатель>». Высота 20–24 px, фон `--chip-bg`, текст `--muted-foreground`, рамка 1 px `--border`.
  - Длинный издатель обрезается до ~24 знаков с многоточием — полное имя в доступном имени. Лучше добавить в `sources.yaml` поле `short`, см. OPEN.
  - Без JS и без поддержки popover это ссылка `#source-N` на «Источники».
  - С поддержкой popover — `<button popovertarget>`. Light dismiss и Esc работают без JS.
- **Содержимое:**
  - издатель · номер;
  - название — ссылка на `url`, в том же окне *мнение*; если писатель настаивает на новом окне, к имени добавляется «(откроется в новом окне)»;
  - дата публикации или ревизии (если есть) · «Проверено {accessed}»;
  - ссылка «К списку источников».
- Подряд стоящие cite одного абзаца объединяются в один чип с листалкой (приём образца): ←/→ внутри слоя, кнопки «Предыдущий / Следующий источник».
- **Семантика:**
  - подсказка интерактивна, поэтому это **не** tooltip, а раскрывающийся слой (паттерн APG Disclosure: `aria-expanded` на кнопке);
  - элемент `popover` в DOM стоит сразу после чипа: порядок Tab ведёт из чипа в слой и дальше по тексту [не проверено: одинаковость навигации фокуса из invoker в popover во всех трёх движках — проверить вручную].

**Поведение (MUST, все три)** [норматив: 1.4.13 — закрывается без сдвига указателя (Esc), на слой можно навести указатель, слой не исчезает сам]:

| Ввод | term / xref | cite |
| --- | --- | --- |
| Мышь: наведение | Открыть через 400 мс (допуск 300–500); при переходе на соседний триггер, пока слой открыт, — мгновенно | То же |
| Мышь: уход | Закрыть через 250 мс (допуск 200–300), если указатель не на слое; на слое — держать | То же |
| Мышь: клик | Переход по ссылке (обычное поведение) | Открыть или закрыть |
| Клавиатура: фокус (`:focus-visible`) | Показать сразу; Tab дальше — скрыть | Не открывать по фокусу; Enter/Space — открыть, фокус остаётся на чипе, Tab ведёт в слой |
| Esc | Скрыть, фокус не двигается; до нового фокуса не показывать снова | Закрыть, фокус на чип |
| Тач: тап | Первый тап — открыть слой с явной ссылкой «Определение в глоссарии» / «Открыть страницу» (`preventDefault` навигации); тап вне — закрыть; тап по ссылке в слое — переход | Открыть или закрыть |
| Скроллинг или ресайз | Перепозиционировать на rAF, а не на каждый event; если триггер ушёл из вьюпорта — закрыть | То же |

[проверить в реализации: активация ссылки двойным тапом VoiceOver iOS и TalkBack должна переходить по ссылке, а не открывать слой. Если `pointerType` у таких событий `touch`, открывать слой только для настоящего тапа (по `pointerdown` с ненулевой площадью контакта), иначе переходить.]

### Переменные окружения `env`

**Источник данных.**
- `data/env.yaml`: одна запись на базовое имя.
- Форма `<ИМЯ>_FILE` отдельной записью не заводится: она выводится из `file: true` базовой записи. В коде так и устроено: `CRANE_CACHE_FILE`, `CRANE_TOKEN_FILE`, `CRANE_DATABASE_URL_FILE` — формы секретов, а не самостоятельные настройки.
- В файл входят и не-CRANE имена, которые читает сервер: `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`.
- Тестовые `CRANE_TEST_*` в файл не попадают: их нет в эксплуатации.

**Сборка (MUST).**
- Неизвестное имя в шорткоде ломает сборку (контракт `authoring.md`).
- В блоках кода известных языков любой токен вида `CRANE_[A-Z0-9_]+`, которого нет ни в `env.yaml`, ни среди выведенных `_FILE`, тоже ломает сборку. Это ловит опечатки в примерах.
- Для `AWS_*` проверка не действует: такие имена встречаются в чужих примерах.

#### Инлайн-вариант (`{{< env "CRANE_TOKEN" >}}`)

**Базовая разметка (без JS).**
- Ссылка на строку справочника `/<lang>/reference/environment-variables/#<anchor>`.
- Внутри — `code` с именем.
- Без JS это просто ссылка, и она работает.

**Вид. Отличие не только цветом.**

| Элемент | Шрифт | Подложка | Подчёркивание |
| --- | --- | --- | --- |
| Обычный `code` | моноширинный | `--code-bg` | нет |
| `env` | моноширинный | `--code-bg` | сплошное 1 px `--env-underline` (= `--link`), смещение 0.2em |
| xref | пропорциональный | нет | сплошное |
| term | пропорциональный | нет | пунктирное |

- Текст имени `env` — `--foreground` (11.91 / 12.75 на `--code-bg`).
- Подчёркивание `--brand` на `--code-bg`: 6.86 / 5.56 ≥ 3.
- Итог: `env` отличается от `code` подчёркиванием, а от term и xref — моношрифтом и подложкой.
- MUST: имя не переносится внутри себя. `white-space: nowrap`, но `overflow-wrap: anywhere` при ширине строки меньше имени, чтобы на 320 px не было горизонтального скролла [норматив: 1.4.10].

**Таб-стопы. Решение: один на переменную.**
- С JS ссылка становится раскрывающей кнопкой: `role="button"`, `aria-expanded`, `aria-controls`. `href` остаётся, поэтому Ctrl/⌘-клик и средняя кнопка открывают справочник.
- Кнопка копирования имени живёт **только в подсказке**, не в чипе. *Мнение*: кнопка в чипе удваивает таб-стопы и цели в абзаце с пятью переменными.
- MAY: Ctrl/⌘+C на сфокусированном чипе без выделенного текста копирует имя. Единственная клавиша без модификатора не вводится [норматив: 2.1.4].

**Подсказка.**
- Общий движок с term/xref/cite: top layer, `--popover`, ширина `min(24rem, 100vw − 32px)`.
- Содержимое сверху вниз:
  1. Шапка: имя (моноширинное, 650) и бейдж «Обязательная» / «Необязательная». Бейдж контурный, текст `--foreground`, рамка `--input`. Не warning: обязательность — свойство, а не опасность.
  2. Назначение: одно предложение `ru` / `en`.
  3. Список `dl`, где `dt` — подпись, `dd` — значение моноширинным:
     - «По умолчанию»: значение; для `null` — «нет»; для `""` — «пустая строка». Пустая строка и отсутствие значения различаются явно (MUST).
     - «Из файла»: `<ИМЯ>_FILE` или «нет».
     - «Ключ TOML»: `toml` или «только окружение».
  4. Действия: «Копировать имя» и ссылка «В справочнике». При `file: true` — MAY вторая кнопка «Копировать <ИМЯ>_FILE».
- Если подсказка открыта на форме `_FILE` (это бывает в коде), в шапке стоит `<ИМЯ>_FILE`, а под ней строка «Путь к файлу со значением <ИМЯ>». Остальные поля — от базовой записи.

**Семантика.**
- Описание для скринридера: `aria-describedby` чипа указывает на предложение о назначении в подсказке. Скрытый `popover` годится как источник описания. Всё остальное скринридер получает, раскрыв подсказку.
- Подсказка — немодальный слой (APG Disclosure), не `role=tooltip`: в ней есть интерактивные элементы.

**Поведение.**

| Ввод | Что происходит |
| --- | --- |
| Мышь, наведение | Открыть через 400 мс (допуск 300–500). Действия сразу активны. Можно перевести указатель на слой. Уход — закрыть через 250 мс |
| Мышь, клик | Закрепить (pinned) или снять закрепление. Переход по ссылке — только Ctrl/⌘ или средней кнопкой |
| Клавиатура, фокус (`:focus-visible`) | Показать слой в режиме просмотра: строка действий `inert`, в порядок Tab не попадает. Tab идёт к следующему элементу текста, подсказка гаснет |
| Enter / Space | Закрепить, фокус на «Копировать имя». В закреплённом слое: Tab по действиям; Tab с последнего — закрыть и перейти к элементу после чипа; Shift+Tab с первого — вернуться на чип |
| Esc | Закрыть в любом режиме. Если фокус был в слое — вернуть на чип; иначе фокус не двигается. До нового фокуса слой не показывать снова |
| Тач, тап | Открыть закреплённым. Цели действий ≥ 44×44 на `pointer: coarse`. Тап вне — закрыть |
| VoiceOver / TalkBack, активация | Как Enter: открыть закреплённым. Конфликта с навигацией нет: с JS это кнопка |
| Без JS | Ссылка на строку справочника |

- [норматив: 1.4.13] Закрывается без сдвига указателя (Esc), на слой можно навести указатель, слой не исчезает сам.
- [норматив: 2.5.8] Чип внутри предложения — исключение для инлайн-целей, но *мнение*: высота строки и подложка дают ≥ 24 px по вертикали. Кнопки в слое ≥ 32×32 (44 на coarse).

**Копирование.**
- Копируется ровно имя: без `$`, пробелов и переносов строк.
- После копирования: подпись кнопки «Скопировано» на 2 с и объявление в общей live region («CRANE_TOKEN скопирован»).
- Ошибка буфера: «Не удалось скопировать…», и имя в слое выделяется для ручного копирования.

#### В блоках кода

**Где.** Языки `bash` / `sh` / `shell` / `console`, `ini`, `yaml`, `toml`, `env` / `dotenv`. MAY: `dockerfile`. [проверить в реализации: имя лексера Chroma для `.env` и его поведение]

**Как находить (MUST).**
- Сопоставление идёт при сборке, **после** подсветки Chroma, по текстовым узлам внутри её токенов.
- Словарь: все базовые имена плюс выведенные `_FILE`. Самое длинное совпадение первым: `CRANE_TOKEN_PRINCIPAL_FILE` → `CRANE_TOKEN_PRINCIPAL` → `CRANE_TOKEN_FILE` → `CRANE_TOKEN`.
- Граница слова: до и после совпадения — не `[A-Za-z0-9_]`. Так `MY_CRANE_TOKEN` и `CRANE_TOKENS` не совпадут.
- Совпадение никогда не пересекает границу токена Chroma.
  - Если токен содержит имя целиком (`"${CRANE_TOKEN}"` в строке, `CRANE_TOKEN=` в `bash`, ключ в `yaml`), он делится на три части: «до», «имя», «после». Каждая часть сохраняет класс исходного токена, поэтому цвета `--syn-*` не меняются.
  - Если имя разорвано между токенами — не оборачивать и вывести предупреждение сборки.
- Внутри строк и подстановок оборачивается только имя: `${` / `}` / `$` / `%` остаются снаружи.
- Ключи TOML (`namespaces`) **не** оборачиваются: они не уникальны и путаются с обычными словами.

**Вид в коде.**
- Подложки нет: она спорит с подсветкой. Цвет — цвет токена Chroma.
- Сплошное подчёркивание 1 px `currentColor`, смещение 0.2em.
- Hover — подчёркивание 2 px.
- Закреплённый слой — подчёркивание 2 px `--brand` и `aria-expanded=true`.
- Подложка при hover отвергнута: `--brand-container` на `--code-bg` даёт 1.0:1 (светлая) и 1.02:1 (тёмная), то есть невидима, а `--surface-high` роняет `--syn-comment` ниже 4.5.

**Клавиатура в `pre` (MUST: не плодить таб-стопы).**
- Все переменные блока — одна группа с roving tabindex:
  - один таб-стоп на блок (первая переменная или последняя активная);
  - ←/→ — соседняя переменная;
  - Home/End — первая и последняя.
- Порядок Tab в блоке: кнопка «Копировать код» → `pre` (если код переполнен и есть `tabindex=0` для скролла стрелками) → группа переменных → дальше по странице.
- В подвале слоя для группы с несколькими переменными строка-подсказка «← → — другие переменные блока».
- Остальное поведение — как у инлайн-варианта.
- При фокусе или закреплении имя прокручивается в видимую часть `pre` (по горизонтали — `nearest`), затем слой позиционируется.
- Если `pre` прокрутили и имя ушло за край видимой области `pre`, слой закрывается.

**Выделение и копирование (MUST).**
- Обёртка не добавляет ни одного символа: нет текстовых узлов, пробелов между `span`, контента в псевдоэлементах, `user-select: none` на имени.
- Ручное выделение и Ctrl+C дают исходный текст.
- Обёртка в коде — `span` с `role="button"`, а не `<button>`. *Мнение*: [не проверено] выделение и копирование текста через `<button>` внутри `pre` одинаково во всех движках, поэтому без риска.
- `draggable="false"` на обёртке, чтобы протяжка выделяла, а не тащила ссылку.
- «Копировать код» берёт исходник блока при сборке (как в разделе «Блоки кода»), а не `innerText` размеченного DOM.
- Приёмка: скопированное побайтно равно исходнику без приглашения `$ `.

**Без JS.** Имена в коде — ссылки на строки справочника. Ссылки `<a>` внутри `pre` выделяются как текст.

#### Связь со справочником `reference/environment-variables`

**Таблица (state: current).**
- Строка `tr id="<anchor>"`. Якорь стабилен и одинаков в RU и EN (MUST).
- Первая ячейка — `th scope="row"` с именем (моноширинное), ссылкой на якорь строки и кнопкой «Копировать имя». В таблице кнопка в строке допустима: это одна цель на строку, а не абзац.
- Колонки: Назначение · По умолчанию · Обязательная · Из файла · Ключ TOML.
- Для формы `_FILE` в ячейке «Из файла» стоит `span id="<anchor>-file"`, чтобы ссылка с `CRANE_TOKEN_FILE` вела на ту же строку.
- На самой странице справочника подсказки `env` не выводятся: упоминания переменных там — обычные внутристраничные ссылки на строки. Пользователь уже у цели, и вес не нужен.

**Подсветка цели.**
- Строка под `:target`: фон `--brand-container`, полоса 3 px `--brand` у начала строки. Подсветка держится, пока строка — цель, а не только вспышкой.
- Контраст: `--foreground` на `--brand-container` — 11.95 / 13.00; `--brand` — 6.89 / 5.67.
- `scroll-margin-top` = высота шапки + 8 px [норматив: 2.4.11].
- MAY: вспышка 600 мс через `opacity`; при reduced motion — без неё.
- Фокус после перехода: на ссылку-якорь в `th`, чтобы с клавиатуры продолжить с этой строки. *Мнение*, SHOULD.
- В forced-colors подсветка — `outline: 2px solid Highlight`.

**Обратные ссылки (SHOULD).**
- При сборке для каждой переменной строится список страниц того же языка, где она упомянута шорткодом или в блоке кода.
- В строке — свёрнутый `details` «Где упоминается (N)» со ссылками на эти страницы.
- Над таблицей, если пришли с другой страницы сайта (по `document.referrer` того же origin, с JS), — ссылка «← Назад к «<заголовок>»». Без JS работает кнопка «Назад» браузера: якоря историю не ломают.

#### Бюджет и способ рендера

**Решение: при сборке, с дедупликацией на странице.**
- Каждая уникальная переменная страницы рендерит **один** слой `popover` в конце `main` (`id="env-<anchor>"`). Все упоминания, инлайн и в коде, ссылаются на него через `aria-controls` / `aria-describedby`.
- Ориентир [не проверено, замерить]: ~0.6–0.9 КБ HTML на уникальную переменную до сжатия.
- JSON по требованию (`/<lang>/env.json` при первом взаимодействии) **не** используется по умолчанию:
  - описание для скринридера должно быть в DOM до взаимодействия;
  - первый показ получил бы сетевую задержку.
- Переход на JSON — только если на обычной странице больше 40 уникальных переменных. Справочник от этого избавлен: подсказок там нет.

## Поиск (Pagefind)

**Версия.** Последний выпуск на 29.10.2026 по GitHub Releases — v1.5.2 (12.04.2026). С 1.5.0 есть Component UI на веб-компонентах (`pagefind-modal-trigger`, `pagefind-modal`, `pagefind-input`, `pagefind-results`, `pagefind-filter-dropdown`, `pagefind-summary`, `pagefind-keyboard-hints`), он заменяет Default UI. Компоненты переводят видимые и вспомогательные тексты по языку сайта. У русского есть стемминг и перевод UI. Индекс отдельный на каждый `lang`. (pagefind.app/docs/multilingual, /docs/search-ui, GitHub Releases — 29.10.2026)

**Решение:** Component UI, модальный вариант.

- **Триггер в шапке:** кнопка «Поиск». На ≥ 48rem — с подсказкой сочетания `Ctrl K` (на Apple — `⌘ K`). Ниже 48rem — иконка лупы, доступное имя «Поиск».
  - MUST: сочетание с модификатором. Одиночные клавиши («/») не используются без возможности их выключить [норматив: 2.1.4].
  - Без JS: кнопка скрыта, вместо неё ссылка «Карта сайта» на индекс раздела языка. *мнение*
- **Палитра:**
  - модальный диалог ширины `min(40rem, 100vw − 32px)`, сверху 12vh (на мобильных — во весь экран);
  - поле поиска (≥ 16 px шрифт — iOS не зумит; рамка `--input`);
  - ряд фильтров; итог «{n} результатов»; список результатов; подсказки клавиш.
- **Фильтры:** Раздел, Аудитория, Жанр — `data-pagefind-filter` из front matter и раздела. MAY: Состояние (target/current) и Статус (in-development). Подписи фильтров и значений — из i18n-каталога (те же «Безопасность», «Объяснение»…), а не сырые id.
- **Результат:**
  - путь раздела (caption) · заголовок (ссылка) · выдержка с подсветкой `mark` (`--brand-container` + `--foreground`, 11.95 / 13.00) · бейджи жанра и статуса;
  - подзаголовки страницы как дочерние результаты — по поддержке Pagefind [проверить в реализации].
- **Индексация:** только `main` статьи (`data-pagefind-body`). Не индексируются шапка, дерево, оглавление, подвал, «Источники» (у них `data-pagefind-ignore`). Метаданные `title`, `description`.
- **Языки:** индекс по `lang` автоматически. MUST: результаты только своего языка; переключение языка в палитре не предусмотрено.
- **Состояния:**
  - пусто до ввода (недавние запросы не хранятся *мнение*: приватность);
  - загрузка индекса: < 300 мс ничего, дальше — «Загрузка индекса…»;
  - нет результатов — текст из CONTENT и кнопка «Сбросить фильтры», если они выставлены;
  - ошибка загрузки — текст из CONTENT.
- **Стили:** Component UI окрашивается токенами сайта (переменные или `::part`) [проверить в реализации: механизм кастомизации Component UI — в найденной документации не описан]. Сторонний CSS Pagefind допускается, только если после переопределения проходят контрасты из таблицы.
- [проверить в реализации:]
  - модальный компонент держит фокус внутри, закрывается по Esc и возвращает фокус на триггер;
  - у результатов есть роль списка и навигация стрелками;
  - если чего-то нет — дополнить своей обвязкой или собрать UI на JS API Pagefind.

## Переключатели и действия

**Язык RU/EN.**
- В шапке ссылка на ту же страницу второго языка. Путь сохраняется: пары 1:1 по контракту, якорь `#…` переносится — якоря одинаковые [норматив: `authoring.md`].
- Видимый текст «EN» / «RU»; имя «EN, English» / «RU, русский»; атрибуты `hreflang`, `lang` у ссылки.
- По клику — запись `crane.locale` в `localStorage` (try/catch): корень `/` при следующем визите уважает выбор.
- MUST: корень `/` без JS — две явные ссылки «Русский» и «English». С JS — переход по `crane.locale`, иначе по `navigator.language`. Без мигания пустой страницы: ссылки видны сразу.

**Тема.**
- Три режима: Светлая, Тёмная, Как в системе (по умолчанию).
- Кнопка в шапке (иконка текущего режима, имя «Тема: Как в системе») открывает `popover` с группой из трёх радиокнопок (`fieldset` + `legend` «Тема»).
- *мнение*: циклическая кнопка на три состояния непредсказуема.
- Хранение — `localStorage` `crane.colorScheme`: тот же ключ и логика, что в консоли (`colorScheme.ts`, `public/theme-init.js`), другой origin.
- **MUST (без мигания):** синхронный инлайн-скрипт ≤ 1 КБ в `<head>` до таблицы стилей ставит `data-theme` и `color-scheme` по сохранённому режиму или по `prefers-color-scheme`.
- Без JS тема следует системе. Механизм — TOLERANCE:
  - токены через `light-dark()` при `color-scheme: light dark` на `:root` [поддержка: `light-dark()` Baseline Newly с 13.05.2024, Widely ожидается 13.11.2026 (web-features explorer, 29.10.2026)];
  - либо блок `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) … }` плюс `:root[data-theme="dark"]`.
- Смена режима мгновенная, без транзиций цвета. В режиме «Как в системе» — подписка на изменение системной темы.
- Без JS переключатель скрыт.

**«Копировать как Markdown»** (SHOULD, без сети к третьим сторонам).
- Кнопка в шапке страницы копирует Markdown-версию страницы (`<страница>.md` того же origin) в буфер.
- Safari теряет активацию пользователя, если запись в буфер идёт после `await fetch`. Поэтому запись — через `ClipboardItem` с Promise в момент клика [проверить в реализации: Safari текущей версии]. Фолбэк — текст из скрытого `<template>`, вставленного при сборке. Цена фолбэка — вес HTML: *мнение*, только если первое не работает.
- Состояния — как у копирования кода.
- Рядом обычная ссылка «Markdown-версия» с `type="text/markdown"`.

**«Открыть в ассистенте» — ПРЕДЛОЖЕНИЕ, ТРЕБУЕТ СОГЛАСОВАНИЯ ВЛАДЕЛЬЦА.** До решения в разметке не выводится.
- Если согласовано: кнопка-меню со списком конкретных сервисов по имени (имя обязательно — пользователь должен знать, куда уходит адрес).
- Каждый пункт — обычная ссылка, открывающая сервис с адресом Markdown-версии в запросе.
- До клика ничего не загружается и не передаётся: без пикселей, предзагрузки и иконок с чужих доменов.
- Под меню строка: «Сервис откроется на стороннем сайте; передаётся только адрес этой страницы».
- Риски для решения владельца:
  - имена сторонних сервисов на сайте;
  - доступность части сервисов из РФ;
  - чужие условия обработки данных;
  - противоречие позиционированию «безопасность прежде всего», если реализовано небрежно.

## Токены сайта (primitive → semantic → component)

**Слои.**
1. **Primitive** (`--p-*`). Палитра hex консоли без смыслов: `--p-gray-50: #f9f9f9`, `--p-gray-900: #29303e`, `--p-plum-600: #951b81`, `--p-plum-300: #e07acb`, `--p-ink-950: #14171d`… Один источник — `tokens.css` консоли.
2. **Semantic.** Имена консоли один к одному (`--background`, `--foreground`, `--brand`, `--success-bg`, …) со значениями для светлой и тёмной темы. Также переиспользуются motion, радиусы, тени. Новые семантические токены сайта:
   - `--link` (= `--brand`), `--link-hover` (светлая `--primary-hover`, тёмная `#f0a3df` [не проверено: контраст посчитать при вводе, ≥ 4.5 к фону]);
   - `--limits-bg`, `--limits-stripe`;
   - `--z-sticky`;
   - `--header-height`;
   - шкала `--type-*`;
   - `--space-*` (4, 8, 12, 16, 24, 32, 48, 64, 96 и fluid-пары Utopia для секций главной);
   - `--measure` (`68ch`).
3. **Component** — только ссылки на semantic, никаких hex:
   - `--callout-{note|tip|important|warning|caution}-{bg|edge|border|title}`;
   - `--callout-limits-{bg|stripe|border|title}`;
   - `--audience-block-{bg|border}`;
   - `--chip-{bg|fg|border}`;
   - `--badge-genre-{fg|border}`, `--badge-state-target-{fg|border}`, `--badge-state-current-{fg|border}`, `--badge-status-dev-{bg|fg}`;
   - `--syn-{keyword|string|number|attr|comment|punct|error}`;
   - `--tooltip-{bg|fg|border|shadow}` (= popover);
   - `--toc-active`, `--nav-active-{bg|fg|bar}` (= `--sidebar-accent*` консоли);
   - `--hero-grid-line`.

**MUST.**
- Значения semantic совпадают с консолью. Расхождение — только через новые токены сайта, а не правкой значения консоли.
- Перенос значений — скриптом синхронизации с проверкой расхождений, а не руками [проверить в реализации: репозиторий сайта сабмодулем лежит внутри CRANE; кто запускает проверку — открытый вопрос, см. OPEN].
- В перенесённых файлах нет упоминаний стороннего кита (DS FIT).
- Формат хранения — MAY: исходник в W3C DTCG JSON и генерация CSS custom properties. Для одного сайта на Hugo достаточно CSS custom properties с комментарием о слоях *мнение*.

## PERF BUDGET

Целевые метрики (MUST, p75, мобильный, по CrUX или полевым данным; до появления трафика — Lighthouse mobile со стандартным троттлингом): LCP ≤ 2.5 с, INP ≤ 200 мс, CLS ≤ 0.1.

| Ресурс | Бюджет (сжатый, gzip/brotli) | Правило |
| --- | --- | --- |
| HTML текстовой страницы | ≤ 60 КБ | Подсказки term/xref рендерятся в HTML — следить на длинных справочниках |
| CSS | ≤ 30 КБ одним файлом с отпечатком в имени | *мнение* по значению, MUST после фиксации |
| JS при загрузке | ≤ 1 КБ инлайн (тема) | Всё остальное — острова: загрузка по `type="module"` + `defer`, инициализация по idle или по первому взаимодействию |
| JS островов на странице текста | ≤ 15 КБ суммарно (подсказки ≤ 6, копирование ≤ 1.5, вкладки ≤ 2, оглавление ≤ 1.5, тема и язык ≤ 1.5, меню-фолбэк ≤ 1) | Острова грузятся, только если на странице есть их разметка |
| Pagefind | Вне бюджета, только при открытии поиска или по Ctrl K | Без предзагрузки индекса до намерения пользователя. MAY: прогрев по наведению на триггер |
| Mermaid (если на клиенте) | Вне бюджета, только на страницах с диаграммами, по приближению к вьюпорту | SHOULD: рендер при сборке |
| Шрифты | Preload одного текстового woff2 языка страницы; суммарно на страницу без кода ≤ 2 файла | [не проверено: вес сабсетов Onest — замерить] |
| Картинки | Снимки AVIF/WebP, явные размеры, `lazy` ниже первого экрана | LCP главной — текст `h1`, без картинки hero |

**MUST:**
- нет layout-анимаций (кроме оговорённого `details`);
- нет сдвигов от появления кнопок копирования: место под шапку блока кода зарезервировано всегда, кнопка лишь становится видимой;
- нет сдвигов от островов: вкладки до гидратации занимают ту же высоту, что после, — либо первая панель видна, а остальные идут ниже как стек без JS, и переход происходит до первой отрисовки в пределах `defer` [проверить в реализации: замер CLS на странице с вкладками];
- подсказки в top layer не меняют раскладку.

**Прочее:**
- SHOULD: `content-visibility: auto` + `contain-intrinsic-size` на крупных секциях ниже первого экрана главной и на длинных справочниках. MUST: не применять к блокам, где есть якоря и find-in-page — проверить, что поиск Ctrl F и переход по якорю работают.
- MAY: Speculation Rules (prefetch внутренних ссылок по `moderate`) [поддержка: Limited — только Chromium 109+ (web-features explorer, 29.10.2026)]; без поддержки ничего не меняется.
- bfcache: нет `unload` и `Cache-Control: no-store` (Pages его не ставит [не проверено]).

## INVARIANTS (MUST)

1. WCAG 2.2 AA: контраст пар — по таблице и не ниже порогов; фокус виден на всём интерактивном; клавиатурный доступ ко всему; цели ≥ 24×24; reflow на 320 CSS px без горизонтального скролла страницы; зум 200 % и 400 %; text spacing без обрезки.
2. Ссылки в тексте подчёркнуты; термины — пунктиром; цвет не единственный носитель смысла.
3. Подсказки: hover с задержкой, focus, Esc без сдвига фокуса, на слой можно навести указатель, тач открывает слой с явной ссылкой; без JS ссылки работают и ведут на глоссарий, страницу или «Источники».
4. Без JS читается всё: текст, дерево (`details`), ссылки, «Термины», «Источники», панели вкладок стеком, плейсхолдеры, диаграммы (SVG или исходник).
5. Нет внешних запросов во время работы страницы: шрифты, иконки, скрипты, Pagefind, mermaid — с getcrane.dev. «Открыть в ассистенте» отправляет запрос только по клику и только после согласования.
6. Шрифты — Onest и JetBrains Mono под OFL, с файлами лицензии; других гарантий нет.
7. Тема: светлая и тёмная из палитры консоли, без мигания при загрузке, следует системе по умолчанию, переключение мгновенное.
8. Ни слова о стороннем UI kit и его бренде в публичных файлах.
9. Анимации — только `transform` и `opacity` (исключение — высота `details` через `interpolate-size`). Всё движение < 5 с без повторов. `prefers-reduced-motion` убирает сдвиги и cross-document transitions.
10. CLS ≤ 0.1, LCP ≤ 2.5 с, INP ≤ 200 мс (p75, мобильный). JS при загрузке ≤ 1 КБ инлайн, острова в бюджете.
11. Порядок секций главной — безопасность первой. LIMITS всегда видна и не сворачивается. Главная не утверждает доступность того, что `in-development`.
12. `<html lang>` = язык страницы, `hreflang`-пары, переключатель языка сохраняет путь и якорь.
13. Неизвестный тип выноски, аудитории, жанра, термина, источника или пути `xref` ломает сборку.
14. Всё всплывающее — в top layer; z-index — только `--z-sticky`.

## TOLERANCES (SHOULD / MAY)

- Длительности ±25 % в пределах колонок MOTION. Любой easing класса decelerate на вход и accelerate на выход.
- Размеры шкалы ±1 ступень. Начертания ±50 `wght`. Колонка текста 60–72ch. Ширины колонок дерева и оглавления ±2rem. Брейкпоинты ±4rem, если контент требует.
- Высота шапки 56–64 px. Ширина кромки выносок 3–4 px. Узор штриховки LIMITS — любой, если он отличим от остальных выносок и в forced-colors есть дубль кромкой.
- Иконки — любой открытый набор с совместимой лицензией. Набор иконок аудиторий — любой, но один на весь сайт.
- Механизм темы: `light-dark()` или блоки `data-theme`.
- Mermaid при сборке или на клиенте (при клиентском — резерв высоты обязателен).
- Состав карточек гарантий 6–8; раскладка bento — любая, если порядок DOM = порядок чтения.
- `backdrop-filter` у шапки — по желанию, кроме мобильных и `prefers-reduced-transparency`.
- Cross-document view transitions, Speculation Rules, `text-wrap: pretty`, `hanging-punctuation`, anchor positioning — только как улучшения, можно не делать.
- Подсказка «Пример отказа» на главной — делать, только если текст взят из кода.

## ACCEPTANCE

Критерии для design/a11y-ревью реализации. Каждый проверяется на главной и на трёх эталонных страницах:
- `features/security/namespace-reservation` (explanation, LIMITS, аудиторный блок, term, xref, cite);
- `deploy/docker-compose` (how-to, вкладки, код);
- `reference/environment-variables` (широкая таблица).

Обе локали, обе темы.

1. **Контраст.** axe DevTools без нарушений `color-contrast`. Ручной замер пипеткой DevTools для выносок, бейджей, подсветки синтаксиса, подсказок, `mark` — не ниже таблицы COLOR.
2. **Клавиатура.** С пустого адреса:
   - Tab: skip link → шапка → дерево → контент;
   - фокус всегда виден и не перекрыт шапкой [2.4.11];
   - подсказка term и xref появляется на фокусе и гаснет по Esc без потери фокуса;
   - cite: Enter открывает, Tab ведёт в слой, Esc возвращает на чип;
   - вкладки: ←/→/Home/End;
   - палитра поиска: Ctrl/⌘ K, Esc, фокус вернулся на триггер;
   - модальное меню: фокус внутри, Esc, возврат на «Меню».
3. **Мышь.** Подсказка открывается через 300–500 мс; указатель переходит на слой, и слой не гаснет; при уходе гаснет через 200–300 мс.
4. **Тач** (iOS Safari, Chrome Android — реальные устройства или эмуляция с проверкой на устройстве): тап по term открывает слой со ссылкой «Определение в глоссарии», тап вне закрывает. VoiceOver iOS: двойной тап по term переходит в глоссарий, определение читается как описание при фокусе.
5. **Скринридер.** VoiceOver macOS + Safari и NVDA + Firefox: ландмарки и уровни заголовков; префикс «Раздел для:» у чипов; выноски читаются с типом; объявления копирования и числа результатов.
6. **Без JS** (DevTools → Disable JavaScript):
   - всё читается;
   - дерево раскрывается;
   - ссылки term/xref ведут на цели, cite — на «Источники»;
   - вкладки — стек панелей;
   - тема по системе;
   - корень `/` показывает две ссылки языка;
   - кнопок копирования, поиска и переключателя темы нет, и пустых мест под ними нет.
7. **Тема.** Выбор «Тёмная» при светлой системе → перезагрузка → нет кадра светлой темы (запись Performance со скриншотами). Скриншоты и диаграммы — тёмного варианта.
8. **Reduced motion** (Rendering → `prefers-reduced-motion: reduce`): схема hero сразу в финальном состоянии; нет сдвигов у подсказок, меню и карточек; нет cross-document transitions.
9. **Forced colors** (Rendering → `forced-colors: active`, а также Windows High Contrast): видны границы выносок, LIMITS с двойной кромкой, чипы и бейджи, выбранная вкладка, активный пункт дерева, фокус.
10. **Reflow и зум.** Окно 320 CSS px и зум 400 % на 1280: нет горизонтального скролла страницы; таблицы и код скроллятся в своих регионах; шапка не sticky при высоте < 30rem; подсказки не выходят за 16 px полей. Text spacing (букмарклет WCAG 1.4.12) — без обрезки.
11. **Производительность.** Lighthouse mobile на главной и на трёх эталонных: LCP ≤ 2.5 с, CLS ≤ 0.1, TBT в зелёной зоне. Вкладка Network: JS при загрузке и CSS в пределах бюджета; ни одного запроса к чужим доменам; Pagefind загружается только после открытия поиска; mermaid — только на странице с диаграммой. Performance с paint flashing на анимации hero и подсказок: нет layout и paint вне анимируемого слоя, нет долгих кадров (LoAF > 50 мс).
12. **Типографика.** RU: нет висячих однобуквенных слов в конце строки; неразрывный пробел перед тире; ни одного nbsp внутри `code` (проверка исходника HTML). Строка текста ≤ 72ch на 1440.
13. **Контент.** Ни одного упоминания стороннего UI kit в собранном сайте (grep по `public/`). Нет «мы», «наш», «оператор» в строках шаблонов и i18n. Все строки интерфейса — из каталога.
14. **Сборка.** Неизвестные тип выноски, аудитория, термин, источник или путь `xref` ломают `hugo` (по одному негативному примеру на каждый).
15. **Поиск.** Запрос «карантин» на RU и «quarantine» на EN: результаты только своего языка; фильтры Раздел, Аудитория, Жанр сужают выдачу; подписи фильтров переведены; пустой запрос и ошибка индекса (сеть отключена после загрузки страницы) показывают тексты из CONTENT.

8. **Язык корня `/` по умолчанию** — уже открыт в `ia.md`.
9. **Рендер mermaid** при сборке (нужен headless-браузер в CI) или на клиенте.

Отброшенные варианты:
- **Подсказки целиком на CSS anchor positioning.** Web-features на 29.10.2026 даёт Limited, caniuse — частичную поддержку в Chrome и Firefox.
- **`popover="hint"` и `interestfor` для hover без JS.** Limited: нет Safari, у `interestfor` нет и Firefox.
- **Категориальные цвета аудиторий.** Конкурируют со статусами и не могут нести смысл одни. Это мнение, согласованное с R14 консоли.
- **Scroll-reveal на главной.** Нет в Firefox; риск невидимого контента без JS; пользы для чтения нет.
- **Одиночная клавиша «/» для поиска.** WCAG 2.1.4 требует возможности её отключить. `Ctrl/⌘ K` проще.
- **Циклическая кнопка темы на три состояния.** Непредсказуема.
- **Hover-only кнопка копирования.** Недоступна на таче.
- **Логотипы экосистем.** Чужие знаки и цвет без смысла.
