# UI-SPEC: селектор версий документации getcrane.dev

Дельта к `design/ui-spec.md` и `design/ui-spec-delta.md` от 29.10.2026. Обозначения те же: **MUST** — инвариант, **SHOULD/MAY** — допуск, *мнение* — вкус, `[норматив: …]`, `[поддержка: …]`, `[не проверено]`, `[проверить в реализации: …]`. CSS-значения — это язык спеки, а не код.

## CONTEXT

- **Задача пользователя.** Читать документацию той версии CRANE, которая у него установлена. Сразу видеть, что он в архиве или в документации невыпущенной версии. Переходить между версиями, не теряя место.
- **Где живёт.** Шапка сайта, панель «Меню», шапка страницы (ряд меток), начало `main`, новая страница `/<lang>/versions/`, палитра поиска, `404.html`.
- **Браузеры.** Как в `ui-spec.md`: две последние мажорные версии Chrome, Edge, Firefox, Safari macOS и iOS, Chrome Android. browserslist сайта до сих пор не задан.
- **Среда.** Hugo 0.157, статика на GitHub Pages, один origin `getcrane.dev` для всех версий. Своих заголовков ответа нет.

## 0. Архитектура: замечания к предложению

**A1. Что лежит в корне (MUST решить до реализации).** По предложению корень — это `main` сайта, то есть «то, что есть в коде сейчас» (`authoring.md`). Сразу после тега vX.Y корень совпадает с выпуском. Потом в него попадает документация следующей версии, а у пользователей стоит vX.Y. Тогда корень по умолчанию начинает описывать переменные и поведение, которых в их бинарнике нет. Для документации инфраструктуры это вредно: читатель задаёт несуществующий параметр.

- **Вариант B (рекомендую).** Корень `/` — последний выпуск (`current`). `/next/` — сборка из `main` сайта (`next`). `/vX.Y/` — прежние выпуски (`previous`). Это ровно три статуса из `versions.yaml` предложения.
  - Цена: Pages собирается из двух ref (тег документации последнего выпуска и `main`). Исправление текущей документации идёт в ветку документации выпуска с cherry-pick в `main`.
- **Вариант A (если оставить корень = `main`).** Каждый выпуск архивируется в `/vX.Y/` сразу по своему тегу, включая последний. Страницы корня с `since` новее последнего выпуска получают чип «Ещё не в выпуске» (раздел 3).
  - Номер у этого чипа запрещён: номеров будущих версий в тексте быть не может (`authoring.md`).
  - Тогда пользователь выпуска должен сам уйти в архив своей версии. *мнение*: так хуже.
- Остальная спека работает при обоих вариантах. Где поведение расходится, это помечено.

**A2. Архив строится из зафиксированного коммита сайта.** Архив делается по тегу документации выпуска, а не по состоянию корня в момент работы workflow. Иначе в архив vX.Y попадёт документация X.Y+1.

**A3. Свежие данные для неизменяемых архивов (MUST).**
- Архив vX.Y не знает о версиях, вышедших после него, и не знает номер текущей.
- Поэтому в корне публикуется `/versions.json`, производный от `data/versions.yaml` текущей сборки. Его читают селекторы всех версий во время работы.
- Каждая сборка (корень, `next`, каждый архив) публикует `<path>pages.json` со списком путей своих страниц по языкам, например `{"en": ["", "start/", "deploy/docker-compose/", …], "ru": […]}`. Это около 1 КБ в gzip на версию *оценка*.
- SHOULD: workflow архива кладёт копию `pages.json` архива в `data/` текущей сборки. Тогда ссылки «из текущей в архив» разрешаются при сборке, без JS.

**A4. Встроенная поддержка версий в Hugo (рассмотрена, не рекомендую сейчас).**
- В Hugo 0.153+ есть измерение `versions` и метод `.Rotate "version"`: все версии собираются одной сборкой, и наличие страницы в другой версии известно статически ([gohugo.io/configuration/versions](https://gohugo.io/configuration/versions/), [gohugo.io/methods/page/rotate](https://gohugo.io/methods/page/rotate/), прочитано 29.10.2026). Для UI это лучше: всё разрешается статически, баннеры всегда свежие.
- Против: старый контент каждый раз пересобирается текущими шаблонами и строгими проверками сборки. Удалённый термин глоссария, `env` или шорткод ломает сборку архива. Неизменяемость пропадает. Как версионируется `data/`, `[не проверено]`.
- Решение — в OPEN 2.

**A5. Гранулярность.** Версия документации = минорный выпуск (`0.3`). Что делать с патч-тегом vX.Y.Z (обновлять архив minor или нет) — OPEN 3.

## LAYOUT

### Шапка (≥ 48rem)

- Порядок: логотип · «Документация» · *spacer* · поиск · **версия** · язык · тема · «Исходный код» · «Меню».
- Версия стоит перед языком: она шире по охвату (`/vX.Y/<lang>/…`) и меняется реже.
- Триггер: ghost, высота 40 (44 на `pointer: coarse`), поля 8/10, gap 4.
  - Подпись — `label` версии, которую читают: «0.3». Для `next` — «Следующая» / «Next».
  - Справа `chevron-down` 16 `--muted-foreground`.
  - SHOULD не добавлять иконку перед подписью, чтобы сэкономить ширину. MAY с 64rem видимый префикс «Версия» / «Version» `--muted-foreground`.
- Слой: `popover="auto"`, у края по `inset-inline-end` триггера, отступ 4 сверху.
  - Ширина `min(18rem, 100vw − 32px)`; `max-block-size` до низа вьюпорта минус 16, дальше скролл внутри.
  - Позиционирование — TOLERANCE: как у `.theme-pop` (фиксированно под шапкой у правого края) или JS по прямоугольнику триггера. CSS anchor positioning MAY только как улучшение `[поддержка: Limited, ui-spec.md, проверено 29.10.2026]`.

**Анатомия слоя (сверху вниз):**
1. Метка группы caption `--muted-foreground`, поля 4/8: «Версия документации».
2. Список версий в порядке `next` → `current` → `previous` по убыванию. Пункт — ссылка, `min-block-size` 36 (44 на coarse), поля 0/8, радиус 8.
   - Строка 1: `label` 600 `--foreground` + статус caption `--muted-foreground` («текущая», «следующая», «прежняя»).
   - Справа `check` 16 у читаемой версии.
   - MAY строка 2, caption `--muted-foreground`. «Недавно открывали» — у версии из `localStorage` (раздел 1.4). «Страницы нет — откроется „<раздел>“» — когда манифест показал, что страницы нет.
3. Разделитель 1 px `--border`.
4. Ссылка «Все версии» → `/<lang>/versions/` (в архиве — корневая, A3), справа `arrow-right` 16.

- Число пунктов: SHOULD не больше 6 версий в слое. Старшие уходят только на страницу «Версии документации».
- Без JS в архиве: статичный список архива + пункт «Текущая» (без номера) + «Все версии». С JS список строится по `/versions.json`.

### Шапка и панель «Меню» (< 48rem)

- Селектора в шапке нет. R3 дельты остаётся в силе.
- Расчёт на 320 px (поля 2 × 16, доступно 288):
  - знак логотипа 40, поиск 40, язык 40, тема 40, «Меню» около 90, промежутки около 20 — уже 270;
  - триггер версии добавляет около 68 — итого около 338, переполнение.
- В панели «Меню» (`<dialog>`) первым блоком, над деревом:
  - `nav aria-label="Версии документации"` с заголовком-подписью caption;
  - тот же список ссылок раскрыт сразу, без вложенного popover;
  - пункт «Все версии».
- Без JS панель — якорь `#site-nav` после `main` (ui-spec), блок версий стоит там же первым.
- Между 48 и 64rem блок в панели скрыт: селектор уже в шапке, дублей нет.
- В архиве и `next` путь к текущей версии на любой ширине даёт полоса баннера (раздел 2.1), без открытия меню.

### Переход с сохранением пути

- Целевой адрес = `<path версии><lang>/<путь страницы>` + якорь. Язык сохраняется.
- Если страницы в целевой версии нет: ближайший существующий предок по сегментам пути, в крайнем случае корень языка этой версии. Якорь в этом случае отбрасывается.
- Разрешение:
  - (1) при сборке, если манифест цели есть в `data/` (переходы из текущей версии в архивы, SHOULD);
  - (2) иначе JS по `pages.json` цели — загрузка при наведении или фокусе триггера, или при открытии слоя;
  - (3) иначе прямая ссылка, а отсутствие страницы ловит `404.html` (раздел 2.4).
- JS перехватывает только обычный клик. Ctrl/⌘/Shift-клик и средняя кнопка идут по `href` браузером. MUST: `href` всегда валиден сам по себе.
- Переключатель языка внутри версии ведёт на тот же путь этой же версии (MUST). Корень `/` с выбором языка всегда относится к текущей версии.

## TYPOGRAPHY

- Подпись триггера — `--type-small` 600, `tabular-nums`. Номера версий во всех местах выводятся с `tabular-nums`.
- Полосы баннеров — `--type-small` (≥ 14 px), межстрочный 1.45, `text-wrap: pretty` как улучшение. Длина строки не ограничена: полоса на всю ширину, текст ≤ 2 строк на 1280.
- Неразрывный пробел между «версии» и номером (MUST): «версии 0.3» не рвётся. Это делает `util/typo.html`.
- Зум 200 %: полоса переносится в 2–4 строки, шапка уже `static` (ui-spec). Триггер версии при зуме попадает в «Меню» по брейкпоинту 48rem — это норма.

## A11Y

**Выбор паттерна: APG Disclosure Navigation.**
- Это навигация: в каждом пункте ссылка на другой адрес.
- APG прямо пишет, что `role="menu"` для навигации сайта не нужен и ожидает от вспомогательных технологий поведения, которого здесь нет ([APG disclosure-navigation](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-navigation/), прочитано 29.10.2026).
- Listbox отброшен: это семантика выбора значения, `option` не может содержать ссылку, а навигация по смене выбора нарушает 3.2.2 On Input.
- Нативный `<select>` с переходом по `change` отброшен по той же причине и потому, что ему нужен JS. Customizable `<select>` `[не проверено: статус на дату]`.

**Разметка (MUST):**
- Триггер `<button type="button" popovertarget="ver-pop">`:
  - без `aria-haspopup`: `menu` и `listbox` объявили бы чужой паттерн;
  - доступное имя содержит видимую подпись [норматив: 2.5.3]: «Версия документации: 0.3, текущая» / «Documentation version: 0.3, current».
- Состояние раскрытия — неявное `aria-expanded` от `popovertarget`.
  - Работает в Chrome, Edge, Firefox и Safari, но только при декларативном `popovertarget` ([hidde.blog/popover-accessibility](https://hidde.blog/popover-accessibility/)) `[не проверено лично на дату]`.
  - MUST: открытие только через `popovertarget`, без `showPopover()` из JS, иначе состояние пропадёт.
- Слой `<div id="ver-pop" popover>` → `<nav aria-label="Версии документации">` → `<ul>` → `<li><a>`.
  - У читаемой версии `aria-current="page"`: ссылка ведёт на эту самую страницу.
  - Метка группы — видимый текст, связан через `aria-labelledby` у `nav`.

**Клавиатура:**
- Enter / Space на триггере открывает и закрывает слой.
- Tab с триггера ведёт в первый пункт: браузер ставит popover в порядок фокуса сразу после триггера (MDN, [Using the Popover API](https://developer.mozilla.org/docs/Web/API/Popover_API/Using)) `[не проверено: одинаковость в Firefox и Safari, WPT popover-focus]`. Tab с последнего пункта выходит дальше по шапке, слой закрывается light dismiss.
- Esc закрывает и возвращает фокус на триггер (`popover="auto"`, нативно).
- MAY: ↓/↑ между пунктами, Home/End к краям. Это дополнение к Tab, не замена (APG).
- Фокус при открытии не переносится автоматически, как в APG disclosure.

**Фолбэк без `popover`:**
- Разметка выводит и кнопку, и ссылку `<a href="/<lang>/versions/">` с той же подписью.
- Видимость переключается по `@supports selector(:popover-open)`, без JS. MUST: видим ровно один из двух элементов, у скрытого `display: none`.

**Полоса архива и `next`:**
- `<section aria-label="Версия документации">` (регион), в DOM сразу после skip link и до `header`.
- Не sticky и не fixed (MUST) [норматив: 2.4.11 — не добавляет высоты sticky-шапке; 1.4.10 — при зуме 400 % не съедает вьюпорт].
- Без `role="alert"` и без live: это постоянное содержимое, а не событие.
- Skip link ведёт мимо полосы в `main`. Порядок Tab: skip → ссылка полосы → шапка.

**Выноска `until`:** `div role="note"` по контракту выносок, заголовок `p`, а не `h*`.

**Уведомление «страницы нет»:**
- Элемент `id="version-missing"` в начале `main`, перед крошками.
- Показывается по `:target`: переход на `<родитель>#version-missing`. Фокус браузер ставит в точку фрагмента, это и есть начало `main`.
- MUST: элемент находится в потоке и не перекрыт шапкой (`scroll-margin-top` = шапка + 8) [норматив: 2.4.11].
- С JS текст уточняется (название страницы, номер версии) и объявляется один раз через общую live-область страницы (`polite`). Фокус JS не двигает.
- Кнопка «Скрыть уведомление» (`x` 16, цель 24×24 минимум, 40×40 SHOULD) снимает фрагмент через `history.replaceState`. Фокус уходит на `h1` с `tabindex="-1"`.
- Не тост: не исчезает сам [норматив: 2.2.1 по духу, 4.1.3].

**Чипы версий:**
- Ссылки на `/<lang>/versions/#labels` с подсказкой по механике xref (`popover="manual"`, тайминги delta 4.3, Esc по R6).
- Это исключение из правила «бейджи не интерактивны»: подсказку требует постановка.
- Префикс для скринридера не нужен, подпись самодостаточна.
- Цель ≥ 24 px по высоте [норматив: 2.5.8]. На строке не больше двух чипов версий, то есть ≤ 2 новых таб-стопов.

**Таблица версий:** `caption`, `th scope="col"`, первая колонка `th scope="row"` со ссылкой. Строка читаемой версии получает визуально скрытое «Вы читаете эту версию».

Критерии: 1.3.1, 1.4.1, 1.4.3, 1.4.10, 1.4.11, 2.1.1, 2.4.3, 2.4.4, 2.4.7, 2.4.11, 2.5.3, 2.5.8, 3.2.2, 3.2.3 (селектор в одном месте на всех страницах всех версий), 4.1.2, 4.1.3.

## 1. Поведение

### 1.1 Чего нет в целевой версии

См. LAYOUT, «Переход с сохранением пути». Уведомление — раздел 2.3.

### 1.2 Что разрешается при сборке, а что во время работы

| Откуда → куда | Без JS | С JS |
| --- | --- | --- |
| Текущая → архив (манифест в `data/`) | Точный `href` с подъёмом к предку и `#version-missing` | То же |
| Текущая → архив (манифеста нет) | Прямой путь, при промахе 404 | По `pages.json` цели |
| Архив → текущая / другой архив | Прямой путь, при промахе 404 | По `pages.json` цели, список по `/versions.json` |
| `next` ↔ текущая (вариант B) | Обе сборки в одном деплое: точный `href` при сборке | То же |

### 1.3 Загрузка данных

- `versions.json` и `pages.json` грузятся по намерению: `pointerenter` или `focus` на триггере, открытие слоя. На старте страницы не грузятся (MUST).
- Кэш — HTTP браузера. Отдельный storage не используется.

### 1.4 Подсказка из localStorage

- Ключ `crane.docsVersion` = id последней версии, выбранной в селекторе. Чтение и запись в try/catch.
- Используется только для строки «Недавно открывали» у пункта. Автоперехода нет (MUST).
- Значение, которого нет в `versions.json`, игнорируется.

## 2. Баннеры

### 2.1 Полоса архива (`previous`) — информирующий тон

- Место: полоса на всю ширину до шапки, в потоке. Поля 8/`--gutter`, `min-block-size` 40.
- Фон `--info-bg`, нижняя граница 1 px `--info-strong`. Слева `history` 16 `--info`. Текст `--foreground` `--type-small`.
- Текст статичный, его знает архив: «Это документация версии 0.3. Есть более новая версия.» Ссылка: «Открыть эту страницу в текущей версии».
  - Без JS ссылка ведёт по прямому пути в корень. С JS — по алгоритму подъёма, и при подъёме текст ссылки становится «Открыть текущую документацию».
- Номер текущей версии в полосе: архив его не знает. Если JS дописывает номер, высота полосы меняется, а полоса стоит над всей страницей, и сдвигается всё (CLS). Поэтому:
  - MUST: JS не меняет высоту полосы;
  - номер текущей версии показывается в слое селектора;
  - MAY: номер в полосе только при ширине ≥ 48rem и заранее зарезервированном месте (`min-inline-size` под «0.10»).
- Печать: полоса печатается (MUST): на распечатке должна быть видна версия.

### 2.2 Полоса `next` (только вариант B; в варианте A её нет)

- Предупреждающий тон: фон `--warning-bg`, граница `--warning-strong`, иконка `flask-conical` 16 `--warning`.
- Текст: «Документация следующего выпуска: она описывает то, чего ещё нет в выпущенной версии.» Ссылка «Перейти к текущей версии». Без номера.
- Корень знает `next` статически: CLS нет.

### 2.3 Уведомление «страницы нет в этой версии»

- Начало `main`, до крошек. Выноска как Callout: фон `--muted`, рамка 1 px `--border` (в forced-colors `CanvasText`), радиус 12, поля 12/16, иконка `corner-left-up` 20 `--muted-foreground`, справа кнопка `x`.
- Статичный текст (работает без JS): «Запрошенной страницы нет в этой версии документации. Открыт ближайший раздел.»
- С JS: «Страницы «{title}» нет в версии {v}. Открыт ближайший раздел.» плюс ссылка «Вернуться к версии {from}» на исходную страницу.
  - Название и исходный адрес передаются через `sessionStorage` (try/catch). TOLERANCE: или через параметр адреса, который снимается `replaceState`.
  - Без данных остаётся статичный текст.
- MUST: элемент есть в HTML каждой страницы, скрыт по умолчанию и виден только по `:target`. Ноль сдвигов от вставки, ноль инлайн-JS.

### 2.4 404

- Корневой `404.html` текущей сборки знает версии.
- Без JS: «Страницы по этому адресу нет.» и ссылки «Текущая документация» (`/<lang>/` по `lang` браузера — без JS просто `/en/` и `/ru/`) и «Все версии».
- С JS:
  - разбирает префикс `/vX.Y/`, `/next/` и язык;
  - загружает `pages.json` этой версии;
  - показывает «Этой страницы нет в версии {v}» со ссылками «Ближайший раздел: «{title}»» и «Эта страница в текущей версии» (если она там есть).
- Автоперехода с 404 нет *мнение*: адрес мог быть набран руками. Селектор и так разрешает путь до перехода, поэтому 404 почти не видна.
- `[не проверено: GitHub Pages отдаёт корневой 404.html на промахи внутри подкаталогов — в документации Pages не сказано; проверить на деплое]`.

### 2.5 Выноска `until` (текущая версия, `until` < current)

- Место: сразу после шапки страницы, до «Терминов на странице».
- Тон warning (тот же, что у WARNING): иконка `archive` 20, заголовок «Страница относится к прежним версиям».
- Тело: «Описанное действует в версиях {from}–{until}. В текущей версии этого нет.» Ссылка «Все версии документации».
- MAY: поле `replaced_by: <путь>` → строка «Что вместо этого: <xref>» (OPEN 6).
- Не сворачивается, не закрывается.
- В архивах `until` такой выноски не даёт: архив — снимок, в нём страница была актуальной.

## 3. Чипы версий в шапке страницы

- Место: `.chips-row`, после бейджей состояния и статуса. Порядок: аудитории · жанр · состояние · статус · версия · изменено.
- Вид: высота 24, поля 0/8, радиус 999, рамка 1 px `--input`, текст `--muted-foreground` caption 500, иконка 14.

| Front matter | Чип | Иконка | Когда показывать |
| --- | --- | --- | --- |
| `since` | «С версии 0.3» | `tag` | Только если `since` новее самой старой версии в `versions.yaml`. Иначе «была всегда», чип — шум |
| `since` + `until` (или только `until`; тогда `since` = самая старая) | «Версии 0.2–0.3» | `tag` | Всегда. Отдельной формы «только until» нет |
| `changed` | «Изменено в 0.4» — последняя версия из списка, не новее читаемой | `file-clock` | Если она новее `since`. Полный список — в подсказке |
| Вариант A: `since` новее последнего выпуска | «Ещё не в выпуске» | `circle-dashed`, рамка пунктиром `--input`, текст `--foreground` | Всегда. Без номера (MUST) |

- Подсказка — `popover="manual"` по механике xref. Тексты — CONTENT. Ссылка чипа ведёт на `/<lang>/versions/#labels`.

**Оглавление и дерево — без маркеров версий (SHOULD NOT).** Почему:
- оглавление показывает разделы внутри страницы, а версия — свойство страницы целиком (многоверсионного содержимого внутри страницы по контракту нет), так что маркировать там нечего;
- в дереве чип стоял бы у большинства страниц: шум, лишняя многословность для скринридера, узкая колонка 16–18rem переполняется в RU;
- информация и так стоит у `h1`, а различие версий — это смена версии селектором.

Исключение — страницы с `until` в текущей версии:
- SHOULD: не показывать их в дереве и в «Назад/Далее»; адрес остаётся живым (OPEN 7);
- в результатах поиска — бейдж «Прежние версии».

**Проверки сборки (MUST, ломают `hugo`):**
- id в `since`, `until`, `changed` есть в `versions.yaml`;
- `until` ≥ `since`;
- каждый `changed` лежит в (`since`, читаемая];
- у `state: current` после первого выпуска нет `since` → ошибка (как в предложении);
- RU и EN: одинаковые значения (паритет `authoring.md`).

## 4. Страница «Версии документации» (`/<lang>/versions/`)

- Жанр `reference`, `state: current`. Шаблон рисует таблицу из `data/versions.yaml`. Вводный абзац пишет руководитель документации.
- Структура:
  1. `h1` «Версии документации», лид «Документация каждого выпуска CRANE хранится отдельно. Выберите версию, которая у вас установлена.»
  2. Таблица, `caption` «Версии документации CRANE». Колонки:
     - «Версия» — `th scope="row"`, ссылка на корень языка этой версии;
     - «Статус» — текст «Текущая» / «Следующая» / «Прежняя», бейдж с текстом;
     - «Дата выпуска» — `<time datetime>`, длинный формат локали;
     - «Обновление» — ссылка на раздел «Обновление» для этой версии, если он есть.
     - Порядок строк: `next` (номер не выводится, «Следующая», дата «—») → `current` → `previous` по убыванию. Все номера `tabular-nums`.
  3. `## Как читать метки версий {#labels}`: `dl` с каждым чипом и каждым баннером (образец, подпись, смысл одним предложением). Сюда ведут чипы.
- На 320 px таблица из 4 колонок ведёт себя по правилу регионов таблиц ui-spec (скролл внутри, `tabindex` при переполнении). MAY: колонка «Обновление» ниже 40rem уходит в строку под версией.
- MUST: в архивах этой страницы нет. Workflow её не публикует, все «Все версии» ведут на корневую. Иначе в архиве жил бы устаревший список.
- Номера на этой странице разрешены: это селектор в табличной форме.

## 5. Поиск

- Индекс у каждой версии свой: `/vX.Y/pagefind/`, `/next/pagefind/`, корневой `/pagefind/`. Внутри версии индекс языковой, как сейчас.
  - `[проверить в реализации: bundle path Pagefind при сборке с baseURL /vX.Y/ — что скрипт палитры грузит бандл своей версии, а не корневой]`.
- MUST NOT смешивать версии: `mergeIndex` есть и поддерживается Component UI через `configureInstance` ([pagefind.app/docs/multisite](https://pagefind.app/docs/multisite/), 29.10.2026), но это вернуло бы в выдачу страницы, которых в версии пользователя нет.
- В архиве и `next`:
  - под полем поиска строка caption `--muted-foreground` с иконкой `history` (в `next` — `flask-conical`): «Поиск по документации версии 0.3» / «Поиск по документации следующего выпуска»;
  - в подвале палитры и в пустом состоянии ссылка «Искать «{q}» в текущей версии». Ведёт на `/<lang>/?search=<q>` корня; скрипт поиска корня открывает палитру с этим запросом и снимает параметр `replaceState`. `[проверить в реализации: обработка параметра в search.ts]`;
  - пустое состояние: «В версии 0.3 по запросу «{q}» ничего не найдено.» + та же ссылка + «Сбросить фильтры», если они выставлены.
  - `href` ссылки обновляется по вводу, ссылка — обычный `<a>`.
- В текущей версии строки охвата нет. Ссылки «искать в прежних» нет *мнение*: редкий сценарий, вход — селектор.
- Результаты страниц с `until` получают бейдж «Прежние версии» (мета Pagefind).

## 6. llms.txt и Markdown-версии

- Каждая сборка публикует свои `llms.txt` и `<lang>/llms-full.txt`.
- Первая строка архивного `llms.txt`: «Documentation for CRANE {v}. Current documentation: https://getcrane.dev/llms.txt».
- Корневой `llms.txt` получает строку со ссылкой на `/en/versions/`.
- SHOULD: Markdown-версия архивной страницы и «Копировать как Markdown» начинаются строкой «> Документация версии {v}.» Скопированный в ассистент текст не должен выдавать себя за текущий.

## PERF BUDGET

- CLS от версионного UI = 0 (MUST): полосы статичны, уведомление по `:target`, JS не меняет высоту элементов над контентом.
- JS острова селектора ≤ 2 КБ gzip, в пределах общих 15 КБ. Инлайн-JS не добавляется (MUST).
- `versions.json` + `pages.json` ≤ 3 КБ gzip, загрузка только по намерению.
- INP: открытие слоя — нативный `popover`, без синхронной работы на клике. Разрешение пути — после загрузки манифеста, клик не ждёт сеть дольше 300 мс: дальше переход по `href`.
- LCP не затронут: полоса — текст, шрифт тот же.
- bfcache: никаких `unload`, переходы — обычные ссылки.

## INVARIANTS (MUST)

1. Селектор — кнопка `popovertarget` + `nav` со списком `<a>`. Без `role="menu"`, `listbox`, `aria-haspopup`. Открытие только декларативное.
2. У каждого пункта рабочий `href` без JS. Модифицированные клики не перехватываются.
3. На 320 CSS px в RU и EN ни один элемент шапки не выходит за вьюпорт. Ниже 48rem селектор только в панели «Меню» [1.4.10, R3].
4. Без поддержки `popover` вместо кнопки видна ссылка на «Версии документации» (`@supports selector(:popover-open)`). Без JS слой работает декларативно.
5. Переход сохраняет язык и путь. При отсутствии страницы — ближайший предок + уведомление. Автоперехода по сохранённой версии нет.
6. Полосы архива и `next` — в потоке, не sticky и не fixed. Уведомление и выноска `until` — в потоке. Ничто из этого не перекрывает фокус [2.4.11].
7. CLS от версионного UI = 0. JS не меняет высоту полос. Уведомление показывается по `:target`.
8. Контрасты — по таблице COLOR. Пары «замерить» — ≥ 4.5 (текст) и ≥ 3 (фокус) на реализации. Смысл не передаётся только цветом [1.4.1].
9. Архив не публикует свою страницу «Версии документации». Все «Все версии» ведут на корневую. Список версий в архиве с JS берётся из `/versions.json`.
10. Поиск ищет только в своей версии и языке. Индексы не сливаются.
11. Неизвестный id версии в front matter, `until` < `since`, `changed` вне диапазона, отсутствие `since` у `state: current` после первого выпуска ломают сборку.
12. Номер невыпущенной версии нигде не выводится (`next` подписан «Следующая», чип — «Ещё не в выпуске»).
13. Бейдж `state: current` переименован. Слово «Текущая» в подписях означает только статус версии.
14. Всплывающее — в top layer, z-index только `--z-sticky`.

## TOLERANCES (SHOULD / MAY)

- Позиционирование слоя: как у `.theme-pop` или JS по триггеру. Anchor positioning — только улучшение.
- Ширина слоя 16–20rem. Высота пункта 36–40 (44 coarse). Префикс «Версия» на триггере с 64rem — по желанию.
- Анимация слоя 150–200 мс на вход, выход короче. С клавиатуры — с анимацией или без, одинаково с `.theme-pop`.
- Передача данных уведомления: `sessionStorage` или параметр адреса со снятием через `replaceState`.
- Ссылки «текущая → архив» при сборке (при манифесте в `data/`) или во время работы.
- Число версий в слое 4–6. Остальные — на странице версий.
- Тон полосы архива: info (рекомендовано) или neutral `--muted`. Не warning и не error: старая версия — не ошибка.
- Номер текущей версии в полосе архива — только с зарезервированным местом и с 48rem.
- Строка «Недавно открывали» — по желанию.

## ACCEPTANCE

1. **320 px**, RU и EN, текущая, архив, `next`: `scrollWidth == 320`. Триггер версии виден с 48rem, ниже — в «Меню» первым блоком. Полоса архива переносится без обрезки (скрипт `matrix.cjs` дельты + проверка `overflow`).
2. **Клавиатура:**
   - Tab до триггера → Enter открывает → Tab входит в первый пункт → Tab доходит до «Все версии» → Esc закрывает, фокус на триггере;
   - в архиве Tab: skip → ссылка полосы → логотип;
   - VoiceOver macOS + Safari и NVDA + Firefox: триггер читается «Версия документации: 0.3, текущая, кнопка, свёрнуто/развёрнуто»; пункт читается как ссылка, у текущей — «текущая страница»; ни «меню», ни «список» не объявлены.
3. **Без JS** (DevTools → Disable JavaScript):
   - слой открывается и закрывается;
   - пункты ведут на страницы;
   - в архиве ссылка полосы ведёт в корень;
   - `<родитель>#version-missing` показывает уведомление.
   - С эмуляцией отсутствия `popover` (временное удаление атрибута в DevTools): ссылка-фолбэк видна, кнопка — нет.
4. **Отсутствующая страница:**
   - из текущей версии выбрать архив, где страницы нет: открылся ближайший раздел, уведомление видно, объявлено один раз, фокус не украден;
   - «Скрыть» убирает уведомление, фокус на `h1`;
   - CLS в записи Performance = 0.
5. **404:** прямой адрес несуществующей страницы архива на деплое Pages открывает корневой `404.html` с разбором версии (с JS) и двумя ссылками без JS.
6. **Контраст:** axe без `color-contrast`. Пипетка по парам «замерить» в обеих темах. Forced-colors: рамки слоя, полос, чипов и уведомления видны, `check` виден.
7. **Reduced motion:** слой только фейдом, шеврон мгновенно.
8. **2.4.11:** при зуме 200 % и 400 % на 1280 фокус на ссылке полосы, пунктах слоя и кнопке «Скрыть» виден целиком и не под шапкой.
9. **Сборка:** по одному негативному примеру на каждую проверку INV 11 — `hugo` падает с понятной ошибкой.
10. **Поиск в архиве:**
    - запрос находит только страницы этой версии;
    - строка охвата видна;
    - «Искать в текущей версии» открывает палитру корня с тем же запросом, параметр снят из адреса;
    - Network: загружен бандл `/vX.Y/pagefind/`, корневой — нет.
11. **Данные:** `versions.json` и `pages.json` не запрашиваются до наведения или фокуса на триггере (Network). Сеть отключена после загрузки — переход идёт по прямому `href`.
12. **Тексты:** grep по `public/` — номера версий только в элементах селектора, чипов, баннеров, таблицы версий и раздела «Обновление». Нет «Текущая версия» в подписи бейджа состояния.

## OPEN

1. **Корень = последний выпуск + `/next/` (B) или корень = `main` (A).** Рекомендация — B (A1). Решает владелец и руководитель документации.
2. **Снимки или встроенные версии Hugo (A4).** Рекомендация — снимки, пока шаблоны и проверки сборки меняются. Пересмотреть, когда контракт `authoring.md` стабилизируется.
3. **Патч-выпуски:** перестраивать ли архив minor по тегу vX.Y.Z (тогда «неизменяемый» = «неизменяемый между патчами»).
4. **SEO архивов:** `canonical` на себя и исключение из корневого `sitemap.xml` (минимум) или ещё и `noindex`. *мнение*: исключить из sitemap, `noindex` не ставить: пользователи старых версий ищут через поисковик.
5. **Сколько версий хранится и показывается** (политика поддержки). На сайте — только факт, без сроков.
6. **Поле `replaced_by`** для страниц с `until`.
7. **Страницы `until` в дереве текущей версии:** скрывать (рекомендация) или оставлять в конце раздела.
8. **Колонка «Обновление»:** на какую страницу и якорь ведёт для каждой версии (`operations/upgrades-and-migrations#…`).

Отброшено:
- **`role="menu"` / menu button.** APG не рекомендует его для навигации, он навязывает стрелки и режим приложения в скринридере.
- **Listbox и `<select>` с переходом по `change`.** Семантика выбора, 3.2.2, нужен JS.
- **Sticky-полоса архива.** 2.4.11 и зум 400 %.
- **Тост «страницы нет».** Исчезает до прочтения, перекрывает контент.
- **Слияние индексов Pagefind.** Выдача из версий, которых у пользователя нет.
- **Автопереход по сохранённой версии.** Решение владельца: адрес = версия.
- **Номер текущей версии в полосе архива через JS без резерва места.** CLS всей страницы.
- **Маркеры версий в оглавлении и дереве.** Шум, а смысл уже у `h1`.

## Решения (29.10.2026)

- **OPEN 1 → вариант B.** Корень `/` — документация последнего выпуска, `/next/` — сборка из `main` сайта с полосой «следующий выпуск», `/vX.Y/` — прежние выпуски. Исправления текущей документации идут в ветку документации выпуска и переносятся в `main` через cherry-pick. До первого выпуска корень временно собирается из `main`: одна версия, селектор скрыт, полосы `next` нет. Сборка Pages из двух ref реализуется вместе с архивным workflow после первой публикации.
- **Бейдж `state: current`** — «Текущее состояние» / «Current state»; `state: target` — «Целевое состояние» / «Design».

## Схема публикации (до реализации)

| Путь | Источник | Когда пересобирается |
| --- | --- | --- |
| `/` | тег документации последнего выпуска (коммит сайта, на который указывает gitlink `docs/site` в теге CRANE) | при новом теге CRANE и при исправлении в ветке документации выпуска |
| `/next/` | `main` сайта, `baseURL …/next/` | при каждом push в `main` |
| `/vX.Y/` | тег документации прежнего выпуска, `baseURL …/vX.Y/` | один раз при выходе следующего выпуска (снимок неизменяем) |
| `/versions.json` | `data/versions.yaml` сборки корня | вместе с корнем |

Workflow деплоя собирает все пути в один артефакт Pages: корень и `next` при каждом запуске, архивы — из закэшированных артефактов или пересборкой по тегам.
