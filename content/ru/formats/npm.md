Страница описывает, как подключить `npm` к CRANE, опубликовать пакет со scope, управлять dist-tags, пометить версию как устаревшую, снять её с публикации и установить пакеты с registry.npmjs.org через {{< term "proxy-repository" "proxy-репозиторий" >}} CRANE. CRANE отдаёт {{< term "packument" >}} со ссылками на архивы на собственный адрес и принимает публикацию штатной командой `npm publish`.

{{< term "hosted-repository" "Hosted-репозиторий" >}} npm принимает только имена со scope (`@acme/lib`): npm выбирает реестр по scope, и внутренний пакет без scope нельзя защитить от подмены публичным ({{< xref "features/security/namespace-reservation#npm-scoped" >}}). Опубликованную версию нельзя перезаписать, а снять её можно только в течение 72 часов после публикации.

## Перед началом {#prerequisites}

- Работающий CRANE и его публичный адрес ({{< env "CRANE_PUBLIC_URL" >}}); ниже он записан как `crane.example.com`. Развёртывание: {{< xref "deploy" >}}.
- Токен доступа: {{< xref "configure/access-token" >}}. npm присылает токен в заголовке `Authorization: Bearer <token>`.
- Репозитории npm. Списки по умолчанию пусты: задайте {{< env "CRANE_NPM_REPOS" >}} для hosted-репозиториев (например `internal`) и {{< env "CRANE_NPM_PROXY_REPOS" >}} для proxy-репозиториев (например `npmjs`): {{< xref "configure/repositories" >}}.
- `npm` последней версии: на ней CRANE проверяется на реальном стенде.

## Шаги {#steps}

### Подключить hosted-репозиторий {#connect}

1. Передайте токен переменной оболочки. Файл `.npmrc` ссылается на неё, поэтому значение в файл не попадает.

   ```bash
   export NPM_TOKEN="<token>"
   ```

2. Назовите репозиторий реестром своего scope и задайте токен для его адреса в `.npmrc` проекта. Адрес репозитория заканчивается на `/`: по этому префиксу npm выбирает токен.

   ```ini
   @acme:registry=https://crane.example.com/npm/internal/
   //crane.example.com/npm/internal/:_authToken=${NPM_TOKEN}
   ```

### Опубликовать пакет {#publish}

1. Убедитесь, что в `package.json` имя со scope и версия, которой ещё нет в репозитории.

   ```json
   { "name": "@acme/lib", "version": "1.0.0" }
   ```

2. Опубликуйте пакет.

   ```bash
   npm publish
   ```

3. Чтобы поставить версии свой dist-tag, добавьте `--tag`. Без него публикация ставит тег `latest`.

   ```bash
   npm publish --tag next
   ```

Перед записью CRANE проверяет:

- **Имя.** Имя без scope получает `422`. В имени нового пакета допустимы только строчные буквы, цифры и `-._`.
- **Состав публикации.** Документ содержит ровно одну версию, одно вложение и один dist-tag, который указывает на публикуемую версию. Имя и версия в манифесте совпадают с запросом.
- **Контрольные суммы.** В `dist.integrity` обязательна сумма sha512. CRANE сверяет её, а также sha1 из `dist.shasum`, если он указан, с фактическим содержимым архива. Несовпадение получает `422`.
- **Зависимости.** Разделы `dependencies`, `optionalDependencies` и `peerDependencies` ссылаются только на реестр: диапазон версий, тег или `npm:<имя>@<диапазон>`. Git, URL, `file:`, `link:` и `workspace:` отклоняются с `400`. Раздел `devDependencies` не проверяется.
- **Резервирование и публичное имя.** Имя, покрытое {{< term "namespace" "namespace-ом" >}} другой команды, даёт `403`. Новое имя, которое уже занято на registry.npmjs.org, тоже даёт `403`; эту проверку CRANE выполняет, когда настроен proxy-репозиторий npm. Правила: {{< xref "features/security/namespace-reservation#publish-rule" >}}.
- **Размер.** Документ публикации больше {{< env "CRANE_MAX_PUBLISH_BYTES" >}} получает `413`. Архив приходит в base64 внутри JSON, то есть примерно на треть больше исходного файла: {{< xref "configure/limits" >}}.

CRANE не сохраняет поля `deprecated`, `publishConfig` и служебные поля с префиксом `_`.

### Управлять dist-tags {#dist-tags}

1. Поставьте тег на версию, посмотрите теги и снимите тег.

   ```bash
   npm dist-tag add @acme/lib@1.0.0 stable
   npm dist-tag ls @acme/lib
   npm dist-tag rm @acme/lib stable
   ```

Имя тега непустое, не длиннее 128 символов, состоит из ASCII-букв, цифр и `-._~` и не совпадает с номером версии. Тег указывает только на версию, которую CRANE отдаёт клиентам. Тег `latest` снять нельзя: если его нет, CRANE выводит его сам, выбирая старшую версию без pre-release (а при их отсутствии старшую вообще).

### Пометить версию устаревшей {#deprecate}

1. Задайте сообщение. Пустая строка вместо сообщения снимает пометку.

   ```bash
   npm deprecate @acme/lib@1.0.0 "use 2.x"
   ```

`npm install` печатает предупреждение `deprecated @acme/lib@1.0.0: use 2.x`. Версия остаётся доступной.

### Установить зависимости через proxy {#proxy}

1. Добавьте в `.npmrc` реестр по умолчанию и токен для proxy-репозитория. Имя `npmjs` в адресе — имя proxy-репозитория на сервере. Пакеты со scope `@acme` по-прежнему идут в hosted-репозиторий, остальные — в proxy.

   ```ini
   registry=https://crane.example.com/npm/npmjs/
   //crane.example.com/npm/npmjs/:_authToken=${NPM_TOKEN}
   ```

2. Установите пакет как обычно.

   ```bash
   npm install is-number@7.0.0
   ```

Первый запрос к каждому документу и архиву CRANE выполняет к registry.npmjs.org сам, сохраняет результат в кэше и отдаёт клиенту; повторные запросы идут из кэша. Ссылки `dist.tarball` в документе указывают на CRANE. Архив проверяется по sha512 из `dist.integrity` документа {{< term "upstream" >}}.

Версия, у которой в документе upstream есть только sha1 (`dist.shasum`), через proxy не отдаётся: проверить архив нечем, и CRANE отвечает `502`. Имя, которое опубликовано в hosted-репозитории или покрыто резервированием, proxy отдаёт как несуществующее (`404`) ({{< xref "features/security/namespace-reservation#no-groups" >}}). Запись в proxy-репозиторий невозможна: сервер отвечает `405`.

> [!NOTE]
> `npm audit` через CRANE не поддерживается: сервер отвечает `501`, потому что список зависимостей проекта нельзя отдавать наружу. Установка при этом не прерывается.

## Проверка {#verify}

1. Проверьте, что репозиторий отвечает на `ping`. Токен передаётся через stdin (`-K -`), поэтому он не виден в списке процессов.

   ```bash
   printf 'header = "Authorization: Bearer %s"\n' "$NPM_TOKEN" \
     | curl -fsS -K - https://crane.example.com/npm/internal/-/ping
   ```

   ```json
   {}
   ```

2. После публикации проверьте теги пакета.

   ```bash
   npm view @acme/lib dist-tags --json
   ```

   Тег `latest` указывает на опубликованную версию.

3. Проверьте, что установка идёт через CRANE.

   ```bash
   npm view is-number@7.0.0 dist.tarball
   ```

   Адрес начинается с `https://crane.example.com/npm/npmjs/`.

## Снятие версии с публикации {#unpublish}

`npm unpublish` снимает версию, если с публикации прошло не больше 72 часов. Версия получает {{< term "tombstone" >}}: её архив больше не отдаётся, а номер занять снова нельзя.

```bash
npm unpublish @acme/lib@1.1.0-beta.0
```

После снятия версия пропадает из `npm view @acme/lib versions`, а повторная публикация того же номера получает `409`. Если окно закрыто, сервер отвечает `403`.

Весь пакет снимает `npm unpublish @acme/lib --force`. Если хотя бы одна версия опубликована больше 72 часов назад, CRANE не меняет ничего и отвечает `403`. Другие способы скрыть версию в npm — `npm deprecate` и перенос dist-tag. Семантика по всем форматам: {{< xref "features/security/immutable-versions#formats" >}}.

## Ответы при отказах {#errors}

| Статус | Когда | Сообщение |
| --- | --- | --- |
| `400` | Документ публикации разобрать нельзя, состав публикации неверный, зависимость вне реестра, недопустимое имя пакета или тега, снятие тега `latest`, неподдерживаемое изменение документа | Причина на русском языке; для неподдерживаемой операции: `операция не поддерживается` |
| `401` | Нет заголовка `Authorization` | `требуется токен` |
| `403` | Токен неверный | `токен отвергнут` |
| `403` | Имя покрыто namespace другой команды | `имя принадлежит namespace другого workspace` |
| `403` | Новое имя уже занято на registry.npmjs.org | `имя занято в публичном реестре: для публикации нужна резервация платформы (CRANE_NAMESPACES)` |
| `403` | Окно снятия версии закрыто; версия заблокирована или находится в карантине | `окно удаления закрыто: версия опубликована слишком давно` или `версия недоступна: …` |
| `404` | Репозиторий, пакет или версия не найдены; имя внутреннее, а запрос идёт в proxy | `не найдено`, `репозиторий не найден` или `версия не найдена` |
| `405` | Запись в proxy-репозиторий | `репозиторий не hosted: публикация запрещена` |
| `409` | Версия уже существует, в том числе снятая | `версия уже существует` |
| `410` | Скачивание архива версии в состоянии tombstone | `версия недоступна: Deleted` |
| `413` | Документ публикации больше {{< env "CRANE_MAX_PUBLISH_BYTES" >}} | — |
| `422` | Имя без scope; сумма архива не совпала с заявленной | `формат требует scope в имени пакета` или `контрольная сумма не совпала: …` |
| `501` | `npm audit` | `аудит уязвимостей через реестр не поддерживается` |
| `502` | Proxy: registry.npmjs.org недоступен, архив не прошёл проверку суммы, в документе нет sha512 или архив больше {{< env "CRANE_PROXY_MAX_ARTIFACT_BYTES" >}} | `upstream недоступен` |
| `503` | Каталог или хранилище blob недоступны; не удалось проверить новое имя на registry.npmjs.org | `хранилище временно недоступно` или `не удалось проверить имя в публичном upstream: повторите позже` |

Тело ошибки имеет вид `{"error":"…"}`. Текст заканчивается на `(request_id <id>)`: идентификатор помогает администратору развёртывания найти запрос в журнале. Статус `503` приходит с заголовком `Retry-After`.
