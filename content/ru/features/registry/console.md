Веб-консоль CRANE — одностраничное приложение, встроенное в бинарник: отдельный веб-сервер не нужен. Каждая роль начинает с собственного рабочего стола, на котором собраны её задачи: разработчик ищет пакет и копирует команду установки, администратор платформы смотрит состояние хранилищ и очередей, специалист по ИБ работает с журналом действий.

Консоль работает через тот же API, что и скрипты, и рисует действие только тогда, когда API вернул на него ссылку: нет ссылки — нет кнопки. Кнопка недоступна с объяснением только там, где API прямо сообщает причину запрета. Подробнее об API: {{< xref "features/registry/integrations#api" >}}.

## Рабочие столы ролей {#desks}

| Роль | Главный экран | Действия в один клик |
| --- | --- | --- |
| Разработчик | Поиск, избранное, недавние; карточка пакета с командой установки под выбранный клиент | Скопировать команду, посмотреть замену устаревшего пакета |
| Владелец библиотеки | Мои пакеты: версии, здоровье, потребители, открытые риски | Пометить устаревшим, назначить замену, запросить approval |
| CI/CD-инженер | Роботы, trust policies, последние публикации из CI, ошибки | Создать trust policy, взять шаблон CI |
| Администратор платформы | Хранилища и классы хранения, объём по командам, попадания в кэш, upstream, очереди | Пробный прогон retention, прогрев кэша, проверка целостности |
| AppSec | Очередь находок с приоритетами и оценками, SLA, экстренные блокировки, состояние фидов, лицензии на проверку | Подтвердить экстренную блокировку, принять VEX, выдать исключение с TTL, создать задачи |
| SecOps | Журнал действий: поиск, маскированные данные, раскрытие с обоснованием, экспорт, проверка целостности; события SIEM, нарушения разделения обязанностей | Раскрыть данные события, выгрузить диапазон, отозвать токен |
| Аудитор | Журнал действий только на чтение с маскированными данными, отчёты о соответствии | Сформировать отчёт |
| Любой пользователь | «Мои токены» и «Мои действия» | Отозвать токен, посмотреть свою историю |
| Руководитель | Владение, доступы команды, риски, потребление ресурсов | — |

Права ролей и разделение обязанностей описаны на странице {{< xref "features/security/access-control" >}}.

## Экраны {#screens}

### Поиск {#s-search}

{{< screenshot story="S1Search" variant="DesktopLight" alt="Экран поиска: строка запроса, сегменты форматов со счётчиками, фильтры по репозиторию и команде и список карточек пакетов" >}}

Экран поиска — главный для разработчика. Результаты появляются по мере ввода, рядом счётчики по форматам и команде. Если ассистенты недоступны, экран сообщает, что поиск работает без семантики. Как работает ранжирование, описано на странице {{< xref "features/registry/search" >}}.

### Карточка пакета {#s-package}

{{< screenshot story="S2Package" variant="DesktopLight" alt="Карточка пакета: заголовок со статусом и форматом, показатели, вкладки и блок установки с командой для выбранного клиента" >}}

Карточка собирает всё о пакете: описание, команду установки под выбранный клиент, последние версии, происхождение последней версии (из claims CI) и открытые риски. Для proxy-репозитория карточка показывает предупреждение, если {{< term "upstream" >}} недоступен и данные взяты из устаревшей копии ({{< xref "features/registry/proxy-cache#stale" >}}).

### Версии пакета {#s-versions}

{{< screenshot story="S3Versions" variant="Desktop1440Sheet" alt="Таблица версий пакета с состоянием и причиной, открытая боковая панель выбранной версии со сводкой, файлами и историей" >}}

Таблица показывает состояние каждой версии и причину блокировки. Боковая панель выбранной версии содержит сводку (PURL, SHA-256, размер), файлы с контрольными суммами, историю и metadata. Кнопки yank и unyank появляются, только если API вернул соответствующие ссылки, а подсказка объясняет, что значит yank в формате пакета ({{< xref "features/security/immutable-versions#formats" >}}).

### Мои токены {#s-tokens}

{{< screenshot story="S5Tokens" variant="DesktopLight" alt="Список токенов пользователя: тип, префикс, права, срок действия, последнее использование и кнопка отзыва" >}}

Каждый пользователь видит свои токены и может отозвать любой из них. Секрет нового токена показывается один раз в отдельном диалоге и не сохраняется в странице. Таблица предупреждает о токенах, срок которых скоро истекает или которые давно не использовались. Токены описаны на странице {{< xref "features/security/secrets" >}}.

### Обзор платформы {#s-platform}

{{< screenshot story="S6Platform" variant="Desktop1440" alt="Обзор платформы: плитки с объёмом хранилищ, попаданием в кэш, доступностью upstream и очередью задач, графики задержек и состояние компонентов" >}}

Экран администратора платформы показывает объём хранилищ, попадание в кэш, доступность upstream, длину очереди задач, состояние компонентов и задержки на фоне целевого SLO. Быстрые действия запускают пробный прогон retention, прогрев кэша по lockfile и проверку целостности. Мёртвые задачи можно повторять по одной. Состояние компонентов совпадает с данными, которые описаны на странице {{< xref "features/operations/observability" >}}.

### Журнал действий {#s-journal}

{{< screenshot story="S9Journal" variant="Desktop1440" alt="Журнал действий: плитки с числом событий и состоянием цепочки, фильтры, таблица событий и панель выбранного события" >}}

Экран журнала действий доступен SecOps целиком, аудитору — только на чтение с маскированными данными, AppSec — только по его собственным решениям. SecOps проверяет целостность цепочки и раскрывает данные события с обоснованием и {{< term "step-up" >}}; экспорт тоже требует step-up. Каждый просмотр журнала записывается в сам журнал. Подробнее: {{< xref "features/security/security-journal" >}}.

### Системные состояния {#s-states}

{{< screenshot story="S10States" variant="Forbidden" alt="Страница отказа в доступе: сработавшее правило, идентификатор запроса, подсказка по исправлению и контакт" >}}

Консоль показывает загрузку, пустые состояния и ошибки единообразно. Ошибка API выводится одним компонентом: с идентификатором запроса и подсказкой по исправлению. Отказ показывает сработавшее правило и контакт, но только для видимого ресурса. Скрытый и несуществующий ресурс получают один и тот же нейтральный ответ «Не найдено или нет доступа». Опасные действия возвращают step-up в виде модального окна, сохраняя введённые данные. Для деградации CRANE показывает баннеры (режим «только чтение», недоступность upstream), а для результатов действий — уведомления с копированием идентификатора запроса.

## Остальные экраны {#more}

- **Вход и сессия:** вход через SSO, step-up, мастер первого запуска.
- **Каталог:** избранное и недавние, полная страница версии с вкладками находок, лицензии, evidence и продвижения.
- **Владелец библиотеки:** мои пакеты, пометка устаревшим с заменой, запрос approval, namespace.
- **Доступ, токены и CI:** мои действия, роботы, trust policies, публикации из CI, доступ команды, диагностика отказа «Почему отказано».
- **Платформа:** хранилища, репозитории, upstream, квоты, retention и сборка мусора, проверка целостности, готовность и прогрев, очереди, вебхуки, интеграции и AI, команды, статус системы, настройки платформы.
- **Команды и владение:** маппинги групп, межкомандный доступ, передача владения, след команды, переключатель команды ({{< xref "features/registry/teams-and-ownership" >}}).
- **AppSec:** находки, бюллетени, фиды, экстренный режим, исключения, VEX, проверка лицензий, политики и gates, approvals, карантин, метрики.
- **SecOps:** рабочий стол, журнал, экспорт и целостность, приёмники SIEM, правила Sigma, нарушения разделения обязанностей, отзыв токенов, SOAR, скачивания.
- **Общее:** граф зависимостей (с обязательной табличной альтернативой), ассистент, подтверждение действий A2A, командная палитра (Ctrl K) и центр уведомлений.

## Доступность и язык {#accessibility}

Интерфейс соответствует WCAG 2.2 AA, имеет светлую и тёмную темы и работает с клавиатуры. Язык переключается в самом интерфейсе: поддерживаются русский и английский, захардкоженных видимых строк нет. Списки любого размера виртуализируются, первая загрузка приложения укладывается в 250 КБ в сжатом виде, а остальное подгружается по маршрутам. Целевая задержка поиска на сервере — менее 150 мс (p95).

## Безопасность отдачи {#delivery}

README, metadata и evidence пакетов недоверенны, поэтому консоль работает со строгой политикой. Политика безопасности содержимого разрешает скрипты, стили, шрифты и соединения только с собственного origin, запрещает встраивание в чужие страницы и не допускает inline-скриптов и `unsafe-eval`. README отображается через очистку разметки: сырой HTML не пропускается, ссылки получают `rel="noopener noreferrer nofollow"`, а внешние картинки не загружаются, а показываются ссылкой, чтобы пиксель слежения не следил за специалистами по безопасности. Гарантия и её границы: {{< xref "features/security/untrusted-content" >}}.
