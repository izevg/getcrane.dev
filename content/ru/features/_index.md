CRANE — self-hosted реестр пакетов и proxy для пяти экосистем: Cargo, npm, PyPI, Maven и NuGet. Реестр стоит на пути каждой сборки, поэтому он одновременно главный актив цепочки поставки и лучшая точка контроля. Из этого следует порядок возможностей: сначала CRANE гарантирует, что в сборку попадают только те байты и только те имена, которым можно доверять, и лишь затем делает работу с пакетами удобной.

Раздел описывает, как CRANE устроен и что он обеспечивает. Как развернуть и настроить его сейчас, описывают разделы {{< xref "deploy" >}} и {{< xref "configure" >}}.

## Безопасность прежде всего {#security-first}

Гарантии, которые CRANE даёт для каждого пакета, проходящего через {{< term "hosted-repository" >}} или {{< term "proxy-repository" >}}: опубликованная версия не меняется, байты проверяются по дайджесту, внутреннее имя никогда не приходит из {{< term "upstream" >}}, новая версия из upstream выдерживается в карантине, исходящие запросы не уходят во внутреннюю сеть, а каждое решение безопасности попадает в журнал. У каждой гарантии есть описанные границы: где она действует и где перестаёт.

{{< xref "features/security" "Безопасность прежде всего" >}}

## Управление реестром {#registry}

Hosted-репозитории для собственных пакетов команд, proxy с кэшем для публичных реестров, пять экосистем со стандартными клиентами, команды и владение, поиск, веб-консоль, CLI и API для интеграций.

{{< xref "features/registry" "Управление реестром" >}}

## Развёртывание и обслуживание {#operations}

Один бинарник и один образ на все профили: от одного узла в Docker Compose до кластера Kubernetes. PostgreSQL — единственный источник истины, кэш и хранилище proxy можно потерять без потери данных, обновления идут без простоя.
