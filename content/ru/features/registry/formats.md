CRANE реализует протоколы Cargo, npm, PyPI, Maven и NuGet по их спецификациям. Разработчик не меняет клиент и не ставит расширений: меняется только адрес репозитория и токен. Совместимость проверяет автоматическая матрица реальных клиентов.

Различаются только протоколы. Права, видимость версии, резервирование имён, кэш и проверки безопасности общие для всех форматов, потому что адаптер формата лишь переводит запросы клиента в команды ядра и ничего не решает сам. Пошаговое подключение каждого клиента описано в разделе {{< xref "formats" >}}.

## Проверенные клиенты {#clients}

| Экосистема | Клиенты в матрице совместимости |
| --- | --- |
| Cargo | cargo |
| npm | npm, pnpm, yarn |
| PyPI | pip, uv, poetry |
| Maven | Maven, Gradle |
| NuGet | dotnet, nuget.exe |

Протоколы реализованы по спецификациям, а матрица проверяет их на реальных клиентах.

## Версии клиентов {#versions}

Поддерживаются две последние мажорные версии каждого клиента. Для cargo поддерживаются две последние стабильные версии. Состав версий фиксирует матрица совместимости.

## Cargo {#cargo}

CRANE реализует только sparse-протокол ({{< term "sparse-registry" >}}, {{< cite "rfc-2789" >}}, {{< cite "cargo-registry-index" >}}); git-индекс не поддерживается. Один репозиторий CRANE — один реестр cargo, hosted (внутренние крейты) или proxy (зеркало crates.io).

- **Индекс.** `config.json` сообщает адрес скачивания и требование аутентификации. Файл индекса крейта — по одной строке JSON на версию; индекс поддерживает `ETag` и условные запросы.
- **Скачивание.** Архив `.crate` CRANE отдаёт потоком или перенаправлением на хранилище.
- **Публикация.** CRANE принимает бинарный формат cargo, проверяет SHA-256, `Cargo.toml` внутри архива и владение именем. Зависимости публикуемого крейта проверяются: зависимость из этого же реестра хранится без поля `registry`, зависимость с crates.io приводится к его каноническому адресу, зависимость на любой другой реестр публикация отклоняет с кодом `400`.
- **Yank.** Команды `yank` и `unyank` ({{< term "yank" >}}) скрывают и возвращают версию; скрытая версия остаётся доступной по lockfile.
- **Владельцы.** Владельцами крейта считаются роли `owner` и `maintainer` команды-владельца ({{< xref "features/registry/teams-and-ownership#membership" >}}).
- **Имена.** Имена крейтов сравниваются без учёта регистра, `-` и `_` равны. Публичность имени при первой публикации CRANE проверяет по API crates.io: любое написание публичного крейта получает отказ, а при сбое проверки CRANE отвечает `503`.
- **Proxy.** Для proxy-репозитория CRANE подставляет собственный адрес скачивания в `config.json`, а индекс и архивы берёт у crates.io. Потребитель направляет зависимости с crates.io через CRANE настройкой `[source.crates-io] replace-with`.

Для SBOM используется `Cargo.lock`, а пакет идентифицируется как {{< term "purl" >}} `pkg:cargo/<name>@<version>`.

## npm {#npm}

CRANE отдаёт {{< term "packument" >}} с адресами архивов на собственный адрес и принимает публикацию штатной командой `npm publish`. Поддерживаются dist-tags, `deprecate` и `unpublish` в окне, которое задаёт политика (72 часа).

- **Scoped-имена.** Hosted-репозиторий npm принимает только имена со scope. Причина в том, что npm выбирает реестр по scope: внутренний пакет без scope нельзя защитить от dependency confusion ({{< xref "features/security/namespace-reservation#npm-scoped" >}}).
- **Время публикации.** Для окна карантина CRANE читает время публикации версии из поля `time` документа.
- **Dist-tag на скрытую версию.** Если тег указывает на версию, которую CRANE не отдаёт, он переводится на наибольшую отдаваемую версию не выше версии тега, а если такой нет, тег убирается ({{< xref "features/security/upstream-quarantine#document" >}}).

## PyPI {#pypi}

CRANE отдаёт Simple API ({{< cite "pep-503" >}}) и поддерживает yank ({{< cite "pep-592" >}}). Имя файла уникально навсегда: его нельзя ни перезаписать, ни занять снова после удаления.

- **Нормализация имён.** Имена приводятся к нижнему регистру, серии символов `-`, `_`, `.` заменяются на `-` ({{< cite "pep-503" >}}).
- **Время публикации.** Для окна карантина CRANE читает `upload-time` ({{< cite "pep-700" >}}).
- **Несколько индексов.** Опция pip `--extra-index-url` объединяет версии из нескольких индексов. CRANE не полагается на порядок источников: имя, покрытое namespace или уже опубликованное в hosted, proxy отдаёт как несуществующее ({{< xref "features/security/namespace-reservation#no-groups" >}}).

## Maven {#maven}

CRANE отдаёт `maven-metadata.xml` и файлы артефактов; с ним работают Maven и Gradle. Контрольные суммы `.sha1`, `.md5`, `.sha256` и `.sha512` CRANE берёт из каталога, где они записаны при приёме файла, и не вычисляет заново при каждом запросе.

- **Скрытие.** В протоколе Maven нет способа скрыть версию, поэтому CRANE переводит её в состояние `Blocked` и показывает диагностику.
- **SNAPSHOT.** Каждая timestamp-сборка — отдельная неизменяемая версия, а `1.0-SNAPSHOT` служит представлением в `maven-metadata.xml` ({{< xref "features/security/immutable-versions#snapshots" >}}).
- **Время публикации.** Для окна карантина CRANE читает `Last-Modified` файла.

## NuGet {#nuget}

CRANE реализует ресурсы NuGet V3 ({{< cite "nuget-server-api" >}}): registration, flat container и публикацию. Клиент dotnet получает токен через credential provider `crane`, который сам продлевает токен через CLI ({{< xref "features/registry/cli#setup" >}}).

- **Unlist.** `unlist` и `relist` реализованы как yank и обратное ему действие: версия скрыта из выбора, доступна по точному номеру, действие обратимо ({{< xref "features/security/immutable-versions#nuget-unlist" >}}).
- **Контрольные суммы.** Значение `packageHash` CRANE отдаёт из каталога.
- **Время публикации.** Для окна карантина CRANE читает поле `published` из registration.

## Скрытие и удаление по форматам {#hide}

Семантика скрытия и удаления зависит от протокола: PyPI и Cargo имеют yank, NuGet — unlist, npm — deprecate и dist-tags, а в Maven скрытия нет. Таблица по всем пяти форматам приведена на странице {{< xref "features/security/immutable-versions#formats" >}}; здесь она не повторяется.
