{{< term "quarantine" "Карантин" >}} — окно после публикации версии в {{< term "upstream" >}}, в течение которого CRANE не отдаёт эту версию клиентам {{< term "proxy-repository" "proxy-репозитория" >}}. Окно отсчитывается от времени публикации в upstream, а не от первого обращения к CRANE.

Это защита от захвата аккаунта maintainer: вредоносная версия популярного пакета обычно живёт в публичном реестре часы, пока её не снимут или пока она не попадёт в фиды вредоносных пакетов. За это время CRANE её не отдаёт. Так же устроены блокировки по правилам: версия исчезает из документов и из скачивания одинаково для свежего и устаревшего кэша.

## Угроза {#threat}

Автоматические обновления и сборки с плавающим диапазоном версий подхватывают её в первые минуты. Реестр не успевает узнать, что версия вредоносна: advisory ещё нет, а автор ещё не заметил взлом.

## Гарантия {#guarantee}

- Версия из upstream, опубликованная менее чем окно назад, клиентам proxy не отдаётся: ни в документе версий, ни по прямой ссылке на файл.
- Тот же фильтр применяется к устаревшей копии документа, которую CRANE отдаёт при недоступном upstream.
- Заблокированная версия не отдаётся ни из свежего, ни из устаревшего кэша, в том числе по прямому URL из lockfile.
- Блокировка по правилу вступает в силу на всех репликах не позже чем за 5 секунд.
- Отсутствие у версии известного времени публикации не подменяется временем первой выдачи.

## Как это устроено {#mechanism}

### Окно и время публикации {#window}

Версия моложе окна не отдаётся. Размер окна — настройка экземпляра; значение по умолчанию — 24 часа. Более длинное окно заметно задерживало бы исправления безопасности.

Время публикации в upstream читает адаптер формата:

| Формат | Источник времени публикации |
| --- | --- |
| npm | `time[версия]` в {{< term "packument" >}} |
| PyPI | `upload-time` ({{< cite "pep-700" >}}) |
| NuGet | `published` в registration |
| Cargo | необязательное поле `pubtime` строки индекса ({{< cite "cargo-registry-index" >}}); у старых версий отсутствует |
| Maven | `Last-Modified` файла |

Если времени нет, решает политика `unknown_age`. Её значение `quarantine` держит такую версию в карантине, значение `release` отдаёт её. По умолчанию версия без времени отдаётся, поэтому старые версии не исчезают из выдачи.

### Фильтрация документа {#document}

Документ (packument, индекс crate, список файлов) CRANE показывает клиенту после фильтра. Версии в карантине или под блокировкой убираются из строк индекса Cargo и из полей `versions` и `time` packument. Dist-tag, указывающий на скрытую версию, переносится на наибольшую отдаваемую версию не выше версии тега и не pre-release (если тег указывал на стабильную). Если такой версии нет, тег убирается.

Срок хранения отфильтрованного документа не превышает времени до ближайшего конца окна среди его версий. Поэтому версия появляется в документе, когда окно истекло, а не после следующего обновления из upstream.

### Проверка артефакта {#artifact}

Отдача файла проверяется независимо от документа. Lockfile с готовой ссылкой (`resolved`) идёт мимо packument, но не мимо этой проверки. CRANE вписывает пару «имя, версия» в URL файлов при переписывании документа; разбор имени файла остаётся запасным путём для старых ссылок.

### Устаревший кэш {#stale}

При недоступном upstream CRANE может отдать сохранённую копию документа ({{< term "stale-if-error" >}}). Фильтр стоит после кэша сырого документа, поэтому устаревшая копия проходит тот же фильтр: заблокированная версия не просочится через кэш.

### Блокировки {#blocks}

Правило блокировки действует по диапазону имени и версий, а не переводом строк в другое состояние. Оно работает на hosted и proxy, в том числе на версии, которые ещё никто не скачивал. Advisory вида `MAL-*` создаёт такое правило автоматически. Индекс правил живёт в памяти реплики и перестраивается по событию, а полная перезагрузка по таймеру страхует от потерянного сообщения. Срок вступления в силу на всех репликах не больше 5 секунд, в худшем случае — период перезагрузки.

Блокировка не пишется в строки версий и вычисляется при каждой выдаче. Поэтому она действует и на версии, у которых строки в каталоге нет, а при снятии блокировки ничего не нужно восстанавливать.

Автоматически правило из `MAL-*` не снимается, даже если {{< term "advisory" >}} отозван: подмена или ошибка фида снимала бы блокировку вредоносного пакета. Отзыв даёт специалисту по безопасности задачу на пересмотр. Снять блокировку может только явное действие дежурного специалиста со {{< term "step-up" >}} и обоснованием.

> [!SECURITY]-
> **Break-glass**
>
> Для конкретного проекта можно временно разрешить скачивание заблокированной версии: не более 24 часов, с двумя подтверждениями (специалист по безопасности и владелец пакета), каждое использование пишется в аудит. Разрешение действует только на скачивание артефакта (сборка с закреплённой версией) и не возвращает версию в документы.

### Что видит клиент {#client-view}

Для клиента карантин выглядит как отсутствие свежей версии. Тег `latest` указывает на предыдущую версию. Lockfile с только что вышедшей версией получает отказ с диагностикой: причина и время окончания окна. После того как окно истекло, версия появляется сама.

## Границы гарантии {#limits}

> [!LIMITS]
> - **Только proxy-репозитории.** Для hosted-репозиториев действует другой механизм: проверки и approval перед выпуском версии.
> - **Версии, выпущенные досрочно.** Версия, выпущенная из карантина досрочно через promotion, отдаётся и внутри окна.
> - **Версия без времени публикации.** Если формат не передал время, версия обрабатывается по `unknown_age`. При значении `release`, принятом по умолчанию, она отдаётся сразу.
> - **Окно не обнаруживает вредоносность.** Оно лишь выигрывает время. Версия, которая оставалась вредоносной дольше окна, после его окончания отдаётся, если на неё нет блокировки.
> - **Блокировка действует по явному правилу.** Версия без advisory и без правила окно прошла как обычная.
> - **Окно задерживает и исправления.** Срочное исправление безопасности из upstream появится у клиентов не раньше окончания окна, если его не выпустить досрочно.
