Страница помогает найти причину ошибки по её точному тексту и сказать, что делать. Ошибки делятся на три группы: сервер не стартует, сервер стартует, но не готов, и клиент получает ошибку в ответе. У каждой группы свой источник текста.

Сервер, который не смог стартовать, пишет запись `роль завершилась с ошибкой` с полем `error` и завершается с кодом `1`. Ошибка клиента приходит в теле ответа, а полный контекст лежит в журнале под тем же идентификатором запроса. Тексты сервера на русском языке, ошибки драйвера PostgreSQL и операционной системы остаются на английском.

## Перед началом {#prerequisites}

- Доступ к журналу `crane`: {{< xref "operations/logs" >}}.
- Для ошибок клиента — идентификатор запроса `request_id` из тела ответа или заголовка `X-Request-Id`.

## Шаги {#steps}

1. Определите стадию. Контейнер перезапускается или остановлен — сервер не стартует. Контейнер работает, но `crane healthcheck` возвращает `1` — сервер не готов. Контейнер здоров, а клиент получает ошибку — ошибка запроса.

   ```bash
   docker compose --project-directory . \
     -f deploy/compose/docker-compose.yaml ps -a
   ```

2. Найдите текст ошибки. Для сервера, который не стартует, — поле `error` последней записи уровня `ERROR`.

   ```bash
   docker compose --project-directory . \
     -f deploy/compose/docker-compose.yaml logs --no-log-prefix --tail 50 crane \
     | jq -cR 'fromjson? | select(.level == "ERROR") | .error'
   ```

3. Сопоставьте текст с таблицей ниже и выполните действие.

4. Перезапустите сервис, если менялась конфигурация, и убедитесь, что `crane healthcheck` возвращает `0`: {{< xref "operations/health-checks" >}}.

## Сервер не стартует {#startup}

Подробные списки сообщений по темам лежат на страницах настройки: {{< xref "configure/network#errors" "адреса и порты" >}}, {{< xref "configure/storage#errors" "хранилища" >}}, {{< xref "configure/cache#errors" "кэш" >}}, {{< xref "configure/limits#errors" "пределы" >}}. Здесь собраны случаи, с которыми чаще всего обращаются.

| Текст в поле `error` | Причина | Что делать |
| --- | --- | --- |
| `использование: crane <serve\|all\|migrate\|healthcheck>` (код `2`) | Аргументов не один или роль неизвестна | Запустите ровно одну роль: {{< xref "reference/server-cli#usage" >}} |
| `не задана переменная CRANE_DATABASE_URL` (также `CRANE_BLOBS`, `CRANE_PUBLIC_URL`, `CRANE_TOKEN`) | Обязательная переменная не задана | Задайте переменную или её форму `_FILE`: {{< xref "reference/environment-variables" >}} |
| `переменные CRANE_TOKEN и CRANE_TOKEN_FILE взаимоисключающие` (то же для `CRANE_DATABASE_URL` и `CRANE_CACHE`) | Заданы обе формы одного секрета | Оставьте одну форму |
| `не удалось прочитать CRANE_TOKEN_FILE: No such file or directory (os error 2)` | Файл секрета не смонтирован, путь неверен или у пользователя `65532` нет прав чтения | Проверьте путь и права файла: {{< xref "deploy/docker-compose#secrets" >}} |
| `некорректное значение CRANE_TOKEN: значение пусто` | Файл секрета пуст | Запишите значение в файл; завершающий перевод строки отбрасывается |
| `CRANE_DATABASE_URL и CRANE_BLOBS: memory нельзя смешивать с постоянным хранилищем` | Один из адресов `memory`, другой нет | Задайте оба постоянными или оба `memory` |
| `не удалось подключиться к PostgreSQL (CRANE_DATABASE_URL): pool timed out while waiting for an open connection` | PostgreSQL недоступна за 5 с: остановлена, неверный адрес или закрыта сеть. Мгновенный отказ даёт `error communicating with database: …` | Запустите PostgreSQL, проверьте адрес в секрете. Compose перезапустит `crane` сам |
| `не удалось подключиться к PostgreSQL (CRANE_DATABASE_URL): error returned from database: password authentication failed …` | Неверный пароль или пользователь | Приведите пароль в секрете адреса в соответствие с базой. Смена файла пароля не меняет пароль в уже созданном томе `pg` |
| `не удалось открыть CRANE_BLOBS: …` | Адрес хранилища разобран, но хранилище не открылось: параметры S3, права каталога | Проверьте параметры адреса и учётные данные: {{< xref "deploy/s3-storage" >}} |
| `не удалось занять порт 8080: Address already in use (os error 98)` | Порт занят другим процессом | Освободите порт или задайте другой: {{< xref "configure/network" >}} |
| ``репозиторий `<имя>` уже существует как Hosted; CRANE_CARGO_PROXY_REPOS требует свободное имя`` | Имя proxy-репозитория совпадает с существующим hosted-репозиторием каталога | Выберите другое имя: {{< xref "configure/repositories" >}} |
| `namespace <шаблон> уже принадлежит другому workspace; владение не передаётся через конфигурацию` | Шаблон из {{< env "CRANE_NAMESPACES" >}} занят другим владельцем | Уберите или измените шаблон: {{< xref "configure/namespaces" >}} |
| `не удалось прочитать файл конфигурации <путь>: …` | Файл из {{< env "CRANE_CONFIG" >}} не читается | Проверьте путь и права |
| `ошибка разбора TOML в <путь>: строка <N>, столбец <M>` | Синтаксическая ошибка в файле. Содержимое строки в текст не попадает | Исправьте файл в указанной позиции |
| ``неизвестный ключ `<ключ>` в файле конфигурации`` | Ключа нет в списке | Сверьте ключи: {{< xref "reference/environment-variables#toml" >}} |

Ошибки миграций и расширений PostgreSQL разобраны на странице {{< xref "operations/upgrades-and-migrations#failure" >}}.

## Сервер не готов {#not-ready}

| Симптом | Причина | Что делать |
| --- | --- | --- |
| `crane healthcheck` пишет `порт 9464 ответил нездоровым статусом: HTTP/1.1 503 Service Unavailable` | Каталог или хранилище blob недоступны или ответили ошибкой | Прочитайте записи `хранилище не готово`: {{< xref "operations/health-checks#failed" >}}, {{< xref "operations/outages" >}} |
| `crane healthcheck` пишет `проба порта 9464 не уложилась в 2s` | Порт проб не отвечает: сервер ещё стартует или завис | Проверьте журнал запуска; в Compose дождитесь окончания `migrate` |
| `crane healthcheck` пишет ошибку соединения | Сервер не запущен или слушает другой порт проб | Команда читает {{< env "CRANE_ADMIN_PORT" >}} из своего окружения: задайте то же значение, что у сервера |
| Контейнер `crane` не создаётся, `migrate` завершился с кодом `1` | Миграция не прошла | {{< xref "operations/upgrades-and-migrations#failure" >}} |

## Клиент получает ошибку {#client}

Форма тела и полный список кодов: {{< xref "reference/errors" >}}. Клиенты Cargo и npm показывают текст ошибки с суффиксом `(request_id <id>)`; по идентификатору найдите запись в журнале.

| Код и текст | Причина | Что делать |
| --- | --- | --- |
| `401` `требуется токен` | Клиент не прислал заголовок с токеном | Настройте клиент: {{< xref "configure/access-token#presenting" >}} |
| `403` `токен отвергнут` | Токен не совпадает с токеном сервера или предъявлен в чужой схеме (например, Basic вместо Bearer у npm) | Проверьте значение {{< term "static-token" "статического токена" >}} и схему. Отказ виден в аудите: событие класса `3002` |
| `403` `имя занято в публичном реестре: …` | Новое имя уже есть в публичном реестре | Выберите другое имя либо попросите администратора платформы зарезервировать его в {{< env "CRANE_NAMESPACES" >}} |
| `403` `имя принадлежит namespace другого workspace` | Имя зарезервировано за другой командой | Выберите другое имя |
| `404` `репозиторий не найден` | Репозиторий не создан или опечатка в адресе клиента | Сверьте имя с {{< env "CRANE_CARGO_REPOS" >}} и {{< env "CRANE_NPM_REPOS" >}} |
| `404` `не найдено` при запросе к proxy | Пакета нет у upstream, либо CRANE считает имя внутренним | Найдите в аудите событие `upstream.shadow` с тем же `request_id`: {{< xref "operations/logs#fields-audit" >}} |
| `405` `репозиторий не hosted: публикация запрещена` | Клиент публикует в proxy-репозиторий | Укажите в клиенте адрес hosted-репозитория |
| `409` `версия уже существует` | Версия уже опубликована; номер занят навсегда | Опубликуйте новый номер версии |
| `413` | Тело публикации больше {{< env "CRANE_MAX_PUBLISH_BYTES" >}} | Уменьшите публикацию или поднимите предел: {{< xref "configure/limits" >}} |
| `502` `upstream недоступен` | {{< term "upstream" >}} не ответил, отказал или прислал архив с неверной суммой | Найдите `upstream_failure` в строке доступа: {{< xref "operations/outages#upstream" >}} |
| `503` `хранилище временно недоступно` | Каталог или хранилище blob не отвечают | Повторите запрос позже; восстановите компонент: {{< xref "operations/outages" >}} |
| `500` `внутренняя ошибка сервера` | Ошибка в самом CRANE | Найдите запись `внутренняя ошибка запроса` по идентификатору запроса |

## Журнал не показывает ожидаемое {#logs}

| Симптом | Причина | Что делать |
| --- | --- | --- |
| В строках доступа вместо адреса клиента адрес прокси | Прокси нет в {{< env "CRANE_TRUSTED_PROXIES" >}} | Добавьте адрес или сеть прокси: {{< xref "configure/network" >}} |
| Нет записи `сервер запущен` | {{< env "RUST_LOG" >}} скрывает записи `info` | Верните `info`; журнал ИБ при этом не пропадает |
| В строке доступа нет поля `actor` | Запрос без принятого токена | Это не ошибка: `actor` пишется только при успешной аутентификации |

## Проверка {#verify}

Проверьте, что исправление подействовало:

1. `crane healthcheck` возвращает `0`.
2. Запрос, который падал, возвращает ожидаемый код. Для проверки без токена достаточно `401` на любом пути репозитория: {{< xref "operations/health-checks#steps" >}}.
3. В журнале нет новых записей `ERROR`.
