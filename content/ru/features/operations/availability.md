CRANE различает сохранность данных и доступность сервиса. Сохранность достижима почти без ограничений: хранилище с erasure coding и проверка SHA-256 исключают потерю и тихую порчу файлов. Доступность ограничена архитектурой: реалистичный целевой уровень скачивания для профиля L равен 99,99% при развёртывании в одном регионе с тремя зонами.

Страница описывает целевые показатели по профилям и поведение CRANE при отказе каждого компонента. Показатели — цели проектирования, а не обязательства. При отказе компонента CRANE деградирует по описанным правилам, а если страдает проверка безопасности, выбирает безопасность: {{< xref "features/security/fail-closed" >}}.

## Сохранность и доступность {#durability}

«Девять девяток» достижимы для сохранности и недостижимы для доступности. 99,9999999% доступности означают около 32 миллисекунд простоя в год, и такого уровня не обещают облачные провайдеры (обычно 99,9–99,99%).

- **Сохранность** байтов пакетов обеспечивают хранилище S3 с erasure coding (11 девяток) и {{< term "cas" >}} с проверкой SHA-256. Подмену или порчу файла обнаруживает проверка дайджеста ({{< xref "features/security/digest-verification" >}}).
- **Доступность** зависит от PostgreSQL, потому что каждый запрос сверяется с каталогом.

## Чтение и запись {#classes}

Операции делятся на два класса с разной достижимой доступностью.

- **Чтение (скачивание пакетов)** критично для сборок. Его обслуживают stateless-реплики из кэша и хранилища. Каждый запрос сверяется с каталогом: резервации {{< term "namespace" >}}, экстренные блокировки и {{< term "quarantine" >}}. Поэтому чтение переживает отказ primary-узла PostgreSQL, пока доступна read-реплика каталога. Если каталога нет совсем, чтение получает `503`.
- **Запись (публикация и управление)** требует primary-узла. Пока идёт failover, который занимает 10–30 секунд, клиенты получают `503` с заголовком `Retry-After: 10`. Стандартные клиенты и шаблоны CI повторяют запрос.

## Целевые показатели по профилям {#slo}

Профили S, M и L описаны на странице {{< xref "features/operations/deployment-model#profiles" >}}.

| Показатель | S | M | L |
| --- | --- | --- | --- |
| Доступность скачивания | 99,5% (одна ВМ) | 99,9% | 99,99% (3 зоны) |
| Доступность публикации | 99,5% | 99,9% | 99,95% |
| p99 metadata при попадании в кэш (на сервере) | < 20 мс | < 10 мс | < 10 мс |
| p99 до первого байта blob из кэша | < 50 мс | < 30 мс | < 30 мс |
| RPO для metadata | ≤ 24 ч (снапшот) или ≤ 5 мин (WAL) | ≤ 1 мин (WAL-архив) | 0 (синхронная реплика) |
| RTO | ≤ 4 ч | ≤ 1 ч | ≤ 1 мин (failover), ≤ 4 ч (восстановление после аварии) |
| Сохранность blob | зависит от диска | ≥ 99,999999999% (S3 с EC) | ≥ 99,999999999% (S3 с EC) |
| Время обнаружения уязвимости (advisory в фиде → finding) | ≤ 60 мин | ≤ 15 мин | ≤ 15 мин |
| Отставание экспорта в {{< term "siem" >}} | ≤ 15 мин | ≤ 5 мин | ≤ 5 мин |

Отзыв credentials применяется на всех репликах обычно за 5 секунд (по событию инвалидации) и гарантированно за 30 секунд (по TTL кэша) во всех профилях.

## Режимы деградации {#degradation}

Таблица описывает, что происходит при отказе компонента и что остаётся работать.

| Отказ | Поведение CRANE |
| --- | --- |
| Primary PostgreSQL, read-реплика доступна | Скачивания идут с реплики. Публикация и управление отвечают `503` с `Retry-After`. Консоль показывает баннер «только чтение» |
| Каталог PostgreSQL недоступен целиком | Все протокольные запросы, включая попадания в кэш и proxy, получают `503` с `Retry-After`. Выборок из upstream нет. Нарушение внутреннего инварианта остаётся ответом `500`: повторять такой запрос бессмысленно |
| Valkey | Кэш переходит в память процесса, данные не теряются. Нагрузка смещается на upstream, а не на PostgreSQL. Межрепликовое объединение выборок пропадает, остаётся внутри процесса: на ключ приходится не больше выборок, чем реплик. Молчащее соединение обнаруживается примерно за секунду, а устаревание кэша процесса из-за пропущенной инвалидации ограничено 30 секундами |
| Upstream | CRANE отдаёт сохранённые metadata ({{< term "stale-if-error" >}}) до настроенного срока, по умолчанию 7 дней, с заголовками возраста. При `429` и `403` срок не больше 24 часов, при `410` и `451` устаревшая копия не отдаётся. Отчёт о готовности к офлайну показывает, что собирается без upstream ({{< xref "features/registry/proxy-cache#stale" >}}) |
| Тихий обрыв соединения к upstream (NAT, файрвол) | CRANE шлёт HTTP/2 PING каждые 15 секунд, в том числе на простаивающем соединении. Если ответа нет за 10 секунд, соединение закрывается, и следующий запрос открывает новое. Мёртвое соединение замечается примерно за 25 секунд, а не держит запросы до таймаута чтения. Для HTTP/1.1 соединение, простоявшее в пуле больше 30 секунд, не используется повторно |
| Trivy | Проверки получают статус «ошибка анализа» или «проверка отсутствует». Поведение продвижения задаёт политика, по умолчанию продвижение блокируется, а скачивание нет. Сопоставление advisory продолжает работать |
| Фид уязвимостей | Используется последнее загруженное состояние. В SIEM уходит событие об отставании фида и срабатывает алерт, остальные фиды работают |
| Модель скоринга | Приоритет и лицензионные решения считаются по правилам (CVSS, EPSS, KEV, категория SPDX). Приоритет P0 по KEV и вредоносным пакетам от модели не зависит |
| Языковая модель | Нет объяснений и ассистентов, поиск работает лексически, A2A-агент отвечает структурированными данными |
| SIEM | События копятся в outbox, экспорт продолжается с курсора после восстановления. Аудит не теряется |
| S3 | Скачивание того, что есть в кэше процесса или CDN, продолжается. Остальное получает `503 Retry-After`, публикация недоступна. Отказ S3 доходит до клиента примерно за 5 секунд, а не за минуты |

## Безопасность важнее доступности {#fail-closed}

Строка про недоступный каталог описывает осознанный выбор. Без каталога CRANE не может проверить резервации namespace, экстренные блокировки и карантин, а выдача имени из upstream или кэша без этих проверок открыла бы путь для typosquatting и dependency confusion. Поэтому CRANE отвечает `503`, а не пропускает запрос ({{< term "fail-closed" >}}). Цена этого выбора — недоступность чтения при отказе каталога. Гарантия и её границы описаны на странице {{< xref "features/security/fail-closed" >}}.

## Как клиенты и люди узнают о деградации {#signals}

- Клиенты получают `503` с `Retry-After`, а для устаревших ответов proxy — заголовок `Age`.
- Эндпоинт состояния сообщает режим (`normal`, `read-only` или `degraded`), состояние компонентов и фидов и отставание экспорта в SIEM.
- Консоль показывает баннеры режима только для чтения и деградации.
- Алерты (потеря доступности скачивания, режим только чтения, недоступный upstream, отставание фидов и SIEM) описаны на странице {{< xref "features/operations/observability#alerts" >}}.
